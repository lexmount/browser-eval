接入 CowAgent 与其它 Agent 的最小可用路径

CowAgent 当前是仓库内置 HTTP + 文本/文档解析，不依赖外部 Web Fetch 供应商。接入点应在现有 WebFetch 类内部，通过 provider 配置切换，模型仍只看到一个 web_fetch。

当前建议路由

public static HTML -> Lexmount Global beta route
PDF/document       -> CowAgent local parser until PDF content passes
JavaScript page    -> browser tool or explicitly selected rendering engine
login/interaction  -> browser tool, never WebFetch
依据本轮实测：Lexmount 静态页快且请求稳定，但 JS/PDF 正文未过；CowAgent PDF 受本地解析依赖影响；Firecrawl 全过但更慢且 PDF 单次 15 credits。

CowAgent 实现细节

  1. 保留现有 URL scheme 与 SSRF 检查，再调用供应商。
  2. 只从环境配置读取 LEXMOUNT_API_KEY / LEXMOUNT_PROJECT_ID；不进入 tool schema、artifact 或模型上下文。
  3. 本次 rollout 只调用 https://api.lexmount.com/v1/extract，401 不跨域重试。
  4. 区分 authentication、rate_limit、upstream、content failure；HTTP 200 空正文不能算成功。
  5. fallback 同时记录 primary 与 fallback 的耗时、费用和 trace，否则指标会被隐藏。

跨 Agent 稳定契约

{
  "name": "web_fetch",
  "input": {"url": "https://example.com"},
  "output": {
    "title": "Example Domain",
    "content": "...",
    "final_url": "https://example.com/",
    "provider": "lexmount-global",
    "trace_id": "..."
  }
}

web_search(query) 负责发现 URL，web_fetch(url) 负责读取正文，browser 负责点击、登录和交互。供应商变化不应制造新的模型可见同义工具。
