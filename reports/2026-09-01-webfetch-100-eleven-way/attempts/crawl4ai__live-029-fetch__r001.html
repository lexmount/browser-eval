## Goals
The goal is to unify fetching across the web platform and provide consistent handling of everything that involves, including:
  * URL schemes
  * Redirects
  * Cross-origin semantics
  * CSP [[CSP]](https://fetch.spec.whatwg.org/#biblio-csp "Content Security Policy Level 3")
  * Fetch Metadata [[FETCH-METADATA]](https://fetch.spec.whatwg.org/#biblio-fetch-metadata "Fetch Metadata Request Headers")
  * Service workers [[SW]](https://fetch.spec.whatwg.org/#biblio-sw "Service Workers Nightly")
  * Mixed Content [[MIX]](https://fetch.spec.whatwg.org/#biblio-mix "Mixed Content")
  * Upgrade Insecure Requests [[UPGRADE-INSECURE-REQUESTS]](https://fetch.spec.whatwg.org/#biblio-upgrade-insecure-requests "Upgrade Insecure Requests")
  * ``Referer`` [[REFERRER]](https://fetch.spec.whatwg.org/#biblio-referrer "Referrer Policy")


To do so it also supersedes the HTTP `[`Origin`](https://fetch.spec.whatwg.org/#http-origin)` header semantics originally defined in The Web Origin Concept. [[ORIGIN]](https://fetch.spec.whatwg.org/#biblio-origin "The Web Origin Concept")
##  1. Preface
At a high level, fetching a resource is a fairly simple operation. A request goes in, a response comes out. The details of that operation are however quite involved and used to not be written down carefully and differ from one API to the next.
Numerous APIs provide the ability to fetch a resource, e.g. HTML’s `img` and `script` element, CSS' `cursor` and `list-style-image`, the `navigator.sendBeacon()` and `self.importScripts()` JavaScript APIs. The Fetch Standard provides a unified architecture for these features so they are all consistent when it comes to various aspects of fetching, such as redirects and the CORS protocol.
The Fetch Standard also defines the [`fetch()`](https://fetch.spec.whatwg.org/#dom-global-fetch) JavaScript API, which exposes most of the networking functionality at a fairly low level of abstraction.

While [fetching](https://fetch.spec.whatwg.org/#concept-fetch) encompasses more than just HTTP, it borrows a number of concepts from HTTP and applies these to resources obtained via other means (e.g., `data` URLs).
An HTTP tab or space is U+0009 TAB or U+0020 SPACE.

An HTTP newline byte is 0x0A (LF) or 0x0D (CR).
An HTTP tab or space byte is 0x09 (HT) or 0x20 (SP).

To parse a single range header value from a [byte sequence](https://infra.spec.whatwg.org/#byte-sequence) value and a boolean allowWhitespace, run these steps:
  1. Let data be the [isomorphic decoding](https://infra.spec.whatwg.org/#isomorphic-decode) of value.
  2. If data does not [start with](https://infra.spec.whatwg.org/#string-starts-with) "`bytes`", then return failure.
  3. Let position be a [position variable](https://infra.spec.whatwg.org/#string-position-variable) for data, initially pointing at the 5th [code point](https://infra.spec.whatwg.org/#code-point) of data.
  4. If allowWhitespace is true, [collect a sequence of code points](https://infra.spec.whatwg.org/#collect-a-sequence-of-code-points) that are [HTTP tab or space](https://fetch.spec.whatwg.org/#http-tab-or-space), from data given position.
  5. If the [code point](https://infra.spec.whatwg.org/#code-point) at position within data is not U+003D (=), then return failure.
  6. Advance position by 1.
  7. If allowWhitespace is true, [collect a sequence of code points](https://infra.spec.whatwg.org/#collect-a-sequence-of-code-points) that are [HTTP tab or space](https://fetch.spec.whatwg.org/#http-tab-or-space), from data given position.
  8. Let rangeStart be the result of [collecting a sequence of code points](https://infra.spec.whatwg.org/#collect-a-sequence-of-code-points) that are [ASCII digits](https://infra.spec.whatwg.org/#ascii-digit), from data given position.
  9. Let rangeStartValue be rangeStart, interpreted as decimal number, if rangeStart is not the empty string; otherwise null.
  10. If allowWhitespace is true, [collect a sequence of code points](https://infra.spec.whatwg.org/#collect-a-sequence-of-code-points) that are [HTTP tab or space](https://fetch.spec.whatwg.org/#http-tab-or-space), from data given position.
  11. If the [code point](https://infra.spec.whatwg.org/#code-point) at position within data is not U+002D (-), then return failure.
  12. Advance position by 1.
  13. If allowWhitespace is true, [collect a sequence of code points](https://infra.spec.whatwg.org/#collect-a-sequence-of-code-points) that are [HTTP tab or space](https://fetch.spec.whatwg.org/#http-tab-or-space), from data given position.
  14. Let rangeEnd be the result of [collecting a sequence of code points](https://infra.spec.whatwg.org/#collect-a-sequence-of-code-points) that are [ASCII digits](https://infra.spec.whatwg.org/#ascii-digit), from data given position.
  15. Let rangeEndValue be rangeEnd, interpreted as decimal number, if rangeEnd is not the empty string; otherwise null.
  16. If position is not past the end of data, then return failure.
  17. If rangeEndValue and rangeStartValue are null, then return failure.
  18. If rangeStartValue and rangeEndValue are numbers, and rangeStartValue is greater than rangeEndValue, then return failure.
  19. Return (rangeStartValue, rangeEndValue).
The range end or start can be omitted, e.g., ``bytes=0-`` or ``bytes=-500`` are valid ranges.

####  2.2.3. Statuses
A status is an integer in the range 0 to 999, inclusive.
Various edge cases in mapping HTTP/1’s `status-code` to this concept are worked on in [issue #1156](https://github.com/whatwg/fetch/issues/1156).
A null body status is a [status](https://fetch.spec.whatwg.org/#concept-status) that is 101, 103, 204, 205, or 304.
An ok status is a [status](https://fetch.spec.whatwg.org/#concept-status) in the range 200 to 299, inclusive.
A range status is a [status](https://fetch.spec.whatwg.org/#concept-status) that is 206 or 416.
A redirect status is a [status](https://fetch.spec.whatwg.org/#concept-status) that is 301, 302, 303, 307, or 308.
####  2.2.4. Bodies

To get a [byte sequence](https://infra.spec.whatwg.org/#byte-sequence) bytes as a body, return the [body](https://fetch.spec.whatwg.org/#body-with-type-body) of the result of [safely extracting](https://fetch.spec.whatwg.org/#bodyinit-safely-extract) bytes.

    1. [Queue a fetch task](https://fetch.spec.whatwg.org/#queue-a-fetch-task) given processEndOfBody and taskDestination.

####  2.2.5. Requests
This section documents how requests work in detail. To get started, see [Setting up a request](https://fetch.spec.whatwg.org/#fetch-elsewhere-request).
The input to [fetch](https://fetch.spec.whatwg.org/#concept-fetch) is a request.
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated method (a [method](https://fetch.spec.whatwg.org/#concept-method)). Unless stated otherwise it is ``GET``.
This can be updated during redirects to ``GET`` as described in [HTTP fetch](https://fetch.spec.whatwg.org/#concept-http-fetch).
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated URL (a [URL](https://url.spec.whatwg.org/#concept-url)).
Implementations are encouraged to make this a pointer to the first [URL](https://url.spec.whatwg.org/#concept-url) in [request](https://fetch.spec.whatwg.org/#concept-request)’s [URL list](https://fetch.spec.whatwg.org/#concept-request-url-list). It is provided as a distinct field solely for the convenience of other standards hooking into Fetch.
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated local-URLs-only flag. Unless stated otherwise it is unset.
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated header list (a [header list](https://fetch.spec.whatwg.org/#concept-header-list)). Unless stated otherwise it is « ».
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated unsafe-request flag. Unless stated otherwise it is unset.
The [unsafe-request flag](https://fetch.spec.whatwg.org/#unsafe-request-flag) is set by APIs such as [`fetch()`](https://fetch.spec.whatwg.org/#dom-global-fetch) and `XMLHttpRequest[](https://xhr.spec.whatwg.org/#xmlhttprequest)` to ensure a [CORS-preflight fetch](https://fetch.spec.whatwg.org/#cors-preflight-fetch-0) is done based on the supplied [method](https://fetch.spec.whatwg.org/#concept-request-method) and [header list](https://fetch.spec.whatwg.org/#concept-request-header-list). It does not free an API from outlawing [forbidden methods](https://fetch.spec.whatwg.org/#forbidden-method) and [forbidden request-headers](https://fetch.spec.whatwg.org/#forbidden-request-header).
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated body (null, a [byte sequence](https://infra.spec.whatwg.org/#byte-sequence), or a [body](https://fetch.spec.whatwg.org/#concept-body)). Unless stated otherwise it is null.
A [byte sequence](https://infra.spec.whatwg.org/#byte-sequence) will be [safely extracted](https://fetch.spec.whatwg.org/#bodyinit-safely-extract) into a [body](https://fetch.spec.whatwg.org/#concept-body) early on in [fetch](https://fetch.spec.whatwg.org/#concept-fetch). As part of [HTTP fetch](https://fetch.spec.whatwg.org/#concept-http-fetch) it is possible for this field to be set to null due to certain redirects.
* * *
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated client (null or an [environment settings object](https://html.spec.whatwg.org/multipage/webappapis.html#environment-settings-object)).
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated reserved client (null, an [environment](https://html.spec.whatwg.org/multipage/webappapis.html#environment), or an [environment settings object](https://html.spec.whatwg.org/multipage/webappapis.html#environment-settings-object)). Unless stated otherwise it is null.
This is only used by [navigation requests](https://fetch.spec.whatwg.org/#navigation-request) and worker requests, but not service worker requests. It references an [environment](https://html.spec.whatwg.org/multipage/webappapis.html#environment) for a [navigation request](https://fetch.spec.whatwg.org/#navigation-request) and an [environment settings object](https://html.spec.whatwg.org/multipage/webappapis.html#environment-settings-object) for a worker request.
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated replaces client id (a string). Unless stated otherwise it is the empty string.
This is only used by [navigation requests](https://fetch.spec.whatwg.org/#navigation-request). It is the [id](https://html.spec.whatwg.org/multipage/webappapis.html#concept-environment-id) of the [target browsing context](https://html.spec.whatwg.org/multipage/webappapis.html#concept-environment-target-browsing-context)’s [active document](https://html.spec.whatwg.org/multipage/document-sequences.html#nav-document)’s [environment settings object](https://html.spec.whatwg.org/multipage/webappapis.html#environment-settings-object).
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated traversable for user prompts, that is "`no-traversable`", "`client`", or a [traversable navigable](https://html.spec.whatwg.org/multipage/document-sequences.html#traversable-navigable). Unless stated otherwise it is "`client`".
This is used to determine whether and where to show necessary UI for the request, such as authentication prompts or client certificate dialogs.

"`no-traversable`"
    No UI is shown; usually the request fails with a [network error](https://fetch.spec.whatwg.org/#concept-network-error).

"`client`"
    This value will automatically be changed to either "`no-traversable`" or to a [traversable navigable](https://html.spec.whatwg.org/multipage/document-sequences.html#traversable-navigable) derived from the request’s [client](https://fetch.spec.whatwg.org/#concept-request-client) during [fetching](https://fetch.spec.whatwg.org/#concept-fetch). This provides a convenient way for standards to not have to explicitly set a request’s [traversable for user prompts](https://fetch.spec.whatwg.org/#concept-request-window).

a [traversable navigable](https://html.spec.whatwg.org/multipage/document-sequences.html#traversable-navigable)
    The UI shown will be associated with the browser interface elements that are displaying that [traversable navigable](https://html.spec.whatwg.org/multipage/document-sequences.html#traversable-navigable).
When displaying a user interface associated with a request in that request’s [traversable for user prompts](https://fetch.spec.whatwg.org/#concept-request-window), the user agent should update the address bar to display something derived from the request’s [current URL](https://fetch.spec.whatwg.org/#concept-request-current-url) (and not, e.g., leave it at its previous value, derived from the URL of the request’s initiator). Additionally, the user agent should avoid displaying content from the request’s initiator in the [traversable for user prompts](https://fetch.spec.whatwg.org/#concept-request-window), especially in the case of cross-origin requests. Displaying a blank page behind such prompts is a good way to fulfill these requirements. Failing to follow these guidelines can confuse users as to which origin is responsible for the prompt.

"`default`"
     [Fetch](https://fetch.spec.whatwg.org/#concept-fetch) will inspect the HTTP cache on the way to the network. If the HTTP cache contains a matching [fresh response](https://fetch.spec.whatwg.org/#concept-fresh-response) it will be returned. If the HTTP cache contains a matching [stale-while-revalidate response](https://fetch.spec.whatwg.org/#concept-stale-while-revalidate-response) it will be returned, and a conditional network fetch will be made to update the entry in the HTTP cache. If the HTTP cache contains a matching [stale response](https://fetch.spec.whatwg.org/#concept-stale-response), a conditional network fetch will be returned to update the entry in the HTTP cache. Otherwise, a non-conditional network fetch will be returned to update the entry in the HTTP cache. [[HTTP]](https://fetch.spec.whatwg.org/#biblio-http "HTTP Semantics") [[HTTP-CACHING]](https://fetch.spec.whatwg.org/#biblio-http-caching "HTTP Caching") [[STALE-WHILE-REVALIDATE]](https://fetch.spec.whatwg.org/#biblio-stale-while-revalidate "HTTP Cache-Control Extensions for Stale Content")

"`no-store`"
    Fetch behaves as if there is no HTTP cache at all.

"`reload`"
    Fetch behaves as if there is no HTTP cache on the way to the network. Ergo, it creates a normal request and updates the HTTP cache with the response.

"`no-cache`"
    Fetch creates a conditional request if there is a response in the HTTP cache and a normal request otherwise. It then updates the HTTP cache with the response.

"`force-cache`"
    Fetch uses any response in the HTTP cache matching the request, not paying attention to staleness. If there was no response, it creates a normal request and updates the HTTP cache with the response.

"`only-if-cached`"
    Fetch uses any response in the HTTP cache matching the request, not paying attention to staleness. If there was no response, it returns a network error. A [request](https://fetch.spec.whatwg.org/#concept-request)’s [URL list](https://fetch.spec.whatwg.org/#concept-request-url-list), [current URL](https://fetch.spec.whatwg.org/#concept-request-current-url), [redirect count](https://fetch.spec.whatwg.org/#concept-request-redirect-count), [response tainting](https://fetch.spec.whatwg.org/#concept-request-response-tainting), [done flag](https://fetch.spec.whatwg.org/#done-flag), [timing allow failed flag](https://fetch.spec.whatwg.org/#timing-allow-failed), and [navigation timing allow values list](https://fetch.spec.whatwg.org/#request-navigation-timing-allow-values-list) are used as bookkeeping details by the [fetch](https://fetch.spec.whatwg.org/#concept-fetch) algorithm.
A [request](https://fetch.spec.whatwg.org/#concept-request) has an associated WebDriver id which is the result of [generating a random UUID](https://w3c.github.io/webcrypto/#dfn-generate-a-random-uuid), set when the [request](https://fetch.spec.whatwg.org/#concept-request) is created. [[WEBCRYPTO]](https://fetch.spec.whatwg.org/#biblio-webcrypto "Web Cryptography Level 2")
The [WebDriver id](https://fetch.spec.whatwg.org/#concept-webdriver-id) is used by WebDriver-BiDi. It remains constant across redirects, authentication attempts, and CORS-preflight fetches of an initial request. When a request is [cloned](https://fetch.spec.whatwg.org/#concept-request-clone), the created request gets a unique [WebDriver id](https://fetch.spec.whatwg.org/#concept-webdriver-id). [[WEBDRIVER-BIDI]](https://fetch.spec.whatwg.org/#biblio-webdriver-bidi "WebDriver BiDi")

A subresource request is a [request](https://fetch.spec.whatwg.org/#concept-request) whose [destination](https://fetch.spec.whatwg.org/#concept-request-destination) is "`audio`", "`audioworklet`", "`font`", "`image`", "`json`", "`manifest`", "`paintworklet`", "`script`", "`style`", "`text`", "`track`", "`video`", "`xslt`", or the empty string.
A non-subresource request is a [request](https://fetch.spec.whatwg.org/#concept-request) whose [destination](https://fetch.spec.whatwg.org/#concept-request-destination) is "`document`", "`embed`", "`frame`", "`iframe`", "`object`", "`report`", "`serviceworker`", "`sharedworker`", or "`worker`".
A navigation request is a [request](https://fetch.spec.whatwg.org/#concept-request) whose [destination](https://fetch.spec.whatwg.org/#concept-request-destination) is "`document`", "`embed`", "`frame`", "`iframe`", or "`object`".
See [handle fetch](https://w3c.github.io/ServiceWorker/#handle-fetch) for usage of these terms. [[SW]](https://fetch.spec.whatwg.org/#biblio-sw "Service Workers Nightly")

To compute the redirect-taint of a [request](https://fetch.spec.whatwg.org/#concept-request) request, perform the following steps. They return "`same-origin`", "`same-site`", or "`cross-site`".
  1. [Assert](https://infra.spec.whatwg.org/#assert): request’s [origin](https://fetch.spec.whatwg.org/#concept-request-origin) is not "`client`".
  2. Let lastURL be null.
  3. Let taint be "`same-origin`".
  4. [For each](https://infra.spec.whatwg.org/#list-iterate) url of request’s [URL list](https://fetch.spec.whatwg.org/#concept-request-url-list):
    1. If lastURL is null, then set lastURL to url and [continue](https://infra.spec.whatwg.org/#iteration-continue).
    2. If url’s [origin](https://url.spec.whatwg.org/#concept-url-origin) is not [same site](https://html.spec.whatwg.org/multipage/browsers.html#same-site) with lastURL’s [origin](https://url.spec.whatwg.org/#concept-url-origin) and request’s [origin](https://fetch.spec.whatwg.org/#concept-request-origin) is not [same site](https://html.spec.whatwg.org/multipage/browsers.html#same-site) with lastURL’s [origin](https://url.spec.whatwg.org/#concept-url-origin), then return "`cross-site`".
    3. If url’s [origin](https://url.spec.whatwg.org/#concept-url-origin) is not [same origin](https://html.spec.whatwg.org/multipage/browsers.html#same-origin) with lastURL’s [origin](https://url.spec.whatwg.org/#concept-url-origin) and request’s [origin](https://fetch.spec.whatwg.org/#concept-request-origin) is not [same origin](https://html.spec.whatwg.org/multipage/browsers.html#same-origin) with lastURL’s [origin](https://url.spec.whatwg.org/#concept-url-origin), then set taint to "`same-site`".
    4. Set lastURL to url.
  5. Return taint.


Serializing a request origin, given a [request](https://fetch.spec.whatwg.org/#concept-request) request, is to run these steps:
  1. [Assert](https://infra.spec.whatwg.org/#assert): request’s [origin](https://fetch.spec.whatwg.org/#concept-request-origin) is not "`client`".
  2. If request’s [redirect-taint](https://fetch.spec.whatwg.org/#concept-request-tainted-origin) is not "`same-origin`", then return "`null`".
  3. Return request’s [origin](https://fetch.spec.whatwg.org/#concept-request-origin), [serialized](https://html.spec.whatwg.org/multipage/browsers.html#ascii-serialisation-of-an-origin).


Byte-serializing a request origin, given a [request](https://fetch.spec.whatwg.org/#concept-request) request, is to return the result of [serializing a request origin](https://fetch.spec.whatwg.org/#serializing-a-request-origin) with request, [isomorphic encoded](https://infra.spec.whatwg.org/#isomorphic-encode).

To clone a [request](https://fetch.spec.whatwg.org/#concept-request) request, run these steps:
  1. Let newRequest be a copy of request, except for its [body](https://fetch.spec.whatwg.org/#concept-request-body) and [WebDriver id](https://fetch.spec.whatwg.org/#concept-webdriver-id).
  2. Set newRequest’s [WebDriver id](https://fetch.spec.whatwg.org/#concept-webdriver-id) to the result of [generating a random UUID](https://w3c.github.io/webcrypto/#dfn-generate-a-random-uuid). [[WEBCRYPTO]](https://fetch.spec.whatwg.org/#biblio-webcrypto "Web Cryptography Level 2")
  3. If request’s [body](https://fetch.spec.whatwg.org/#concept-request-body) is non-null, set newRequest’s [body](https://fetch.spec.whatwg.org/#concept-request-body) to the result of [cloning](https://fetch.spec.whatwg.org/#concept-body-clone) request’s [body](https://fetch.spec.whatwg.org/#concept-request-body).
  4. Return newRequest.

To add a range header to a [request](https://fetch.spec.whatwg.org/#concept-request) request, with an integer first, and an optional integer last, run these steps:
  1. [Assert](https://infra.spec.whatwg.org/#assert): last is not given, or first is less than or equal to last.
  2. Let rangeValue be ``bytes=``.
  3. [Serialize](https://fetch.spec.whatwg.org/#serialize-an-integer) and [isomorphic encode](https://infra.spec.whatwg.org/#isomorphic-encode) first, and append the result to rangeValue.
  4. Append 0x2D (-) to rangeValue.
  5. If last is given, then [serialize](https://fetch.spec.whatwg.org/#serialize-an-integer) and [isomorphic encode](https://infra.spec.whatwg.org/#isomorphic-encode) it, and append the result to rangeValue.
  6. [Append](https://fetch.spec.whatwg.org/#concept-header-list-append) (``Range``, rangeValue) to request’s [header list](https://fetch.spec.whatwg.org/#concept-request-header-list).


A range header denotes an inclusive byte range. There a range header where first is 0 and last is 500, is a range of 501 bytes.
Features that combine multiple responses into one logical resource are historically a source of security bugs. Please seek security review for features that deal with partial responses.

To serialize a response URL for reporting, given a [response](https://fetch.spec.whatwg.org/#concept-response) response, run these steps:
  1. [Assert](https://infra.spec.whatwg.org/#assert): response’s [URL list](https://fetch.spec.whatwg.org/#concept-response-url-list) [is not empty](https://infra.spec.whatwg.org/#list-is-empty).
  2. Let url be a copy of response’s [URL list](https://fetch.spec.whatwg.org/#concept-response-url-list)[0].
This is not response’s [URL](https://fetch.spec.whatwg.org/#concept-response-url) in order to avoid leaking information about redirect targets (see [similar considerations for CSP reporting](https://w3c.github.io/webappsec-csp/#security-violation-reports) too). [[CSP]](https://fetch.spec.whatwg.org/#biblio-csp "Content Security Policy Level 3")
  3. [Set the username](https://url.spec.whatwg.org/#set-the-username) given url and the empty string.
  4. [Set the password](https://url.spec.whatwg.org/#set-the-password) given url and the empty string.
  5. Return the [serialization](https://url.spec.whatwg.org/#concept-url-serializer) of url with [_exclude fragment_](https://url.spec.whatwg.org/#url-serializer-exclude-fragment) set to true.


To check if Cross-Origin-Embedder-Policy allows credentials, given a [request](https://fetch.spec.whatwg.org/#concept-request) request, run these steps:
  1. [Assert](https://infra.spec.whatwg.org/#assert): request’s [origin](https://fetch.spec.whatwg.org/#concept-request-origin) is not "`client`".
  2. If request’s [mode](https://fetch.spec.whatwg.org/#concept-request-mode) is not "`no-cors`", then return true.
  3. If request’s [client](https://fetch.spec.whatwg.org/#concept-request-client) is null, then return true.
  4. If request’s [client](https://fetch.spec.whatwg.org/#concept-request-client)’s [policy container](https://html.spec.whatwg.org/multipage/webappapis.html#concept-settings-object-policy-container)’s [embedder policy](https://html.spec.whatwg.org/multipage/browsers.html#policy-container-embedder-policy)’s [value](https://html.spec.whatwg.org/multipage/browsers.html#embedder-policy-value-2) is not "[`credentialless`](https://html.spec.whatwg.org/multipage/browsers.html#coep-credentialless)", then return true.
  5. If request’s [origin](https://fetch.spec.whatwg.org/#concept-request-origin) is [same origin](https://html.spec.whatwg.org/multipage/browsers.html#same-origin) with request’s [current URL](https://fetch.spec.whatwg.org/#concept-request-current-url)’s [origin](https://url.spec.whatwg.org/#concept-url-origin) and request’s [redirect-taint](https://fetch.spec.whatwg.org/#concept-request-tainted-origin) is not "`same-origin`", then return true.
  6. Return false.


####  2.2.6. Responses
The result of [fetch](https://fetch.spec.whatwg.org/#concept-fetch) is a response. A [response](https://fetch.spec.whatwg.org/#concept-response) evolves over time. That is, not all its fields are available straight away.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated type which is "`basic`", "`cors`", "`default`", "`error`", "`opaque`", or "`opaqueredirect`". Unless stated otherwise, it is "`default`".
A [response](https://fetch.spec.whatwg.org/#concept-response) can have an associated aborted flag, which is initially unset.
This indicates that the request was intentionally aborted by the developer or end-user.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated URL. It is a pointer to the last [URL](https://url.spec.whatwg.org/#concept-url) in [response](https://fetch.spec.whatwg.org/#concept-response)’s [URL list](https://fetch.spec.whatwg.org/#concept-response-url-list) and null if [response](https://fetch.spec.whatwg.org/#concept-response)’s [URL list](https://fetch.spec.whatwg.org/#concept-response-url-list) [is empty](https://infra.spec.whatwg.org/#list-is-empty).
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated URL list (a [list](https://infra.spec.whatwg.org/#list) of zero or more [URLs](https://url.spec.whatwg.org/#concept-url)). Unless stated otherwise, it is « ».
Except for the first and last [URL](https://url.spec.whatwg.org/#concept-url), if any, a [response](https://fetch.spec.whatwg.org/#concept-response)’s [URL list](https://fetch.spec.whatwg.org/#concept-response-url-list) is not directly exposed to script as that would violate [atomic HTTP redirect handling](https://fetch.spec.whatwg.org/#atomic-http-redirect-handling).
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated status, which is a [status](https://fetch.spec.whatwg.org/#concept-status). Unless stated otherwise it is 200.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated status message. Unless stated otherwise it is the empty byte sequence.
Responses over an HTTP/2 connection will always have the empty byte sequence as status message as HTTP/2 does not support them.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated header list (a [header list](https://fetch.spec.whatwg.org/#concept-header-list)). Unless stated otherwise it is « ».
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated body (null or a [body](https://fetch.spec.whatwg.org/#concept-body)). Unless stated otherwise it is null.
The [source](https://fetch.spec.whatwg.org/#concept-body-source) and [length](https://fetch.spec.whatwg.org/#concept-body-total-bytes) concepts of a network’s [response](https://fetch.spec.whatwg.org/#concept-response)’s [body](https://fetch.spec.whatwg.org/#concept-response-body) are always null.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated cache state (the empty string, "`local`", or "`validated`"). Unless stated otherwise, it is the empty string.
This is intended for usage by Service Workers and Resource Timing. [[SW]](https://fetch.spec.whatwg.org/#biblio-sw "Service Workers Nightly") [[RESOURCE-TIMING]](https://fetch.spec.whatwg.org/#biblio-resource-timing "Resource Timing")
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated CORS-exposed header-name list (a list of zero or more [header](https://fetch.spec.whatwg.org/#concept-header) [names](https://fetch.spec.whatwg.org/#concept-header-name)). The list is empty unless otherwise specified.
A [response](https://fetch.spec.whatwg.org/#concept-response) will typically get its [CORS-exposed header-name list](https://fetch.spec.whatwg.org/#concept-response-cors-exposed-header-name-list) set by [extracting header values](https://fetch.spec.whatwg.org/#extract-header-values) from the `[`Access-Control-Expose-Headers`](https://fetch.spec.whatwg.org/#http-access-control-expose-headers)` header. This list is used by a [CORS filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response-cors) to determine which headers to expose.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated range-requested flag, which is initially unset.
This is used to prevent a partial response from an earlier ranged request being provided to an API that didn’t make a range request. See the flag’s usage for a detailed description of the attack.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated request-includes-credentials (a boolean), which is initially true.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated timing allow passed flag, which is initially unset.
This is used so that the caller to a fetch can determine if sensitive timing data is allowed on the resource fetched by looking at the flag of the response returned. Because the flag on the response of a redirect has to be set if it was set for previous responses in the redirect chain, this is also tracked internally using the request’s [timing allow failed flag](https://fetch.spec.whatwg.org/#timing-allow-failed).
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated navigation timing allow values list (a [list](https://infra.spec.whatwg.org/#list) of [lists](https://infra.spec.whatwg.org/#list) of [strings](https://infra.spec.whatwg.org/#string)). Unless stated otherwise, it is « ».
This holds the ``Timing-Allow-Origin`` values of each redirect [response](https://fetch.spec.whatwg.org/#concept-response) in a navigation’s redirect chain. It is used so that callers can determine, once the navigation’s destination origin is known, whether that origin is allowed by every redirect in the redirect chain.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated body info (a [response body info](https://fetch.spec.whatwg.org/#response-body-info)). Unless stated otherwise, it is a new [response body info](https://fetch.spec.whatwg.org/#response-body-info).
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated service worker timing info (null or a [service worker timing info](https://w3c.github.io/ServiceWorker/#service-worker-timing-info)), which is initially null.
A [response](https://fetch.spec.whatwg.org/#concept-response) has an associated redirect taint ("`same-origin`", "`same-site`", or "`cross-site`"), which is initially "`same-origin`".
* * *
A network error is a [response](https://fetch.spec.whatwg.org/#concept-response) whose [type](https://fetch.spec.whatwg.org/#concept-response-type) is "`error`", [status](https://fetch.spec.whatwg.org/#concept-response-status) is 0, [status message](https://fetch.spec.whatwg.org/#concept-response-status-message) is the empty byte sequence, [header list](https://fetch.spec.whatwg.org/#concept-response-header-list) is « », [body](https://fetch.spec.whatwg.org/#concept-response-body) is null, and [body info](https://fetch.spec.whatwg.org/#concept-response-body-info) is a new [response body info](https://fetch.spec.whatwg.org/#response-body-info).
An aborted network error is a [network error](https://fetch.spec.whatwg.org/#concept-network-error) whose [aborted flag](https://fetch.spec.whatwg.org/#concept-response-aborted) is set.
To create the appropriate network error given [fetch params](https://fetch.spec.whatwg.org/#fetch-params) fetchParams:
  1. [Assert](https://infra.spec.whatwg.org/#assert): fetchParams is [canceled](https://fetch.spec.whatwg.org/#fetch-params-canceled).
  2. Return an [aborted network error](https://fetch.spec.whatwg.org/#concept-aborted-network-error) if fetchParams is [aborted](https://fetch.spec.whatwg.org/#fetch-params-aborted); otherwise return a [network error](https://fetch.spec.whatwg.org/#concept-network-error).


* * *
A filtered response is a [response](https://fetch.spec.whatwg.org/#concept-response) that offers a limited view on an associated [response](https://fetch.spec.whatwg.org/#concept-response). This associated [response](https://fetch.spec.whatwg.org/#concept-response) can be accessed through [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response)’s internal response (a [response](https://fetch.spec.whatwg.org/#concept-response) that is neither a [network error](https://fetch.spec.whatwg.org/#concept-network-error) nor a [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response)).
Unless stated otherwise a [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response)’s associated concepts (such as its [body](https://fetch.spec.whatwg.org/#concept-response-body)) refer to the associated concepts of its [internal response](https://fetch.spec.whatwg.org/#concept-internal-response). (The exceptions to this are listed below as part of defining the concrete types of [filtered responses](https://fetch.spec.whatwg.org/#concept-filtered-response).)
The [fetch](https://fetch.spec.whatwg.org/#concept-fetch) algorithm by way of [_processResponse_](https://fetch.spec.whatwg.org/#process-response) and equivalent parameters exposes [filtered responses](https://fetch.spec.whatwg.org/#concept-filtered-response) to callers to ensure they do not accidentally leak information. If the information needs to be revealed for legacy reasons, e.g., to feed image data to a decoder, the associated [internal response](https://fetch.spec.whatwg.org/#concept-internal-response) can be used by specification algorithms.
New specifications ought not to build further on [opaque filtered responses](https://fetch.spec.whatwg.org/#concept-filtered-response-opaque) or [opaque-redirect filtered responses](https://fetch.spec.whatwg.org/#concept-filtered-response-opaque-redirect). Those are legacy constructs and cannot always be adequately protected given contemporary computer architecture.
A basic filtered response is a [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response) whose [type](https://fetch.spec.whatwg.org/#concept-response-type) is "`basic`" and [header list](https://fetch.spec.whatwg.org/#concept-response-header-list) excludes any [headers](https://fetch.spec.whatwg.org/#concept-header) in [internal response](https://fetch.spec.whatwg.org/#concept-internal-response)’s [header list](https://fetch.spec.whatwg.org/#concept-response-header-list) whose [name](https://fetch.spec.whatwg.org/#concept-header-name) is a [forbidden response-header name](https://fetch.spec.whatwg.org/#forbidden-response-header-name).
A CORS filtered response is a [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response) whose [type](https://fetch.spec.whatwg.org/#concept-response-type) is "`cors`" and [header list](https://fetch.spec.whatwg.org/#concept-response-header-list) excludes any [headers](https://fetch.spec.whatwg.org/#concept-header) in [internal response](https://fetch.spec.whatwg.org/#concept-internal-response)’s [header list](https://fetch.spec.whatwg.org/#concept-response-header-list) whose [name](https://fetch.spec.whatwg.org/#concept-header-name) is _not_ a [CORS-safelisted response-header name](https://fetch.spec.whatwg.org/#cors-safelisted-response-header-name), given [internal response](https://fetch.spec.whatwg.org/#concept-internal-response)’s [CORS-exposed header-name list](https://fetch.spec.whatwg.org/#concept-response-cors-exposed-header-name-list).
An opaque filtered response is a [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response) whose [type](https://fetch.spec.whatwg.org/#concept-response-type) is "`opaque`", [URL list](https://fetch.spec.whatwg.org/#concept-response-url-list) is « », [status](https://fetch.spec.whatwg.org/#concept-response-status) is 0, [status message](https://fetch.spec.whatwg.org/#concept-response-status-message) is the empty byte sequence, [header list](https://fetch.spec.whatwg.org/#concept-response-header-list) is « », [body](https://fetch.spec.whatwg.org/#concept-response-body) is null, and [body info](https://fetch.spec.whatwg.org/#concept-response-body-info) is a new [response body info](https://fetch.spec.whatwg.org/#response-body-info).
An opaque-redirect filtered response is a [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response) whose [type](https://fetch.spec.whatwg.org/#concept-response-type) is "`opaqueredirect`", [status](https://fetch.spec.whatwg.org/#concept-response-status) is 0, [status message](https://fetch.spec.whatwg.org/#concept-response-status-message) is the empty byte sequence, [header list](https://fetch.spec.whatwg.org/#concept-response-header-list) is « », [body](https://fetch.spec.whatwg.org/#concept-response-body) is null, and [body info](https://fetch.spec.whatwg.org/#concept-response-body-info) is a new [response body info](https://fetch.spec.whatwg.org/#response-body-info).
Exposing the [URL list](https://fetch.spec.whatwg.org/#concept-response-url-list) for [opaque-redirect filtered responses](https://fetch.spec.whatwg.org/#concept-filtered-response-opaque-redirect) is harmless since no redirects are followed.
In other words, an [opaque filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response-opaque) and an [opaque-redirect filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response-opaque-redirect) are nearly indistinguishable from a [network error](https://fetch.spec.whatwg.org/#concept-network-error). When introducing new APIs, do not use the [internal response](https://fetch.spec.whatwg.org/#concept-internal-response) for internal specification algorithms as that will leak information.
This also means that JavaScript APIs, such as [`response.ok`](https://fetch.spec.whatwg.org/#dom-response-ok), will return rather useless results.
The [type](https://fetch.spec.whatwg.org/#concept-response-type) of a [response](https://fetch.spec.whatwg.org/#concept-response) is exposed to script through the `type[](https://fetch.spec.whatwg.org/#dom-response-type)` getter:

```
console.log(new Response().type); // "default"

console.log((await fetch("/")).type); // "basic"

console.log((await fetch("https://api.example/status")).type); // "cors"

console.log((await fetch("https://crossorigin.example/image", { mode: "no-cors" })).type); // "opaque"

console.log((await fetch("/surprise-me", { redirect: "manual" })).type); // "opaqueredirect"

```

(This assumes that the various resources exist, `https://api.example/status` has the appropriate CORS headers, and `/surprise-me` uses a [redirect status](https://fetch.spec.whatwg.org/#redirect-status).)

To clone a [response](https://fetch.spec.whatwg.org/#concept-response) response, run these steps:
  1. If response is a [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response), then return a new identical [filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response) whose [internal response](https://fetch.spec.whatwg.org/#concept-internal-response) is a [clone](https://fetch.spec.whatwg.org/#concept-response-clone) of response’s [internal response](https://fetch.spec.whatwg.org/#concept-internal-response).
  2. Let newResponse be a copy of response, except for its [body](https://fetch.spec.whatwg.org/#concept-response-body).
  3. If response’s [body](https://fetch.spec.whatwg.org/#concept-response-body) is non-null, then set newResponse’s [body](https://fetch.spec.whatwg.org/#concept-response-body) to the result of [cloning](https://fetch.spec.whatwg.org/#concept-body-clone) response’s [body](https://fetch.spec.whatwg.org/#concept-response-body).
  4. Return newResponse.

A fresh response is a [response](https://fetch.spec.whatwg.org/#concept-response) whose [current age](https://httpwg.org/specs/rfc9111.html#age.calculations) is within its [freshness lifetime](https://httpwg.org/specs/rfc9111.html#calculating.freshness.lifetime).
A stale-while-revalidate response is a [response](https://fetch.spec.whatwg.org/#concept-response) that is not a [fresh response](https://fetch.spec.whatwg.org/#concept-fresh-response) and whose [current age](https://httpwg.org/specs/rfc9111.html#age.calculations) is within the [stale-while-revalidate lifetime](https://httpwg.org/specs/rfc5861.html#n-the-stale-while-revalidate-cache-control-extension). [[HTTP-CACHING]](https://fetch.spec.whatwg.org/#biblio-http-caching "HTTP Caching") [[STALE-WHILE-REVALIDATE]](https://fetch.spec.whatwg.org/#biblio-stale-while-revalidate "HTTP Cache-Control Extensions for Stale Content")
A stale response is a [response](https://fetch.spec.whatwg.org/#concept-response) that is not a [fresh response](https://fetch.spec.whatwg.org/#concept-fresh-response) or a [stale-while-revalidate response](https://fetch.spec.whatwg.org/#concept-stale-while-revalidate-response).

The location URL of a [response](https://fetch.spec.whatwg.org/#concept-response) response, given null or an [ASCII string](https://infra.spec.whatwg.org/#ascii-string) requestFragment, is the value returned by the following steps. They return null, failure, or a [URL](https://url.spec.whatwg.org/#concept-url).
  1. If response’s [status](https://fetch.spec.whatwg.org/#concept-response-status) is not a [redirect status](https://fetch.spec.whatwg.org/#redirect-status), then return null.
  2. Let location be the result of [extracting header list values](https://fetch.spec.whatwg.org/#extract-header-list-values) given ``Location`` and response’s [header list](https://fetch.spec.whatwg.org/#concept-response-header-list).
  3. If location is a [header value](https://fetch.spec.whatwg.org/#header-value), then set location to the result of [parsing](https://url.spec.whatwg.org/#concept-url-parser) location with response’s [URL](https://fetch.spec.whatwg.org/#concept-response-url).
If response was constructed through the `Response[](https://fetch.spec.whatwg.org/#response)` constructor, response’s [URL](https://fetch.spec.whatwg.org/#concept-response-url) will be null, meaning that location will only parse successfully if it is an [absolute-URL-with-fragment string](https://url.spec.whatwg.org/#absolute-url-with-fragment-string).
  4. If location is a [URL](https://url.spec.whatwg.org/#concept-url) whose [fragment](https://url.spec.whatwg.org/#concept-url-fragment) is null, then set location’s [fragment](https://url.spec.whatwg.org/#concept-url-fragment) to requestFragment.
This ensures that synthetic (indeed, all) responses follow the processing model for redirects defined by HTTP. [[HTTP]](https://fetch.spec.whatwg.org/#biblio-http "HTTP Semantics")
  5. Return location.


The [location URL](https://fetch.spec.whatwg.org/#concept-response-location-url) algorithm is exclusively used for redirect handling in this standard and in HTML’s navigate algorithm which handles redirects manually. [[HTML]](https://fetch.spec.whatwg.org/#biblio-html "HTML Standard")

###  2.5. Resolving domains
To resolve an origin, given a [network partition key](https://fetch.spec.whatwg.org/#network-partition-key) key and an [origin](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin) origin:
  1. If origin’s [host](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin-host) is an [IP address](https://url.spec.whatwg.org/#ip-address), then return « origin’s [host](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin-host) ».
  2. If origin’s [host](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin-host)’s [public suffix](https://url.spec.whatwg.org/#host-public-suffix) is "`localhost`" or "`localhost.`", then return « `::1`, `127.0.0.1` ».
  3. Perform an [implementation-defined](https://infra.spec.whatwg.org/#implementation-defined) operation to turn origin into a [set](https://infra.spec.whatwg.org/#ordered-set) of one or more [IP addresses](https://url.spec.whatwg.org/#ip-address).
It is also [implementation-defined](https://infra.spec.whatwg.org/#implementation-defined) whether other operations might be performed to get connection information beyond just [IP addresses](https://url.spec.whatwg.org/#ip-address). For example, if origin’s [scheme](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin-scheme) is an [HTTP(S) scheme](https://fetch.spec.whatwg.org/#http-scheme), the implementation might perform a DNS query for HTTPS RRs. [[SVCB]](https://fetch.spec.whatwg.org/#biblio-svcb "Service Binding and Parameter Specification via the DNS \(SVCB and HTTPS Resource Records\)")
If this operation succeeds, return the [set](https://infra.spec.whatwg.org/#ordered-set) of [IP addresses](https://url.spec.whatwg.org/#ip-address) and any additional [implementation-defined](https://infra.spec.whatwg.org/#implementation-defined) information.
  4. Return failure.


The results of [resolve an origin](https://fetch.spec.whatwg.org/#resolve-an-origin) may be cached. If they are cached, key should be used as part of the cache key.
Typically this operation would involve DNS and as such caching can happen on DNS servers without key being taken into account. Depending on the implementation it might also not be possible to take key into account locally. [[RFC1035]](https://fetch.spec.whatwg.org/#biblio-rfc1035 "Domain names - implementation and specification")
The order of the [IP addresses](https://url.spec.whatwg.org/#ip-address) that the [resolve an origin](https://fetch.spec.whatwg.org/#resolve-an-origin) algorithm can return can differ between invocations.
The particulars (apart from the cache key) are not tied down as they are not pertinent to the system the Fetch Standard establishes. Other documents ought not to build on this primitive without having a considered discussion with the Fetch Standard community first.
###  2.6. Connections

connection start time (default 0)


connection end time (default 0)


secure connection start time (default 0)
    A `DOMHighResTimeStamp[](https://w3c.github.io/hr-time/#dom-domhighrestimestamp)`.

Return a new [connection timing info](https://fetch.spec.whatwg.org/#connection-timing-info) whose [domain lookup start time](https://fetch.spec.whatwg.org/#connection-timing-info-domain-lookup-start-time) is the result of [coarsen time](https://w3c.github.io/hr-time/#dfn-coarsen-time) given timingInfo’s [domain lookup start time](https://fetch.spec.whatwg.org/#connection-timing-info-domain-lookup-start-time) and crossOriginIsolatedCapability, [domain lookup end * * *
A new connection setting is "`no`", "`yes`", or "`yes-and-dedicated`".
To obtain a connection, given a [network partition key](https://fetch.spec.whatwg.org/#network-partition-key) key, [URL](https://url.spec.whatwg.org/#concept-url) url, boolean credentials, an optional [new connection setting](https://fetch.spec.whatwg.org/#new-connection-setting) new (default "`no`"), an optional boolean requireUnreliable (default false), and an optional [WebTransport-hash list](https://fetch.spec.whatwg.org/#webtransport-hash-list) webTransportHashes (default « »):
  1. If new is "`no`":
    1. [Assert](https://infra.spec.whatwg.org/#assert): webTransportHashes [is empty](https://infra.spec.whatwg.org/#list-is-empty).
    2. Let connections be a set of [connections](https://fetch.spec.whatwg.org/#concept-connection) in the user agent’s [connection pool](https://fetch.spec.whatwg.org/#concept-connection-pool) whose [key](https://fetch.spec.whatwg.org/#connection-key) is key, [origin](https://fetch.spec.whatwg.org/#connection-origin) is url’s [origin](https://url.spec.whatwg.org/#concept-url-origin), and [credentials](https://fetch.spec.whatwg.org/#connection-credentials) is credentials.
    3. If connections is not empty and requireUnreliable is false, then return one of connections.
    4. If there is a [connection](https://fetch.spec.whatwg.org/#concept-connection) capable of supporting unreliable transport in connections, e.g., HTTP/3, then return that [connection](https://fetch.spec.whatwg.org/#concept-connection).
  2. Let proxies be the result of finding proxies for url in an [implementation-defined](https://infra.spec.whatwg.org/#implementation-defined) manner. If there are no proxies, let proxies be « "`DIRECT`" ».
This is where non-standard technology such as [Web Proxy Auto-Discovery Protocol (WPAD)](https://en.wikipedia.org/wiki/Web_Proxy_Auto-Discovery_Protocol) and [proxy auto-config (PAC)](https://en.wikipedia.org/wiki/Proxy_auto-config) come into play. The "`DIRECT`" value means to not use a proxy for this particular url.
  3. Let timingInfo be a new [connection timing info](https://fetch.spec.whatwg.org/#connection-timing-info).
  4. [For each](https://infra.spec.whatwg.org/#list-iterate) proxy of proxies:
    1. Set timingInfo’s [domain lookup start time](https://fetch.spec.whatwg.org/#connection-timing-info-domain-lookup-start-time) to the [unsafe shared current time](https://w3c.github.io/hr-time/#dfn-unsafe-shared-current-time).
    2. Let hosts be « url’s [origin](https://url.spec.whatwg.org/#concept-url-origin)’s [host](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin-host) ».
    3. If proxy is "`DIRECT`", then set hosts to the result of running [resolve an origin](https://fetch.spec.whatwg.org/#resolve-an-origin) given key and url’s [origin](https://url.spec.whatwg.org/#concept-url-origin).
    4. If hosts is failure, then [continue](https://infra.spec.whatwg.org/#iteration-continue).
    5. Set timingInfo’s [domain lookup end time](https://fetch.spec.whatwg.org/#connection-timing-info-domain-lookup-end-time) to the [unsafe shared current time](https://w3c.github.io/hr-time/#dfn-unsafe-shared-current-time).
    6. Let connection be the result of running this step: run [create a connection](https://fetch.spec.whatwg.org/#create-a-connection) given key, url’s [origin](https://url.spec.whatwg.org/#concept-url-origin), credentials, proxy, an [implementation-defined](https://infra.spec.whatwg.org/#implementation-defined) [host](https://url.spec.whatwg.org/#concept-host) from hosts, timingInfo, requireUnreliable, and webTransportHashes an [implementation-defined](https://infra.spec.whatwg.org/#implementation-defined) number of times, [in parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel) from each other, and wait for at least 1 to return a value. In an [implementation-defined](https://infra.spec.whatwg.org/#implementation-defined) manner, select a value to return from the returned values and return it. Any other returned values that are [connections](https://fetch.spec.whatwg.org/#concept-connection) may be closed.
Essentially this allows an implementation to pick one or more [IP addresses](https://url.spec.whatwg.org/#ip-address) from the return value of [resolve an origin](https://fetch.spec.whatwg.org/#resolve-an-origin) (assuming proxy is "`DIRECT`") and race them against each other, favor [IPv6 addresses](https://url.spec.whatwg.org/#concept-ipv6), retry in case of a timeout, etc.
    7. If connection is failure, then [continue](https://infra.spec.whatwg.org/#iteration-continue).
    8. If new is not "`yes-and-dedicated`", then [append](https://infra.spec.whatwg.org/#set-append) connection to the user agent’s [connection pool](https://fetch.spec.whatwg.org/#concept-connection-pool).
    9. Return connection.
  5. Return failure.


This is intentionally a little vague as there are a lot of nuances to connection management that are best left to the discretion of implementers. Describing this helps explain the `<link rel=preconnect>` feature and clearly stipulates that [connections](https://fetch.spec.whatwg.org/#concept-connection) are keyed on [credentials](https://fetch.spec.whatwg.org/#credentials). The latter clarifies that, e.g., TLS session identifiers are not reused across [connections](https://fetch.spec.whatwg.org/#concept-connection) whose [credentials](https://fetch.spec.whatwg.org/#connection-credentials) are false with [connections](https://fetch.spec.whatwg.org/#concept-connection) whose [credentials](https://fetch.spec.whatwg.org/#connection-credentials) are true.
* * *
To create a connection, given a [network partition key](https://fetch.spec.whatwg.org/#network-partition-key) key, [origin](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin) origin, boolean credentials, string proxy, [host](https://url.spec.whatwg.org/#concept-host) host, [connection timing info](https://fetch.spec.whatwg.org/#connection-timing-info) timingInfo, boolean requireUnreliable, and a [WebTransport-hash list](https://fetch.spec.whatwg.org/#webtransport-hash-list) webTransportHashes:
  1. Set timingInfo’s [connection start time](https://fetch.spec.whatwg.org/#connection-timing-info-connection-start-time) to the [unsafe shared current time](https://w3c.github.io/hr-time/#dfn-unsafe-shared-current-time).
  2. Let connection be a new [connection](https://fetch.spec.whatwg.org/#concept-connection) whose [key](https://fetch.spec.whatwg.org/#connection-key) is key, [origin](https://fetch.spec.whatwg.org/#connection-origin) is origin, [credentials](https://fetch.spec.whatwg.org/#connection-credentials) is credentials, and [timing info](https://fetch.spec.whatwg.org/#concept-connection-timing-info) is timingInfo. [Record connection timing info](https://fetch.spec.whatwg.org/#record-connection-timing-info) given connection and use connection to establish an HTTP connection to host, taking proxy and origin into account, with the following caveats: [[HTTP]](https://fetch.spec.whatwg.org/#biblio-http "HTTP Semantics") [[HTTP1]](https://fetch.spec.whatwg.org/#biblio-http1 "HTTP/1.1") [[TLS]](https://fetch.spec.whatwg.org/#biblio-tls "The Transport Layer Security \(TLS\) Protocol Version 1.3")
     * If requireUnreliable is true, then establish a connection capable of unreliable transport, e.g., an HTTP/3 connection. [[HTTP3]](https://fetch.spec.whatwg.org/#biblio-http3 "HTTP/3")
     * When establishing a connection capable of unreliable transport, enable options that are necessary for WebTransport. For HTTP/3, this means including `SETTINGS_ENABLE_WEBTRANSPORT` with a value of `1` and `H3_DATAGRAM` with a value of `1` in the initial `SETTINGS` frame. [[WEBTRANSPORT-HTTP3]](https://fetch.spec.whatwg.org/#biblio-webtransport-http3 "WebTransport over HTTP/3") [[HTTP3-DATAGRAM]](https://fetch.spec.whatwg.org/#biblio-http3-datagram "HTTP Datagrams and the Capsule Protocol")
     * If credentials is false, then do not send a TLS client certificate.
     * If webTransportHashes [is not empty](https://infra.spec.whatwg.org/#list-is-empty), instead of using the default certificate verification algorithm, consider the server certificate valid if it meets the [custom certificate requirements](https://w3c.github.io/webtransport/#custom-certificate-requirements) and if [verifying the certificate hash](https://w3c.github.io/webtransport/#verify-a-certificate-hash) against webTransportHashes returns true. If either condition is not met, then return failure.
     * If establishing a connection does not succeed (e.g., a UDP, TCP, or TLS error), then return failure.
  3. Set timingInfo’s [ALPN negotiated protocol](https://fetch.spec.whatwg.org/#connection-timing-info-alpn-negotiated-protocol) to connection’s ALPN Protocol ID, with the following caveats: [[RFC7301]](https://fetch.spec.whatwg.org/#biblio-rfc7301 "Transport Layer Security \(TLS\) Application-Layer Protocol Negotiation Extension")
     * When a proxy is configured, if a tunnel connection is established then this must be the ALPN Protocol ID of the tunneled protocol, otherwise it must be the ALPN Protocol ID of the first hop to the proxy.
     * In case the user agent is using an experimental, non-registered protocol, the user agent must use the used ALPN Protocol ID, if any. If ALPN was not used for protocol negotiations, the user agent may use another descriptive string.
timingInfo’s [ALPN negotiated protocol](https://fetch.spec.whatwg.org/#connection-timing-info-alpn-negotiated-protocol) is intended to identify the network protocol in use regardless of how it was actually negotiated; that is, even if ALPN is not used to negotiate the network protocol, this is the ALPN Protocol IDs that indicates the protocol in use.
IANA maintains a [list of ALPN Protocol IDs](https://www.iana.org/assignments/tls-extensiontype-values/tls-extensiontype-values.xhtml#alpn-protocol-ids).
  4. Return connection.


* * *
To record connection timing info given a [connection](https://fetch.spec.whatwg.org/#concept-connection) connection, let timingInfo be connection’s [timing info](https://fetch.spec.whatwg.org/#concept-connection-timing-info) and observe these requirements:
  * timingInfo’s [connection end time](https://fetch.spec.whatwg.org/#connection-timing-info-connection-end-time) should be the [unsafe shared current time](https://w3c.github.io/hr-time/#dfn-unsafe-shared-current-time) immediately after establishing the connection to the server or proxy, as follows:
    * The returned time must include the time interval to establish the transport connection, as well as other time intervals such as SOCKS authentication. It must include the time interval to complete enough of the TLS handshake to request the resource.
    * If the user agent used TLS False Start for this connection, this interval must not include the time needed to receive the server’s Finished message. [[RFC7918]](https://fetch.spec.whatwg.org/#biblio-rfc7918 "Transport Layer Security \(TLS\) False Start")
    * If the user agent sends the request with early data without waiting for the full handshake to complete, this interval must not include the time needed to receive the server’s ServerHello message. [[RFC8470]](https://fetch.spec.whatwg.org/#biblio-rfc8470 "Using Early Data in HTTP")
    * If the user agent waits for full handshake completion to send the request, this interval includes the full TLS handshake even if other requests were sent using early data on connection.
Suppose the user agent establishes an HTTP/2 connection over TLS 1.3 to send a `GET` request and a `POST` request. It sends the ClientHello at time t1 and then sends the `GET` request with early data. The `POST` request is not safe ([[HTTP]](https://fetch.spec.whatwg.org/#biblio-http "HTTP Semantics"), section 9.2.1), so the user agent waits to complete the handshake at time t2 before sending it. Although both requests used the same connection, the `GET` request reports a connection end time of t1, while the `POST` request reports t2.
  * If a secure transport is used, timingInfo’s [secure connection start time](https://fetch.spec.whatwg.org/#connection-timing-info-secure-connection-start-time) should be the result of calling [unsafe shared current time](https://w3c.github.io/hr-time/#dfn-unsafe-shared-current-time) immediately before starting the handshake process to secure connection. [[TLS]](https://fetch.spec.whatwg.org/#biblio-tls "The Transport Layer Security \(TLS\) Protocol Version 1.3")
  * If connection is an HTTP/3 connection, timingInfo’s [connection start time](https://fetch.spec.whatwg.org/#connection-timing-info-connection-start-time) and timingInfo’s [secure connection start time](https://fetch.spec.whatwg.org/#connection-timing-info-secure-connection-start-time) must be equal. (In HTTP/3 the secure transport handshake process is performed as part of the initial connection setup.) [[HTTP3]](https://fetch.spec.whatwg.org/#biblio-http3 "HTTP/3")


The [clamp and coarsen connection timing info](https://fetch.spec.whatwg.org/#clamp-and-coarsen-connection-timing-info) algorithm ensures that details of reused connections are not exposed and time values are coarsened.
###  2.7. Network partition keys

###  3.2. ``Origin`` header
The ``Origin`` request [header](https://fetch.spec.whatwg.org/#concept-header) indicates where a [fetch](https://fetch.spec.whatwg.org/#concept-fetch) originates from.
The `[`Origin`](https://fetch.spec.whatwg.org/#http-origin)` header is a version of the ``Referer`` [sic] header that does not reveal a [path](https://url.spec.whatwg.org/#concept-url-path). It is used for all [HTTP fetches](https://fetch.spec.whatwg.org/#concept-http-fetch) whose [request](https://fetch.spec.whatwg.org/#concept-request)’s [response tainting](https://fetch.spec.whatwg.org/#concept-request-response-tainting) is "`cors`", as well as those where [request](https://fetch.spec.whatwg.org/#concept-request)’s [method](https://fetch.spec.whatwg.org/#concept-request-method) is neither ``GET`` nor ``HEAD``. Due to compatibility constraints it is not included in all [fetches](https://fetch.spec.whatwg.org/#concept-fetch).
Its possible [values](https://fetch.spec.whatwg.org/#concept-header-value) are all the return values of [byte-serializing a request origin](https://fetch.spec.whatwg.org/#byte-serializing-a-request-origin), given a [request](https://fetch.spec.whatwg.org/#concept-request). These are represented by the following [ABNF](https://fetch.spec.whatwg.org/#abnf):

```

dec-octet         = DIGIT                 ; 0-9
                  / %x31-39 DIGIT         ; 10-99
                  / "1" 2DIGIT            ; 100-199
                  / "2" %x30-34 DIGIT     ; 200-249
                  / "25" %x30-35          ; 250-255

serialized-ipv6   =                            7( h16 ":" ) h16
                  /                       "::" 5( h16 ":" ) h16

                  / [ *1( h16 ":" ) h16 ] "::" 3( h16 ":" ) h16
                  / [ *2( h16 ":" ) h16 ] "::" 2( h16 ":" ) h16
                  / [ *3( h16 ":" ) h16 ] "::"    h16 ":"   h16
                  / [ *4( h16 ":" ) h16 ] "::"              h16
                  / [ *5( h16 ":" ) h16 ] "::"
h16               = "0" / ( non-zero-hex 0*3hex )
non-zero-hex      = %x31-39 / %x61-66 ; '1'-'9' or lowercase 'a'-'f'
hex               = %x30-39 / %x61-66 ; '0'-'9' or lowercase 'a'-'f

lower-alpha       = %x61-7A
lower-alphanum    = [lower-alpha](https://fetch.spec.whatwg.org/#lower-alpha) / DIGIT
domain-label      = [lower-alphanum](https://fetch.spec.whatwg.org/#lower-alphanum) / ( [lower-alphanum](https://fetch.spec.whatwg.org/#lower-alphanum) *( [lower-alphanum](https://fetch.spec.whatwg.org/#lower-alphanum) / "-" ) [lower-alphanum](https://fetch.spec.whatwg.org/#lower-alphanum) )
serialized-domain = *( [domain-label](https://fetch.spec.whatwg.org/#domain-label) "." ) [domain-label](https://fetch.spec.whatwg.org/#domain-label)

serialized-scheme = [lower-alpha](https://fetch.spec.whatwg.org/#lower-alpha) *( [lower-alphanum](https://fetch.spec.whatwg.org/#lower-alphanum) / "+" / "-" / "." )

serialized-origin = [serialized-scheme](https://fetch.spec.whatwg.org/#serialized-scheme) "://" [serialized-host](https://fetch.spec.whatwg.org/#serialized-host) [ ":" [serialized-port](https://fetch.spec.whatwg.org/#serialized-port) ]
origin-or-null    = [serialized-origin](https://fetch.spec.whatwg.org/#serialized-origin) / %s"null" ; case-sensitive

Origin = [origin-or-null](https://fetch.spec.whatwg.org/#origin-or-null)

This supplants the definition in The Web Origin Concept. [[ORIGIN]](https://fetch.spec.whatwg.org/#biblio-origin "The Web Origin Concept")
The origin serialization defined here is more constrained than [[RFC3986]](https://fetch.spec.whatwg.org/#biblio-rfc3986 "Uniform Resource Identifier \(URI\): Generic Syntax")’s grammar in two substantial ways. First, scheme and domains serializations are all lower case ASCII, without percent encoding. Second, following the recommendations of [URL § 3.6 Host serializing](https://url.spec.whatwg.org/#host-serializing) and [[RFC5952]](https://fetch.spec.whatwg.org/#biblio-rfc5952 "A Recommendation for IPv6 Address Text Representation"), IPv6 addresses are limited as follows:

  * Leading zeros are forbidden.
  * All hex characters are lowercase.
  * "::" can’t elide only a single "0" block, so we allow at most 6 blocks when "::" is present.

###  3.3. CORS protocol
To allow sharing responses cross-origin and allow for more versatile [fetches](https://fetch.spec.whatwg.org/#concept-fetch) than possible with HTML’s `form[](https://html.spec.whatwg.org/multipage/forms.html#the-form-element)` element, the CORS protocol exists. It is layered on top of HTTP and allows responses to declare they can be shared with other [origins](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin).
It needs to be an opt-in mechanism to prevent leaking data from responses behind a firewall (intranets). Additionally, for [requests](https://fetch.spec.whatwg.org/#concept-request) including [credentials](https://fetch.spec.whatwg.org/#credentials) it needs to be opt-in to prevent leaking potentially-sensitive data.
This section explains the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol) as it pertains to server developers. Requirements for user agents are part of the [fetch](https://fetch.spec.whatwg.org/#concept-fetch) algorithm, except for the [new HTTP header syntax](https://fetch.spec.whatwg.org/#http-new-header-syntax).
####  3.3.1. General
The [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol) consists of a set of headers that indicates whether a response can be shared cross-origin.
For [requests](https://fetch.spec.whatwg.org/#concept-request) that are more involved than what is possible with HTML’s `form[](https://html.spec.whatwg.org/multipage/forms.html#the-form-element)` element, a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) is performed, to ensure [request](https://fetch.spec.whatwg.org/#concept-request)’s [current URL](https://fetch.spec.whatwg.org/#concept-request-current-url) supports the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol).
####  3.3.2. HTTP requests
A CORS request is an HTTP request that includes an `[`Origin`](https://fetch.spec.whatwg.org/#http-origin)` header. It cannot be reliably identified as participating in the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol) as the `[`Origin`](https://fetch.spec.whatwg.org/#http-origin)` header is also included for all [requests](https://fetch.spec.whatwg.org/#concept-request) whose [method](https://fetch.spec.whatwg.org/#concept-request-method) is neither ``GET`` nor ``HEAD``.
A CORS-preflight request is a [CORS request](https://fetch.spec.whatwg.org/#cors-request) that checks to see if the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol) is understood. It uses ``OPTIONS`` as [method](https://fetch.spec.whatwg.org/#concept-method) and includes the following [header](https://fetch.spec.whatwg.org/#concept-header):

``Access-Control-Request-Method``

Indicates which [method](https://fetch.spec.whatwg.org/#concept-method) a future [CORS request](https://fetch.spec.whatwg.org/#cors-request) to the same resource might use.
A [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) can also include the following [header](https://fetch.spec.whatwg.org/#concept-header):

``Access-Control-Request-Headers``

Indicates which [headers](https://fetch.spec.whatwg.org/#concept-header) a future [CORS request](https://fetch.spec.whatwg.org/#cors-request) to the same resource might use.
####  3.3.3. HTTP responses
An HTTP response to a [CORS request](https://fetch.spec.whatwg.org/#cors-request) can include the following [headers](https://fetch.spec.whatwg.org/#concept-header):

``Access-Control-Allow-Origin``

Indicates whether the response can be shared, via returning the literal [value](https://fetch.spec.whatwg.org/#concept-header-value) of the `[`Origin`](https://fetch.spec.whatwg.org/#http-origin)` request [header](https://fetch.spec.whatwg.org/#concept-header) (which can be ``null``) or ``*`` in a response.

``Access-Control-Allow-Credentials``

Indicates whether the response can be shared when [request](https://fetch.spec.whatwg.org/#concept-request)’s [credentials mode](https://fetch.spec.whatwg.org/#concept-request-credentials-mode) is "`include`".
For a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request), [request](https://fetch.spec.whatwg.org/#concept-request)’s [credentials mode](https://fetch.spec.whatwg.org/#concept-request-credentials-mode) is always "`same-origin`", i.e., it excludes credentials, but for any subsequent [CORS requests](https://fetch.spec.whatwg.org/#cors-request) it might not be. Support therefore needs to be indicated as part of the HTTP response to the [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) as well.
An HTTP response to a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) can include the following [headers](https://fetch.spec.whatwg.org/#concept-header):

``Access-Control-Allow-Methods``

Indicates which [methods](https://fetch.spec.whatwg.org/#concept-method) are supported by the [response](https://fetch.spec.whatwg.org/#concept-response)’s [URL](https://fetch.spec.whatwg.org/#concept-response-url) for the purposes of the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol).
The ``Allow`` [header](https://fetch.spec.whatwg.org/#concept-header) is not relevant for the purposes of the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol).

``Access-Control-Allow-Headers``

Indicates which [headers](https://fetch.spec.whatwg.org/#concept-header) are supported by the [response](https://fetch.spec.whatwg.org/#concept-response)’s [URL](https://fetch.spec.whatwg.org/#concept-response-url) for the purposes of the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol).

``Access-Control-Max-Age``

Indicates the number of seconds (5 by default) the information provided by the `[`Access-Control-Allow-Methods`](https://fetch.spec.whatwg.org/#http-access-control-allow-methods)` and `[`Access-Control-Allow-Headers`](https://fetch.spec.whatwg.org/#http-access-control-allow-headers)` [headers](https://fetch.spec.whatwg.org/#concept-header) can be cached.
An HTTP response to a [CORS request](https://fetch.spec.whatwg.org/#cors-request) that is not a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) can also include the following [header](https://fetch.spec.whatwg.org/#concept-header):

``Access-Control-Expose-Headers``

Indicates which [headers](https://fetch.spec.whatwg.org/#concept-header) can be exposed as part of the response by listing their [names](https://fetch.spec.whatwg.org/#concept-header-name).

A successful HTTP response, i.e., one where the server developer intends to share it, to a [CORS request](https://fetch.spec.whatwg.org/#cors-request) can use any [status](https://fetch.spec.whatwg.org/#concept-status), as long as it includes the [headers](https://fetch.spec.whatwg.org/#concept-header) stated above with [values](https://fetch.spec.whatwg.org/#concept-header-value) matching up with the request.
A successful HTTP response to a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) is similar, except it is restricted to an [ok status](https://fetch.spec.whatwg.org/#ok-status), e.g., 200 or 204.
Any other kind of HTTP response is not successful and will either end up not being shared or fail the [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request). Be aware that any work the server performs might nonetheless leak through side channels, such as timing. If server developers wish to denote this explicitly, the 403 [status](https://fetch.spec.whatwg.org/#concept-status) can be used, coupled with omitting the relevant [headers](https://fetch.spec.whatwg.org/#concept-header).
If desired, “failure” could also be shared, but that would make it a successful HTTP response. That is why for a successful HTTP response to a [CORS request](https://fetch.spec.whatwg.org/#cors-request) that is not a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) the [status](https://fetch.spec.whatwg.org/#concept-status) can be anything, including 403.
Ultimately server developers have a lot of freedom in how they handle HTTP responses and these tactics can differ between the response to the [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) and the [CORS request](https://fetch.spec.whatwg.org/#cors-request) that follows it:
  * They can provide a static response. This can be helpful when working with caching intermediaries. A static response can both be successful and not successful depending on the [CORS request](https://fetch.spec.whatwg.org/#cors-request). This is okay.
  * They can provide a dynamic response, tuned to [CORS request](https://fetch.spec.whatwg.org/#cors-request). This can be helpful when the response body is to be tailored to a specific origin or a response needs to have credentials and be successful for a set of origins.

```
Access-Control-Request-Method    = [method](https://httpwg.org/specs/rfc9110.html#method.overview)
Access-Control-Request-Headers   = 1#[field-name](https://httpwg.org/specs/rfc9110.html#fields.names)

wildcard                         = "*"
Access-Control-Allow-Origin      = [origin-or-null](https://fetch.spec.whatwg.org/#origin-or-null) / [wildcard](https://fetch.spec.whatwg.org/#wildcard)

####  3.3.5. CORS protocol and credentials
When [request](https://fetch.spec.whatwg.org/#concept-request)’s [credentials mode](https://fetch.spec.whatwg.org/#concept-request-credentials-mode) is "`include`" it has an impact on the functioning of the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol) other than including [credentials](https://fetch.spec.whatwg.org/#credentials) in the [fetch](https://fetch.spec.whatwg.org/#concept-fetch).
In the old days, `XMLHttpRequest[](https://xhr.spec.whatwg.org/#xmlhttprequest)` could be used to set [request](https://fetch.spec.whatwg.org/#concept-request)’s [credentials mode](https://fetch.spec.whatwg.org/#concept-request-credentials-mode) to "`include`":

```
var client = new XMLHttpRequest()
client.open("GET", "./")
client.withCredentials = true
/* … */

```

Nowadays, `fetch("./", { credentials:"include" }).then(/* … */)` suffices.
A [request](https://fetch.spec.whatwg.org/#concept-request)’s [credentials mode](https://fetch.spec.whatwg.org/#concept-request-credentials-mode) is not necessarily observable on the server; only when [credentials](https://fetch.spec.whatwg.org/#credentials) exist for a [request](https://fetch.spec.whatwg.org/#concept-request) can it be observed by virtue of the [credentials](https://fetch.spec.whatwg.org/#credentials) being included. Note that even so, a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) never includes [credentials](https://fetch.spec.whatwg.org/#credentials).
The server developer therefore needs to decide whether or not responses "tainted" with [credentials](https://fetch.spec.whatwg.org/#credentials) can be shared. And also needs to decide if [requests](https://fetch.spec.whatwg.org/#concept-request) necessitating a [CORS-preflight request](https://fetch.spec.whatwg.org/#cors-preflight-request) can include [credentials](https://fetch.spec.whatwg.org/#credentials). Generally speaking, both sharing responses and allowing requests with [credentials](https://fetch.spec.whatwg.org/#credentials) is rather unsafe, and extreme care has to be taken to avoid the [confused deputy problem](https://en.wikipedia.org/wiki/Confused_deputy_problem).
To share responses with [credentials](https://fetch.spec.whatwg.org/#credentials), the `[`Access-Control-Allow-Origin`](https://fetch.spec.whatwg.org/#http-access-control-allow-origin)` and `[`Access-Control-Allow-Credentials`](https://fetch.spec.whatwg.org/#http-access-control-allow-credentials)` [headers](https://fetch.spec.whatwg.org/#concept-header) are important. The following table serves to illustrate the various legal and illegal combinations for a request to `https://rabbit.invalid/`:
| Request’s credentials mode   | `[`Access-Control-Allow-Origin`](https://fetch.spec.whatwg.org/#http-access-control-allow-origin)`   | `[`Access-Control-Allow-Credentials`](https://fetch.spec.whatwg.org/#http-access-control-allow-credentials)`   | Shared?   | Notes   |
| --- | --- | --- | --- | --- |
| "`omit`"   | ``*``   | Omitted   | ✅   | —​   |
| "`omit`"   | ``*``   | ``true``   | ✅   | If credentials mode is not "`include`", then `[`Access-Control-Allow-Credentials`](https://fetch.spec.whatwg.org/#http-access-control-allow-credentials)` is ignored.   |
| "`omit`"   | ``https://rabbit.invalid/``   | Omitted   | ❌   | A [serialized](https://html.spec.whatwg.org/multipage/browsers.html#ascii-serialisation-of-an-origin) origin has no trailing slash.   |
| "`omit`"   | ``https://rabbit.invalid``   | Omitted   | ✅   | —​   |
| "`include`"   | ``*``   | ``true``   | ❌   | If credentials mode is "`include`", then `[`Access-Control-Allow-Origin`](https://fetch.spec.whatwg.org/#http-access-control-allow-origin)` cannot be ``*``.   |
| "`include`"   | ``https://rabbit.invalid``   | ``true``   | ✅   | —​   |
| "`include`"   | ``https://rabbit.invalid``   | ``True``   | ❌   | ``true`` is (byte) case-sensitive.   |
Similarly, `[`Access-Control-Expose-Headers`](https://fetch.spec.whatwg.org/#http-access-control-expose-headers)`, `[`Access-Control-Allow-Methods`](https://fetch.spec.whatwg.org/#http-access-control-allow-methods)`, and `[`Access-Control-Allow-Headers`](https://fetch.spec.whatwg.org/#http-access-control-allow-headers)` response headers can only use ``*`` as value when [request](https://fetch.spec.whatwg.org/#concept-request)’s [credentials mode](https://fetch.spec.whatwg.org/#concept-request-credentials-mode) is not "`include`".
####  3.3.6. Examples
A script at `https://foo.invalid/` wants to fetch some data from `https://bar.invalid/`. (Neither [credentials](https://fetch.spec.whatwg.org/#credentials) nor response header access is important.)

```
var url = "https://bar.invalid/api?key=730d67a37d7f3d802e96396d00280768773813fbe726d116944d814422fc1a45&data=about:unicorn";
fetch(url).then(success, failure)

```

This will use the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol), though this is entirely transparent to the developer from `foo.invalid`. As part of the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol), the user agent will include the `[`Origin`](https://fetch.spec.whatwg.org/#http-origin)` header in the request:

```
Origin: https://foo.invalid

```

Upon receiving a response from `bar.invalid`, the user agent will verify the `[`Access-Control-Allow-Origin`](https://fetch.spec.whatwg.org/#http-access-control-allow-origin)` response header. If its value is either ``https://foo.invalid`` or ``*``, the user agent will invoke the `success` callback. If it has any other value, or is missing, the user agent will invoke the `failure` callback.
The developer of `foo.invalid` is back, and now wants to fetch some data from `bar.invalid` while also accessing a response header.

```
fetch(url).then(response => {
  var hsts = response.headers.get("strict-transport-security"),
      csp = response.headers.get("content-security-policy")
  log(hsts, csp)
})

```

`bar.invalid` provides a correct `[`Access-Control-Allow-Origin`](https://fetch.spec.whatwg.org/#http-access-control-allow-origin)` response header per the earlier example. The values of `hsts` and `csp` will depend on the `[`Access-Control-Expose-Headers`](https://fetch.spec.whatwg.org/#http-access-control-expose-headers)` response header. For example, if the response included the following headers

```
Content-Security-Policy: default-src 'self'
Strict-Transport-Security: max-age=31536000; includeSubdomains; preload
Access-Control-Expose-Headers: Content-Security-Policy

```

then `hsts` would be null and `csp` would be "`default-src 'self'`", even though the response did include both headers. This is because `bar.invalid` needs to explicitly share each header by listing their names in the `[`Access-Control-Expose-Headers`](https://fetch.spec.whatwg.org/#http-access-control-expose-headers)` response header.
Alternatively, if `bar.invalid` wanted to share all its response headers, for requests that do not include [credentials](https://fetch.spec.whatwg.org/#credentials), it could use ``*`` as value for the `[`Access-Control-Expose-Headers`](https://fetch.spec.whatwg.org/#http-access-control-expose-headers)` response header. If the request would have included [credentials](https://fetch.spec.whatwg.org/#credentials), the response header names would have to be listed explicitly and ``*`` could not be used.
The developer of `foo.invalid` returns, now fetching some data from `bar.invalid` while including [credentials](https://fetch.spec.whatwg.org/#credentials). This time around the [CORS protocol](https://fetch.spec.whatwg.org/#cors-protocol) is no longer transparent to the developer as [credentials](https://fetch.spec.whatwg.org/#credentials) require an explicit opt-in:

```
fetch(url, { credentials:"include" }).then(success, failure)

```

This also makes any ``Set-Cookie`` response headers `bar.invalid` includes fully functional (they are ignored otherwise).
The user agent will make sure to include any relevant [credentials](https://fetch.spec.whatwg.org/#credentials) in the request. It will also put stricter requirements on the response. Not only will `bar.invalid` need to list ``https://foo.invalid`` as value for the `[`Access-Control-Allow-Origin`](https://fetch.spec.whatwg.org/#http-access-control-allow-origin)` header (``*`` is not allowed when [credentials](https://fetch.spec.whatwg.org/#credentials) are involved), the `[`Access-Control-Allow-Credentials`](https://fetch.spec.whatwg.org/#http-access-control-allow-credentials)` header has to be present too:

```
Access-Control-Allow-Origin: https://foo.invalid
Access-Control-Allow-Credentials: true

```

If the response does not include those two headers with those values, the `failure` callback will be invoked. However, any ``Set-Cookie`` response headers will be respected.
####  3.3.7. CORS protocol exceptions
Specifications have allowed limited exceptions to the CORS safelist for non-safelisted ``Content-Type`` header values. These exceptions are made for requests that can be triggered by web content but whose headers and bodies can be only minimally controlled by the web content. Therefore, servers should expect cross-origin web content to be allowed to trigger non-preflighted requests with the following non-safelisted ``Content-Type`` header values:
  * ``application/csp-report`` [[CSP]](https://fetch.spec.whatwg.org/#biblio-csp "Content Security Policy Level 3")
  * ``application/expect-ct-report+json`` [[RFC9163]](https://fetch.spec.whatwg.org/#biblio-rfc9163 "Expect-CT Extension for HTTP")
  * ``application/xss-auditor-report``
  * ``application/ocsp-request`` [[RFC6960]](https://fetch.spec.whatwg.org/#biblio-rfc6960 "X.509 Internet Public Key Infrastructure Online Certificate Status Protocol - OCSP")


Specifications should avoid introducing new exceptions and should only do so with careful consideration for the security consequences. New exceptions can be proposed by [filing an issue](https://github.com/whatwg/fetch/issues/new).
###  3.4. ``Content-Length`` header
The ``Content-Length`` header is largely defined in HTTP. Its processing model is defined here as the model defined in HTTP is not compatible with web content. [[HTTP]](https://fetch.spec.whatwg.org/#biblio-http "HTTP Semantics")
To extract a length from a [header list](https://fetch.spec.whatwg.org/#concept-header-list) headers, run these steps:
  1. Let values be the result of [getting, decoding, and splitting](https://fetch.spec.whatwg.org/#concept-header-list-get-decode-split) ``Content-Length`` from headers.

  3. Let candidateValue be null.

  6. Return candidateValue, interpreted as decimal number.
