###  14.11.1 Error correcting conditions for the three-qubit code[](https://qubit.guide/14.11-remarks-and-exercises-error-correction#error-correcting-conditions-for-the-three-qubit-code)
When building the Shor [[9,1,3]][[9,1,3]][[9,1,3]] code, we used the three-qubit code twice: once to correct for XXX-errors, and once for ZZZ-errors. However, there is no reason why we couldn’t instead have used one copy to correct for YYY-errors instead of XXX-errors, and we can see this using the dot-error diagrams.
Consider the stabiliser code given by S=⟨ZZ1,1ZZ⟩\mathcal{S}=\langle ZZ\mathbf{1},\mathbf{1}ZZ\rangleS=⟨ZZ1,1ZZ⟩. In Figure [14.13](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fig:all-weight-1-errors-three-qubit-code) we draw all the computational errors of weight at most 111, and we see that this does _not_ describe a correctable scenario. That is, as we already know, the three-qubit code cannot alone correct for all single-qubit errors.
![All computational errors of weight at most 1 for the three-qubit code given by \\langle ZZ\\mathbf{1},\\mathbf{1}ZZ\\rangle. Note that this describes a non-correctable scenario. In fact, both of the two rules are broken.](https://qubit.guide/qubit_guide_files/figure-html/all-weight-1-errors-three-qubit-code-1.png)
Figure 14.13: All computational errors of weight at most 111 for the three-qubit code given by ⟨ZZ1,1ZZ⟩\langle ZZ\mathbf{1},\mathbf{1}ZZ\rangle⟨ZZ1,1ZZ⟩. Note that this describes a _non_ -correctable scenario. In fact, _both_ of the two rules are broken. 
But now let’s look at XXX-, YYY-, and ZZZ-errors all individually and see what happens. As Figure [14.14](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fig:xyz-type-weight-1-errors-three-qubit-code) shows, the three-qubit code given by ⟨ZZ1,1ZZ⟩\langle ZZ\mathbf{1},\mathbf{1}ZZ\rangle⟨ZZ1,1ZZ⟩ can correct for all XXX-errors (as we already knew), but also for all YYY-errors!
![Different types of computational errors of weight at most 1. Left to right: X-type errors \(correctable\); Y-type errors \(correctable\); Z-type errors \(non-correctable\).](https://qubit.guide/qubit_guide_files/figure-html/xyz-type-weight-1-errors-three-qubit-code-1.png)
Figure 14.14: Different types of computational errors of weight at most 111. _Left to right:_ XXX-type errors (correctable); YYY-type errors (correctable); ZZZ-type errors (non-correctable). 
###  14.11.2 The smallest d=3d=3d=3 code, full stop[](https://qubit.guide/14.11-remarks-and-exercises-error-correction#the-smallest-d3-code-full-stop)
We have already seen the Shor [[9,1,3]][[9,1,3]][[9,1,3]] code, which can protect against any single-qubit error. Despite its simplicity, it is not the smallest code that can do this: that title belongs to the [[5,1,3]][[5,1,3]][[5,1,3]] stabiliser code, given by S=⟨XZZX1,1ZXXZ,X1XZZ,ZX1XZ⟩ \mathcal{S} = \langle XZZX\mathbf{1}, \mathbf{1}ZXXZ, X\mathbf{1}XZZ, ZX\mathbf{1}XZ\rangle S=⟨XZZX1,1ZXXZ,X1XZZ,ZX1XZ⟩ shown as a Tanner graph in Figure [**??**](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fig:five-qubit-code-tanner). Note that the stabiliser generators (i.e. parity checks) are related to each other by cyclic shifts: we just take different length-five chunks from the infinite string XZZX1XZZX1XZZX1…XZZX\mathbf{1}XZZX\mathbf{1}XZZX\mathbf{1}\ldotsXZZX1XZZX1XZZX1…. This code is unusual compared to the ones we have seen before, since it’s actually impossible to write its generators as operators that consist of either all XXX or all ZZZ.
![The Tanner graph for the \[\[5,1,3\]\] stabiliser code. Solid lines represent X-checks, and dashed ones Z-checks.](https://qubit.guide/qubit_guide_files/figure-html/unnamed-chunk-130-1.png)
Figure 14.15: The Tanner graph for the [[5,1,3]][[5,1,3]][[5,1,3]] stabiliser code. Solid lines represent XXX-checks, and dashed ones ZZZ-checks. 
This [[5,1,3]][[5,1,3]][[5,1,3]] code truly is optimal, in that it is the smallest possible[321](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fn321) quantum error correcting code with d=3d=3d=3. Indeed, suppose that we have nnn qubits representing one logical qubit, and each error XXX, YYY, or ZZZ on any of these nnn qubits maps the two-dimensional codespace to a different, mutually orthogonal subspace.[322](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fn322) This means that we have to fit the codespace, plus 3n3n3n two-dimensional subspaces, into the 2n2^n2n-dimensional Hilbert space associated with the nnn qubits. This implies that we need to satisfy 2(1+3n)⩽2n 2(1+3n) \leqslant 2^n 2(1+3n)⩽2n which tells us that we must have at least n⩾5n\geqslant 5n⩾5.
Note that this code is _not_ a CSS code! To prove this, we could use theorems about **transversal gates**. The smallest CSS code with d=3d=3d=3 is described in Exercise [14.11.10](https://qubit.guide/14.11-remarks-and-exercises-error-correction#smallest-d-3-css-code).[↩︎](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fnref321)
The counting argument above tells us that the smallest code must have _at least_ five qubits, but doesn’t tell us if we can actually make one with exactly five qubits! How do we actually go about finding optimal codes then? The answer is simply that we do not know — there is no universal prescription for designing optimal quantum codes. But we do know quite a few things about designing _good_ quantum codes.
One last thing to mention is how this code displays that quantum codes can be used for more than just error correction. The [[5,1,3]][[5,1,3]][[5,1,3]] code gives a way of designing a [**((3,5))((3,5))((3,5)) quantum secret sharing**](https://en.wikipedia.org/wiki/Quantum_secret_sharing) protocol.

###  14.11.13 Steane error correction: towards fault tolerance[](https://qubit.guide/14.11-remarks-and-exercises-error-correction#steane-error-correction-towards-fault-tolerance)
We have seen how we can measure the stabilisers of a stabiliser code by using a Hadamard test, resulting in ±1\pm1±1 outcomes. From these, we can determine where the errors are likely to have occurred and then correct them. In Chapter [15](https://qubit.guide/15-fault-tolerance#fault-tolerance), we will see that the scenario of fault-tolerant computation requires us to be very careful with how we construct our error-correcting circuits in order to minimise the propagation of faults that occur during the error-process itself. A particularly useful strategy is to not have multiple qubits interacting, but this contradicts the measurements of the stabilisers, since these, by definition, act on many qubits. There are a variety of ways to deal with this. In the case of CSS codes, Steane himself provided a particularly elegant method, which we will now explore.
Note that, while we are _motivated_ by the possibility of there being faults during the error correction, for now we will still assume that the error-correction process proceeds perfectly, and we are only trying to identify and fix errors on the incoming (logical) state ∣ψ⟩L|\psi\rangle_L∣ψ⟩L​.
