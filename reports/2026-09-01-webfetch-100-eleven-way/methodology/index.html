预先登记的评测方法

评测方法与公平性

主问题是“给定公开 URL，能否稳定返回正确、完整、可供 Agent 使用的正文”。搜索召回、登录交互、反机器人解锁和结构化 AI 抽取不混入主分数。

执行顺序

  1. 冻结当前版本数据集的标准答案、参考正文与复核清单，再运行任何方法。
  2. 本次保存结果的方法并发数为 11。执行器支持不同方法并行；同一方法内始终按相同 URL 顺序串行，并遵守该方法的冷却时间，避免并发状态和 QPS 干扰正确性。
  3. 每个方法使用相同 URL、超时和运行次数；保存完整响应或异常。
  4. 先判请求，再按显著标记、最小长度、评分核对点（事实组）和反向标记做程序判断。
  5. 主榜耗时只取“请求成功且程序判断通过”的调用；失败耗时另存用于诊断。
  6. 每条调用页并排展示题目、标准答案、方法输出和程序判定，供最终复核。
  7. HTML 只由 JSONL 与原始结果生成；不手工填写方法分数。

Cloudflare 为什么只测 /markdown

本轮参评：/markdown

它把浏览器加载后的页面转为 Markdown，并去除样式和脚本；与 Lexmount main_text、Firecrawl Markdown、Tavily Extract、Exa text 的“可读正文”目标最接近。

官方 Markdown 文档 →

不参评：/content

它返回执行 JavaScript 后的完整 HTML（包含 head），适合检查 DOM 渲染，不是清洗后的 Agent 正文。把它并列计分会同时改变输出契约和噪声水平。

当前内容裁判到底是什么

第一层是确定性机器初判：先确认请求成功，再要求输出命中显著标记、达到最小长度、覆盖每个预登记事实组，并且不含错误页或挑战页标记。字符串比较不调用 LLM，任何人用相同结果都能复算。

第二层是人工最终复核：调用页同时展示完整题目、参考答案、事实组、供应商输出和机器命中。复核者按正确性、完整性、可读性重新判断，可保存到浏览器或导出 JSON。机器初判可能因同义改写产生假阴性，也可能因关键词散落产生假阳性，所以不能直接冒充最终结论。

LLM judge 当前不进入主榜：若后续启用，只作为盲化的二级辅助审阅，必须固定模型、提示、量表和 JSON 结构，并由人工抽检。LLM 不能反向修改冻结标准答案。

因此本报告证明的是：评测过程可重算、每个判断可下钻、人工可以覆盖机器初判；不是声称单次关键词规则天然等同于最终质量。
