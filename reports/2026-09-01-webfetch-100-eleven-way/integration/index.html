接入 CowAgent 与其它 Agent 的最小可用路径

CowAgent 当前是仓库内置 HTTP + 文本/文档解析，不依赖外部 Web Fetch 供应商。接入点应在现有 WebFetch 类内部，通过 provider 配置切换，模型仍只看到一个 web_fetch。

建议路由原则

known public URL  -> one stable web_fetch tool; provider chosen by policy
PDF/document       -> route only to a method that passes the PDF ground truth
JavaScript page    -> route only to a rendering-capable method that passes the JS case
login/interaction  -> browser tool, never lightweight Web Fetch
search query       -> web_search first, then web_fetch selected result URLs
具体默认 provider 必须以本报告“结果分析”和逐案例事实覆盖率为准。认证失败的方法不能被判为产品能力失败，也不能在修复凭据前获得人工补分。

CowAgent 实现细节

  1. 保留现有 URL scheme 与 SSRF 检查，再调用供应商。
  2. 凭据只从环境配置读取；不进入 tool schema、artifact 或模型上下文。
  3. 区域由显式 provider 配置决定：Global 只调用 https://api.lexmount.com/v1/extract，CN 只调用 https://api.lexmount.cn/v1/extract；401 不跨域重试。
  4. 区分 authentication、rate_limit、upstream、content failure；HTTP 200 空正文不能算成功。
  5. fallback 同时记录 primary 与 fallback 的耗时、费用和 trace，否则指标会被隐藏。

跨 Agent 稳定契约

{
  "name": "web_fetch",
  "input": {"url": "https://example.com"},
  "output": {
    "title": "Example Domain",
    "content": "...",
    "final_url": "https://example.com/",
    "provider": "lexmount-global",
    "trace_id": "..."
  }
}

web_search(query) 负责发现 URL，web_fetch(url) 负责读取正文，browser 负责点击、登录和交互。供应商变化不应制造新的模型可见同义工具。
