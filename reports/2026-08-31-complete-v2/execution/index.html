详细执行过程与复现

一个脚本会验证配置、运行固定数据集和供应商、保存所有 artifacts、生成分页 HTML 并检查本地链接。脚本能复现评测过程和报告结构；实时网站与云服务会变化，因此不能保证未来逐字节复现本次数值。

新环境完整步骤

git clone https://github.com/lexmount/browser-harness-eval.git
cd browser-harness-eval
cp .env.example ~/.env  # fill keys; never commit this file
python3 -m unittest discover -s tests -v
python3 -m browser_harness_eval validate --env-file ~/.env --providers cowagent-built-in,lexmount-global,firecrawl,tavily,exa,cloudflare-markdown,cloudflare-content
WEBFETCH_REAL_SMOKE=1 WEBFETCH_SMOKE_ENV_FILE=~/.env python3 -m unittest tests.test_real_smoke -v
./scripts/reproduce_report.sh runs/reproduced
open runs/reproduced/report/index.html

两种复现语义

重放已保存结果

python3 -m browser_harness_eval report runs/<run-id>

不发网络请求；从 JSONL/artifacts 重新生成相同指标和 HTML。

重新实测

./scripts/reproduce_report.sh runs/new-run

重新调用真实服务；页面内容、时延、credits 与供应商行为可能变化。

失败定位顺序

  1. 看 providers 页区分 transport 与 strict content。
  2. 下钻 attempt 页，检查 HTTP 状态、error_type、事实组 MISS、反向标记和 provider metadata。
  3. 用 SHA-256 对照完整 artifact，避免网页预览截断造成误判。
  4. 认证失败先运行 token 官方验证；内容失败再对照 ground-truth 原始证据。
  5. 修复后创建新 run 目录，禁止覆盖原结果，以保留审计链。
