文件、图片与视频：Web Fetch 到底返回什么

“支持”拆成三件不同的事：①抽取为可读文字；②返回资源 URL/元数据；③下载原始二进制。正文主榜只测第一项，不能因为 Markdown 中出现一张图的链接就宣称已抓取图片，更不能因为接口能返回 PDF 文件就宣称已理解 PDF 正文。

能力集 webfetch-file-media-v110 种方法核验 2026-09-01

先给结论

网页与文档

TXT 通常能直接作为正文；PDF、DOCX 需要文档解析器。把二进制按 UTF-8 解码或只返回下载链接，都不算正文抽取成功。

图片与视频

主流 Web Fetch 通常不把媒体二进制塞进正文。常见结果是保留图片/视频 URL 或元数据；视觉理解、OCR、视频转写属于另一个工具面。

Agent 的稳定契约

正文放 content；资源放 resources[]；需要二进制时再调用受限的 download_resource，避免 token、带宽和安全风险。

方法能力矩阵

“另有接口”表示当前参评的正文接口本身不返回该能力，但同一产品提供独立 endpoint；不能把两个 endpoint 的能力合并成一次 Web Fetch 成功。

下载结构化能力证据 JSON

推荐输出模型

{
  "content": "抽取后的正文；图片/视频不转成乱码",
  "content_type": "text/html | application/pdf | ...",
  "resources": [{"kind":"image|video|audio|document", "url":"...", "mime_type":"..."}],
  "attachments": [{"kind":"download", "url":"受控下载地址", "sha256":"...", "bytes":123}]
}
默认只返回正文与资源引用。只有调用方明确请求、大小与 MIME 在白名单内、下载 URL 通过 SSRF/重定向检查时，才获取原始二进制；下载不应偷偷计入正文抓取耗时。

官方与源码证据

  • Firecrawl Parse：公开文档 URL 可经 Scrape，Parse 支持 PDF、DOCX、XLSX 等并返回抽取结果
  • Tavily Extract：include_images 可返回图片 URL 列表
  • Exa Contents：正文外可请求 links、imageLinks 和 richImageLinks
  • Cloudflare Browser Rendering：markdown、content、links、screenshot、snapshot、pdf 是不同接口
  • OpenClaw web_fetch：默认 HTTP + Readability，不执行 JavaScript，可选 Firecrawl 回退
  • DeepSeek Harness web-fetch-http：文本 MIME 白名单；二进制内容明确拒绝
  • Crawl4AI CrawlResult：media 分为 images/videos/audios，links 分为 internal/external，均为元数据
