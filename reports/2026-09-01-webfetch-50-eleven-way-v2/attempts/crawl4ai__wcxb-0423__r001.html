###  14.11.1 Error correcting conditions for the three-qubit code[](https://qubit.guide/14.11-remarks-and-exercises-error-correction#error-correcting-conditions-for-the-three-qubit-code)
When building the Shor [[9,1,3]][[9,1,3]][[9,1,3]] code, we used the three-qubit code twice: once to correct for XXX-errors, and once for ZZZ-errors. However, there is no reason why we couldn’t instead have used one copy to correct for YYY-errors instead of XXX-errors, and we can see this using the dot-error diagrams.
Consider the stabiliser code given by S=⟨ZZ1,1ZZ⟩\mathcal{S}=\langle ZZ\mathbf{1},\mathbf{1}ZZ\rangleS=⟨ZZ1,1ZZ⟩. In Figure [14.13](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fig:all-weight-1-errors-three-qubit-code) we draw all the computational errors of weight at most 111, and we see that this does _not_ describe a correctable scenario. That is, as we already know, the three-qubit code cannot alone correct for all single-qubit errors.
![All computational errors of weight at most 1 for the three-qubit code given by \\langle ZZ\\mathbf{1},\\mathbf{1}ZZ\\rangle. Note that this describes a non-correctable scenario. In fact, both of the two rules are broken.](https://qubit.guide/qubit_guide_files/figure-html/all-weight-1-errors-three-qubit-code-1.png)
Figure 14.13: All computational errors of weight at most 111 for the three-qubit code given by ⟨ZZ1,1ZZ⟩\langle ZZ\mathbf{1},\mathbf{1}ZZ\rangle⟨ZZ1,1ZZ⟩. Note that this describes a _non_ -correctable scenario. In fact, _both_ of the two rules are broken.

As Figure [14.14](https://qubit.guide/14.11-remarks-and-exercises-error-correction#fig:xyz-type-weight-1-errors-three-qubit-code) shows, the three-qubit code given by ⟨ZZ1,1ZZ⟩\langle ZZ\mathbf{1},\mathbf{1}ZZ\rangle⟨ZZ1,1ZZ⟩ can correct for all XXX-errors (as we already knew), but also for all YYY-errors!
