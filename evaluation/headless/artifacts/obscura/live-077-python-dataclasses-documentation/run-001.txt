# `dataclasses` — Data Classes[¶](../_static/pygments.css?v=b86133f3 "viewport")

**Source code:** [Lib/dataclasses.py](../_static/pygments.css?v=b86133f3 "viewport")

---

This module provides a decorator and functions for automaticallyadding generated
[special methods](../_static/pygments.css?v=b86133f3 "viewport") such as [`__init__()`](../_static/pygments.css?v=b86133f3 "viewport") and[`__repr__()`](../_static/pygments.css?v=b86133f3 "viewport") to user-defined classes.  It was originally describedin
[**PEP 557**](../_static/pygments.css?v=b86133f3 "viewport").

The member variables to use in these generated methods are definedusing [**PEP 526**](../_static/pygments.css?v=b86133f3 "viewport") type annotations.  For example, this code:

Copy

```from dataclasses import dataclass@dataclassclass InventoryItem:    """Class for 
keeping track of an item in inventory."""    name: str    unit_price: float    quantity_on_hand: 
int = 0    def total_cost(self) -> float:        return self.unit_price \* self.quantity_on_hand```

will add, among other things, a `__init__()` that looks like:

Copy

```def __init__(self, name: str, unit_price: float, quantity_on_hand: int = 0):  
self.name = name    self.unit_price = unit_price    self.quantity_on_hand = quantity_on_hand```

Note that this method is automatically added to the class: it is notdirectly specified
in the `InventoryItem` definition shown above.


Added in version 3.7.

## Module contents[¶](../_static/classic.css?v=234b1a7c "highlight-")
@dataclasses.dataclass(*\**, *init=True*, *repr=True*, *eq=True*, *order=False*,
*unsafe_hash=False*, *frozen=False*, *match_args=True*, *kw_only=False*, *slots=False*,
*weakref_slot=False*)[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")
This function is a [decorator](../_static/pydoctheme.css?v=4365c8fe "highlight-") that is used to add
generated[special methods](../_static/pydoctheme.css?v=4365c8fe "highlight-") to classes, as described below.

The `@dataclass` decorator examines the class to find`field`s.  A `field` is defined as a class variable
that has a[type annotation](../_static/pydoctheme.css?v=4365c8fe "highlight-").  With twoexceptions described below, nothing in
`@dataclass`examines the type specified in the variable annotation.

The order of the fields in all of the generated methods is theorder in which they
appear in the class definition.

The `@dataclass` decorator will add various “dunder” methods tothe class, described below.
If any of the added methods alreadyexist in the class, the behavior depends on the
parameter, as documentedbelow. The decorator returns the same class that it is called
on; no newclass is created.

If `@dataclass` is used just as a simple decorator with no parameters,it acts as if it has
the default values documented in thissignature.  That is, these three uses of `@dataclass`
areequivalent:

Copy

```@dataclassclass C:    ...@dataclass()class C:    ...@dataclass(init=True, repr=True, 
eq=True, order=False, unsafe_hash=False, frozen=False,           match_args=True, 
kw_only=False, slots=False, weakref_slot=False)class C:    ...```

The parameters to `@dataclass` are:

- *init*: If true (the default), a [`__init__()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") method will begenerated.

	If the class already defines `__init__()`, this parameter isignored.
- *repr*: If true (the default), a [`__repr__()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") method will begenerated.  The generated repr string will have the class name andthe name and repr of each field, in the order they are defined inthe class.  Fields that are marked as being excluded from the reprare not included.  For example:`InventoryItem(name='widget', unit_price=3.0, quantity_on_hand=10)`.

	If the class already defines `__repr__()`, this parameter isignored.
- *eq*: If true (the default), an [`__eq__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") method will begenerated.

	This method compares the class by comparing each field in order. Bothinstances in the comparison must be of the identical type.

	If the class already defines `__eq__()`, this parameter is ignored.

Changed in version 3.13: The generated `__eq__` method now compares each field individually(for example, `self.a == other.a and self.b == other.b`), rather thancomparing tuples of fields as in previous versions.

	This change makes the comparison faster but it may alter results in caseswhere attributes compare equal by identity but not by value (such as`float('nan')`).

	In Python 3.12 and earlier, the comparison was performed by creatingtuples of the fields and comparing them (for example,`(self.a, self.b) == (other.a, other.b)`).
- *order*: If true (the default is `False`), [`__lt__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"),[`__le__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`__gt__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), and [`__ge__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") methods will begenerated.  These compare the class as if it were a tuple of itsfields, in order.  Both instances in the comparison must be of theidentical type.  If *order* is true and *eq* is false, a[`ValueError`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") is raised.

	If the class already defines any of `__lt__()`,`__le__()`, `__gt__()`, or `__ge__()`, then[`TypeError`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") is raised.
- *unsafe_hash*: If true, force `dataclasses` to create a[`__hash__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") method, even though it may not be safe to do so.Otherwise, generate a `__hash__()` method according to how*eq* and *frozen* are set.The default value is `False`.

	`__hash__()` is used by built-in [`hash()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), and when objects areadded to hashed collections such as dictionaries and sets.  Having a`__hash__()` implies that instances of the class are immutable.Mutability is a complicated property that depends on the programmer’sintent, the existence and behavior of `__eq__()`, and the values ofthe *eq* and *frozen* flags in the `@dataclass` decorator.

	By default, `@dataclass` will not implicitly add a [`__hash__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")method unless it is safe to do so.  Neither will it add or change anexisting explicitly defined `__hash__()` method.  Setting the classattribute `__hash__ = None` has a specific meaning to Python, asdescribed in the `__hash__()` documentation.

	If `__hash__()` is not explicitly defined, or if it is set to `None`,then `@dataclass` *may* add an implicit `__hash__()` method.Although not recommended, you can force `@dataclass` to create a`__hash__()` method with `unsafe_hash=True`. This might be the caseif your class is logically immutable but can still be mutated.This is a specialized use case and should be considered carefully.

	Here are the rules governing implicit creation of a `__hash__()`method.  Note that you cannot both have an explicit `__hash__()`method in your dataclass and set `unsafe_hash=True`; this will resultin a [`TypeError`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").

	If *eq* and *frozen* are both true, by default `@dataclass` willgenerate a `__hash__()` method for you.  If *eq* is true and*frozen* is false, `__hash__()` will be set to `None`, marking itunhashable (which it is, since it is mutable).  If *eq* is false,`__hash__()` will be left untouched meaning the `__hash__()`method of the superclass will be used (if the superclass is[`object`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), this means it will fall back to id-based hashing).
- *frozen*: If true (the default is `False`), assigning to fields willgenerate an exception.  This emulates read-only frozen instances.See the [discussion](../_static/pydoctheme.css?v=4365c8fe "stylesheet") below.

	If [`__setattr__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") or [`__delattr__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") is defined in the classand *frozen* is true, then [`TypeError`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") is raised.
- *match_args*: If true (the default is `True`), the[`__match_args__`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") tuple will be created from the list ofnon keyword-only parameters to the generated [`__init__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") method (even if`__init__()` is not generated, see above).  If false, or if`__match_args__` is already defined in the class, then`__match_args__` will not be generated.

> 
> 
> Added in version 3.10.
> 
> 

- *kw_only*: If true (the default value is `False`), then allfields will be marked as keyword-only.  If a field is marked askeyword-only, then the only effect is that the [`__init__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")parameter generated from a keyword-only field must be specifiedwith a keyword when `__init__()` is called. See the [parameter](../_static/pydoctheme.css?v=4365c8fe "stylesheet")glossary entry for details.  Also see the[`KW_ONLY`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") section.

	Keyword-only fields are not included in `__match_args__`.

> 
> 
> Added in version 3.10.
> 
> 

- *slots*: If true (the default is `False`), [`__slots__`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") attributewill be generated and new class will be returned instead of the original one.If `__slots__` is already defined in the class, then [`TypeError`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation")is raised.

> 
> 
> Warning
> 
> Passing parameters to a base class [`__init_subclass__()`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation")
> when using `slots=True` will result in a [`TypeError`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation").
> Either use `__init_subclass__` with no parameters
> or use default values as a workaround.
> See [gh-91126]( "Search within Python 3.14.7 documentation") for full details.
> 
> 
> 
> Added in version 3.10.
> 
> 
> 
> Changed in version 3.11: If a field name is already included in the `__slots__`
> of a base class, it will not be included in the generated `__slots__`
> to prevent [overriding them](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").
> Therefore, do not use `__slots__` to retrieve the field names of a
> dataclass. Use [`fields()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") instead.
> To be able to determine inherited slots,
> base class `__slots__` may be any iterable, but *not* an iterator.
> 
> 

- *weakref_slot*: If true (the default is `False`), add a slotnamed “__weakref__”, which is required to make an instance[`weakref-able`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").It is an error to specify `weakref_slot=True`without also specifying `slots=True`.

> 
> 
> Added in version 3.11.
> 
> 

`field`s may optionally specify a default value, using normalPython syntax:

Copy

```@dataclassclass C:    a: int       # 'a' has no default value    b: int = 0   
# assign a default value for 'b'```

In this example, both `a` and `b` will be included in the added[`__init__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method, which will be defined as:

Copy

```def __init__(self, a: int, b: int = 0):```

[`TypeError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") will be raised if a field without a default valuefollows a field with a default value.  This is true whether thisoccurs in a single class, or as a result of class inheritance.
dataclasses.field(*\**, *default=MISSING*, *default_factory=MISSING*, *init=True*, 
*repr=True*, *hash=None*, *compare=True*, *metadata=None*, *kw_only=MISSING*, *doc=None*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
For common and simple use cases, no other functionality isrequired.  There are, however, 
some dataclass features thatrequire additional per-field information.  To satisfy 
this need foradditional information, you can replace the default field valuewith 
a call to the provided `field()` function.  For example:

Copy

```@dataclassclass C:    mylist: list[int] = field(default_factory=list)c = C()c.mylist
+= [1, 2, 3]```

As shown above, the [`MISSING`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") value is a sentinel object used todetect if some parameters are provided by the user. This sentinel isused because `None`
is a valid value for some parameters witha distinct meaning.  No code should directly
use the `MISSING` value.

The parameters to `field()` are:

- *default*: If provided, this will be the default value for thisfield.  This is needed because the `field()` call itselfreplaces the normal position of the default value.
- *default_factory*: If provided, it must be a zero-argumentcallable that will be called when a default value is needed forthis field.  Among other purposes, this can be used to specifyfields with mutable default values, as discussed below.  It is anerror to specify both *default* and *default_factory*.
- *init*: If true (the default), this field is included as aparameter to the generated [`__init__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method.
- *repr*: If true (the default), this field is included in thestring returned by the generated [`__repr__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method.
- *hash*: This can be a bool or `None`.  If true, this field isincluded in the generated [`__hash__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method.  If false,this field is excluded from the generated `__hash__()`.If `None` (the default), use the value of *compare*: this wouldnormally be the expected behavior, since a field should be includedin the hash if it’s used for comparisons.  Setting this value to anythingother than `None` is discouraged.

	One possible reason to set `hash=False` but `compare=True`would be if a field is expensive to compute a hash value for,that field is needed for equality testing, and there are otherfields that contribute to the type’s hash value.  Even if a fieldis excluded from the hash, it will still be used for comparisons.
- *compare*: If true (the default), this field is included in thegenerated equality and comparison methods ([`__eq__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"),[`__gt__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), et al.).
- *metadata*: This can be a mapping or `None`. `None` is treated asan empty dict.  This value is wrapped in[`MappingProxyType()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") to make it read-only, and exposedon the [`Field`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object. It is not used at all by DataClasses, and is provided as a third-party extension mechanism.Multiple third-parties can each have their own key, to use as anamespace in the metadata.
- *kw_only*: If true, this field will be marked as keyword-only.This is used when the generated [`__init__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method’sparameters are computed.

	Keyword-only fields are also not included in `__match_args__`.

>
>
> Added in version 3.10.
>
>

- *doc*: optional docstring for this field.

>
>
> Added in version 3.14.
>
>

If the default value of a field is specified by a call to`field()`, then the class attribute
for this field will bereplaced by the specified *default* value.  If *default* is
notprovided, then the class attribute will be deleted.  The intent isthat after the
[`@dataclass`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") decorator runs, the classattributes will all contain the default values for the fields, justas if the default value itself were specified.  For example,after:

Copy

```@dataclassclass C:    x: int    y: int = field(repr=False)    z: int = field(repr=False, 
default=10)    t: int = 20```

The class attribute `C.z` will be `10`, the class attribute`C.t` will be `20`, and the class 
attributes `C.x` and`C.y` will not be set.
*class *dataclasses.Field[¶](../_static/opensearch.xml "Search within Python 3.14.7 documentation")
`Field` objects describe each defined field. These objectsare created internally, and 
are returned by the [`fields()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation")module-level method (see below).  Users should never instantiate a`Field` 
object directly.  Its documented attributes are:

- `name`: The name of the field.
- `type`: The type of the field.
- `default`, `default_factory`, `init`, `repr`, `hash`,`compare`, `metadata`, and `kw_only` have the identicalmeaning and values as they do in the [`field()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") function.

Other attributes may exist, but they are private and must not beinspected or relied 
on.
*class *dataclasses.InitVar[¶](../_static/opensearch.xml "Search within Python 3.14.7 documentation")
`InitVar[T]` type annotations describe variables that are [init-only](../_static/opensearch.xml "Search within Python 3.14.7 documentation"). Fields annotated with
`InitVar`are considered pseudo-fields, and thus are neither returned by the[`fields()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") function nor used in any way except adding them asparameters to [`__init__()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") and an optional[`__post_init__()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation").
dataclasses.fields(*class_or_instance*)[¶](../_static/opensearch.xml "Search within Python 3.14.7 documentation")
Returns a tuple of [`Field`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") objects that define the fields for thisdataclass.  Accepts either a dataclass, or an instance of a dataclass.Raises [`TypeError`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") if not passed a dataclass or instance of one.Does not return pseudo-fields which are `ClassVar` 
or `InitVar`.
dataclasses.asdict(*obj*, *\**, *dict_factory=dict*)[¶](warnings.html "warnings — Warning control")
Converts the dataclass *obj* to a dict (by using thefactory function *dict_factory*). 
 Each dataclass is convertedto a dict of its fields, as `name: value` pairs.  dataclasses, dicts,lists, 
and tuples are recursed into.  Other objects are copied with[`copy.deepcopy()`](../_static/pydoctheme_dark.css "previous chapter").

Example of using `asdict()` on nested dataclasses:

Copy

```@dataclassclass Point:     x: int     y: int@dataclassclass C:     mylist: list[Point]p
= Point(10, 20)assert asdict(p) == {'x': 10, 'y': 20}c = C([Point(0, 0), Point(10,
4)])assert asdict(c) == {'mylist': [{'x': 0, 'y': 0}, {'x': 10, 'y': 4}]}```

To create a shallow copy, the following workaround may be used:

Copy

```{field.name: getattr(obj, field.name) for field in fields(obj)}```

`asdict()` raises [`TypeError`](../_static/py.svg "previous chapter") if *obj* is not a dataclassinstance.
dataclasses.astuple(*obj*, *\**, *tuple_factory=tuple*)[¶](https://www.python.org/ "previous chapter")
Converts the dataclass *obj* to a tuple (by using thefactory function *tuple_factory*). 
 Each dataclass is convertedto a tuple of its field values.  dataclasses, dicts, 
lists, andtuples are recursed into. Other objects are copied with[`copy.deepcopy()`](../contents.html "previous chapter").

Continuing from the previous example:

Copy

```assert astuple(p) == (10, 20)assert astuple(c) == ([(0, 0), (10, 4)],)```

To create a shallow copy, the following workaround may be used:

Copy

```tuple(getattr(obj, field.name) for field in dataclasses.fields(obj))```

`astuple()` raises [`TypeError`](../contents.html "previous chapter") if *obj* is not a dataclassinstance.
dataclasses.make_dataclass(*cls_name*, *fields*, *\**, *bases=()*, *namespace=None*, 
*init=True*, *repr=True*, *eq=True*, *order=False*, *unsafe_hash=False*, *frozen=False*, 
*match_args=True*, *kw_only=False*, *slots=False*, *weakref_slot=False*, *module=None*, 
*decorator=dataclass*)[¶](https://github.com/python/cpython/blob/main/Doc/library/dataclasses.rst?plain=1 "General Index")
Creates a new dataclass with name *cls_name*, fields as definedin *fields*, base 
classes as given in *bases*, and initializedwith a namespace as given in *namespace*. 
 *fields* is aniterable whose elements are each either `name`, `(name, type)`,or `(name, type, Field)`.  If just `name` 
is supplied,[`typing.Any`](https://www.python.org/ "warnings — Warning control") is used for `type`. 
 The values of *init*,*repr*, *eq*, *order*, *unsafe_hash*, *frozen*,*match_args*, 
*kw_only*, *slots*, and *weakref_slot* havethe same meaning as they do in [`@dataclass`](../index.html "Link to this heading").

If *module* is defined, the `__module__` attributeof the dataclass is set to that value.By 
default, it is set to the module name of the caller.

The *decorator* parameter is a callable that will be used to create the dataclass.It 
should take the class object as a first argument and the same keyword argumentsas 
[`@dataclass`](../index.html "Link to this heading"). By default, the `@dataclass`function is used.

This function is not strictly required, because any Pythonmechanism for creating 
a new class with [`__annotations__`](../index.html "Link to this heading") canthen apply the [`@dataclass`](../index.html "Link to this heading") function to convert that class toa dataclass.  This function is provided as a convenience.  Forexample:

Copy

```C = make_dataclass('C',                   [('x', int),                     'y',
('z', int, field(default=5))],                   namespace={'add_one':
lambda self: self.x + 1})```

Is equivalent to:

Copy

```@dataclassclass C:    x: int    y: 'typing.Any'    z: int = 5    def add_one(self): 
       return self.x + 1```


Added in version 3.14: Added the *decorator* parameter.
dataclasses.replace(*obj*, */*, *\*\*changes*)[¶](../_static/classic.css?v=234b1a7c "highlight-")
Creates a new object of the same type as *obj*, replacingfields with values from 
*changes*.  If *obj* is not a DataClass, raises [`TypeError`](../_static/classic.css?v=234b1a7c "highlight-").  If keys in
*changes* are notfield names of the given dataclass, raises `TypeError`.

The newly returned object is created by calling the [`__init__()`](../_static/classic.css?v=234b1a7c "highlight-")method of the dataclass.  This ensures that[`__post_init__()`](../_static/classic.css?v=234b1a7c "highlight-"), if present, is also called.

Init-only variables without default values, if any exist, must bespecified on the 
call to `replace()` so that they can be passed to`__init__()` and [`__post_init__()`](../_static/classic.css?v=234b1a7c "highlight-").

It is an error for *changes* to contain any fields that aredefined as having `init=False`. 
 A [`ValueError`](../_static/classic.css?v=234b1a7c "highlight-") will be raisedin this case.

Be forewarned about how `init=False` fields work during a call to`replace()`.  They are not copied from 
the source object, butrather are initialized in [`__post_init__()`](../_static/classic.css?v=234b1a7c "highlight-"), if they’reinitialized at all.  It is expected that `init=False` 
fields willbe rarely and judiciously used.  If they are used, it might be wiseto 
have alternate class constructors, or perhaps a custom`replace()` (or similarly named) method 
which handles instancecopying.

Dataclass instances are also supported by generic function [`copy.replace()`](../_static/classic.css?v=234b1a7c "highlight-").
dataclasses.is_dataclass(*obj*)[¶](../_static/classic.css?v=234b1a7c "highlight-")
Return `True` if its parameter is a dataclass (including subclasses of adataclass, but 
not including [generic aliases](../_static/classic.css?v=234b1a7c "highlight-"))or an instance of one, otherwise return
`False`.

If you need to know if a class is an instance of a dataclass (andnot a dataclass 
itself), then add a further check for `not
isinstance(obj, type)`:

Copy

```def is_dataclass_instance(obj):    return is_dataclass(obj) and not isinstance(obj,
type)```
dataclasses.MISSING[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")
A sentinel value signifying a missing default or default_factory.
dataclasses.KW_ONLY[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")
A sentinel value used as a type annotation.  Any fields after apseudo-field with
the type of `KW_ONLY` are marked askeyword-only fields.  Note that a pseudo-field of type`KW_ONLY`
is otherwise completely ignored.  This includes thename of such a field.  By convention,
a name of `_` is used for a`KW_ONLY` field.  Keyword-only fields signify[`__init__()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") parameters that must be specified as keywords whenthe class is instantiated.

In this example, the fields `y` and `z` will be marked as keyword-only fields:

Copy

```@dataclassclass Point:    x: float    _: KW_ONLY    y: float    z: floatp = Point(0, 
y=1.5, z=2.0)```

In a single dataclass, it is an error to specify more than onefield whose type is 
`KW_ONLY`.


Added in version 3.10.
*exception *dataclasses.FrozenInstanceError[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")
Raised when an implicitly defined [`__setattr__()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") or[`__delattr__()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") is called on a dataclass which was defined
with`frozen=True`. It is a subclass of [`AttributeError`](../_static/pydoctheme.css?v=4365c8fe "highlight-").

## Post-init processing[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")
dataclasses.__post_init__()[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")
When defined on the class, it will be called by the generated[`__init__()`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), normally as
`self.__post_init__()`.However, if any `InitVar` fields are defined, they will also bepassed 
to `__post_init__()` in the order they were defined in theclass.  If no `__init__()` method is generated, 
then`__post_init__()` will not automatically be called.

Among other uses, this allows for initializing field values thatdepend on one or 
more other fields.  For example:

Copy

```@dataclassclass C:    a: float    b: float    c: float = field(init=False)    
def __post_init__(self):        self.c = self.a + self.b```

The [`__init__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") method generated by [`@dataclass`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") does not call baseclass `__init__()`
methods. If the base class has an `__init__()` methodthat has to be called, it is common to
call this method in a[`__post_init__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") method:

Copy

```class Rectangle:    def __init__(self, height, width):        self.height = height 
       self.width = width@dataclassclass Square(Rectangle):    side: float    def 
__post_init__(self):        super().__init__(self.side, self.side)```

Note, however, that in general the dataclass-generated `__init__()` methodsdon’t need to 
be called, since the derived dataclass will take care ofinitializing all fields of 
any base class that is a dataclass itself.

See the section below on init-only variables for ways to passparameters to `__post_init__()`.  Also 
see the warning about how[`replace()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") handles `init=False` 
fields.

## Class variables[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

One of the few places where [`@dataclass`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") actually inspects the typeof a field is to determine if a field is a class variable as definedin
[**PEP 526**](../_static/pydoctheme.css?v=4365c8fe "stylesheet").  It does this by checking if the type of the field is[`typing.ClassVar`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").  If a field is a
`ClassVar`, it is excludedfrom consideration as a field and is ignored by the dataclassmechanisms. 
 Such `ClassVar` pseudo-fields are not returned by themodule-level [`fields()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") function.

## Init-only variables[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

Another place where [`@dataclass`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") inspects a type annotation is todetermine if a field is an init-only variable.  It does this by seeingif the type of a field is of type [`InitVar`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").  If a fieldis an
`InitVar`, it is considered a pseudo-field called an init-onlyfield.  As it is not 
a true field, it is not returned by themodule-level [`fields()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") function.  Init-only fields are added asparameters to the generated [`__init__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") method, and are passed tothe optional [`__post_init__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") method.  They are not otherwise usedby dataclasses.

For example, suppose a field will be initialized from a database, if avalue is not 
provided when creating the class:

Copy

```@dataclassclass C:    i: int    j: int | None = None    database: InitVar[DatabaseType
| None] = None    def __post_init__(self, database):        if self.j is None and
database is not None:            self.j = database.lookup('j')c = C(10, database=my_database)```

In this case, [`fields()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") will return [`Field`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") objects for `i`
and`j`, but not for `database`.

## Frozen instances[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

It is not possible to create truly immutable Python objects.  However,by passing
`frozen=True` to the [`@dataclass`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") decorator you canemulate immutability.  In that case, dataclasses will add[`__setattr__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") and [`__delattr__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") methods to the class.  Thesemethods will raise a [`FrozenInstanceError`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") when invoked.

There is a tiny performance penalty when using `frozen=True`:[`__init__()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") cannot use simple assignment to initialize fields, andmust use
`object.__setattr__()`.

## Inheritance[¶](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation")

When the dataclass is being created by the [`@dataclass`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation") decorator,it looks through all of the class’s base classes in reverse MRO (thatis, starting at [`object`]( "Search within Python 3.14.7 documentation")) and, for each dataclass that it finds,adds the fields from that base class to an ordered mapping of fields.After all of the base class fields are added, it adds its own fieldsto the ordered mapping.  All of the generated methods will use thiscombined, calculated ordered mapping of fields.  Because the fieldsare in insertion order, derived classes override base classes.  Anexample:

Copy

```@dataclassclass Base:    x: Any = 15.0    y: int = 0@dataclassclass C(Base):  
  z: int = 10    x: int = 15```

The final list of fields is, in order, `x`, `y`, `z`.  The finaltype of `x` is [`int`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), as specified in class
`C`.

The generated [`__init__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method for `C` 
will look like:

Copy

```def __init__(self, x: int = 15, y: int = 0, z: int = 10):```

## Re-ordering of keyword-only parameters in `__init__()`[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

After the parameters needed for [`__init__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") are computed, anykeyword-only parameters are moved to come after all regular(non-keyword-only) parameters.  This is a requirement of howkeyword-only parameters are implemented in Python: they must comeafter non-keyword-only parameters.

In this example, `Base.y`, `Base.w`, and `D.t` are keyword-onlyfields, and `Base.x` and `D.z` are regular
fields:

Copy

```@dataclassclass Base:    x: Any = 15.0    _: KW_ONLY    y: int = 0    w: int = 
1@dataclassclass D(Base):    z: int = 10    t: int = field(kw_only=True, default=0)```

The generated `__init__()` method for `D` will look like:

Copy

```def __init__(self, x: Any = 15.0, z: int = 10, \*, y: int = 0, w: int = 1, t:
int = 0):```

Note that the parameters have been re-ordered from how they appear inthe list of
fields: parameters derived from regular fields arefollowed by parameters derived
from keyword-only fields.

The relative ordering of keyword-only parameters is maintained in there-ordered `__init__()`
parameter list.

## Default factory functions[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

If a [`field()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") specifies a
*default_factory*, it is called withzero arguments when a default value for the
field is needed.  Forexample, to create a new instance of a list, use:

Copy

```mylist: list = field(default_factory=list)```

If a field is excluded from [`__init__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") (using
`init=False`)and the field also specifies *default_factory*, then the defaultfactory 
function will always be called from the generated`__init__()` function.  This happens because 
there is no otherway to give the field an initial value.

## Mutable default values[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

Python stores default member variable values in class attributes.Consider this example, 
not using dataclasses:

Copy

```class C:    x = []    def add(self, element):        self.x.append(element)o1
= C()o2 = C()o1.add(1)o2.add(2)assert o1.x == [1, 2]assert o1.x is o2.x```

Note that the two instances of class `C` share the same classvariable `x`, as expected.

Using dataclasses, *if* this code was valid:

Copy

```@dataclassclass D:    x: list = []      # This code raises ValueError    def add(self, 
element):        self.x.append(element)```

it would generate code similar to:

Copy

```class D:    x = []    def __init__(self, x=x):        self.x = x    def add(self,
element):        self.x.append(element)assert D().x is D().x```

This has the same issue as the original example using class `C`.That is, two instances
of class `D` that do not specify a valuefor `x` when creating a class instance will
share the same copyof `x`.  Because dataclasses just use normal Python classcreation
they also share this behavior.  There is no general wayfor Data Classes to detect
this condition.  Instead, the[`@dataclass`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") decorator will raise a [`ValueError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") if itdetects an unhashable default parameter.  The assumption is that ifa value is unhashable, it is mutable.  This is a partial solution,but it does protect against many common errors.

Using default factory functions is a way to create new instances ofmutable types
as default values for fields:

Copy

```@dataclassclass D:    x: list = field(default_factory=list)assert D().x is not 
D().x```


Changed in version 3.11: Instead of looking for and disallowing objects of type [`list`](../_static/opensearch.xml "Search within Python 3.14.7 documentation"),[`dict`](../_static/opensearch.xml "Search within Python 3.14.7 documentation"), or [`set`](../_static/opensearch.xml "Search within Python 3.14.7 documentation"), unhashable objects are now not allowed asdefault values.  Unhashability is used to approximatemutability.

## Descriptor-typed fields[¶](../_static/opensearch.xml "Search within Python 3.14.7 documentation")

Fields that are assigned [descriptor objects](../_static/opensearch.xml "Search within Python 3.14.7 documentation") as theirdefault value have the following special behaviors:

- The value for the field passed to the dataclass’s [`__init__()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") method ispassed to the descriptor’s [`__set__()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") method rather than overwriting thedescriptor object.
- Similarly, when getting or setting the field, the descriptor’s[`__get__()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") or `__set__()` method is called rather than returning oroverwriting the descriptor object.
- To determine whether a field contains a default value, [`@dataclass`](../_static/opensearch.xml "Search within Python 3.14.7 documentation")will call the descriptor’s `__get__()` method using its class accessform: `descriptor.__get__(obj=None, type=cls)`.  If thedescriptor returns a value in this case, it will be used as thefield’s default. On the other hand, if the descriptor raises[`AttributeError`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") in this situation, no default value will beprovided for the field.

Copy

```class IntConversionDescriptor:    def __init__(self, \*, default):        self._default
= default    def __set_name__(self, owner, name):        self._name = "_" + name
def __get__(self, obj, type):        if obj is None:            return self._default
return getattr(obj, self._name, self._default)    def __set__(self, obj, value):
setattr(obj, self._name, int(value))@dataclassclass InventoryItem:    quantity_on_hand:
IntConversionDescriptor = IntConversionDescriptor(default=100)i =
InventoryItem()print(i.quantity_on_hand)   # 100i.quantity_on_hand = 2.5    # calls
__set__ with 2.5print(i.quantity_on_hand)   # 2```

Note that if a field is annotated with a descriptor type, but is not assigneda descriptor
object as its default value, the field will act like a normalfield.
