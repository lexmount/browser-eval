# `sqlite3` — DB-API 2.0 interface for SQLite databases[¶](../_static/classic.css?v=234b1a7c "highlight-")

**Source code:** [Lib/sqlite3/](../_static/classic.css?v=234b1a7c "highlight-")

SQLite is a C library that provides a lightweight disk-based database thatdoesn’t
require a separate server process and allows accessing the databaseusing a nonstandard
variant of the SQL query language. Some applications can useSQLite for internal data
storage.  It’s also possible to prototype anapplication using SQLite and then port
the code to a larger database such asPostgreSQL or Oracle.

The `sqlite3` module was written by Gerhard Häring.  It provides an SQL interfacecompliant
with the DB-API 2.0 specification described by [**PEP 249**](../_static/classic.css?v=234b1a7c "highlight-"), andrequires the third-party [SQLite](../_static/classic.css?v=234b1a7c "highlight-") library.

This is an [optional module](../_static/classic.css?v=234b1a7c "highlight-").If it is missing from your copy of CPython,look for documentation from your distributor (that is,whoever provided Python to you).If you are the distributor, see
[Requirements for optional modules](../_static/classic.css?v=234b1a7c "highlight-").

This document includes four main sections:

- [Tutorial](../_static/classic.css?v=234b1a7c "highlight-") teaches how to use the `sqlite3` module.
- [Reference](../_static/classic.css?v=234b1a7c "highlight-") describes the classes and functions this moduledefines.
- [How-to guides](../_static/classic.css?v=234b1a7c "highlight-") details how to handle specific tasks.
- [Explanation](../_static/classic.css?v=234b1a7c "highlight-") provides in-depth background ontransaction control.


See also
[https://www.sqlite.org](../_static/classic.css?v=234b1a7c "highlight-")
The SQLite web page; the documentation describes the syntax and theavailable data
types for the supported SQL dialect.
[https://www.w3schools.com/sql/](../_static/classic.css?v=234b1a7c "highlight-")
Tutorial, reference and examples for learning SQL syntax.
[**PEP 249**](../_static/classic.css?v=234b1a7c "highlight-") - Database API Specification 2.0
PEP written by Marc-André Lemburg.

## Tutorial[¶](../_static/classic.css?v=234b1a7c "highlight-")

In this tutorial, you will create a database of Monty Python moviesusing basic `sqlite3`
functionality.It assumes a fundamental understanding of database concepts,including
[cursors](../_static/classic.css?v=234b1a7c "highlight-") and [transactions](../_static/classic.css?v=234b1a7c "highlight-").

First, we need to create a new database and opena database connection to allow `sqlite3`
to work with it.Call [`sqlite3.connect()`](../_static/classic.css?v=234b1a7c "highlight-") to create a connection tothe database `tutorial.db`
in the current working directory,implicitly creating it if it does not exist:

Copy

```import sqlite3con = sqlite3.connect("tutorial.db")```

The returned [`Connection`](../_static/pydoctheme.css?v=4365c8fe "highlight-") object `con`represents 
the connection to the on-disk database.

In order to execute SQL statements and fetch results from SQL queries,we will need 
to use a database cursor.Call [`con.cursor()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") to create the [`Cursor`](../_static/pydoctheme.css?v=4365c8fe "highlight-"):

Copy

```cur = con.cursor()```

Now that we’ve got a database connection and a cursor,we can create a database
table `movie` with columns for title,release year, and review score.For simplicity, we
can just use column names in the table declaration –thanks to the [flexible typing](../_static/pydoctheme.css?v=4365c8fe "highlight-") feature of SQLite,specifying the data types is optional.Execute the `CREATE TABLE`
statementby calling [`cur.execute(...)`](../_static/pydoctheme.css?v=4365c8fe "highlight-"):

Copy

```cur.execute("CREATE TABLE movie(title, year, score)")```

We can verify that the new table has been created by queryingthe `sqlite_master` table built-in 
to SQLite,which should now contain an entry for the `movie` table definition(see [The Schema Table](../_static/pydoctheme.css?v=4365c8fe "highlight-") for details).Execute that query by calling [`cur.execute(...)`](../_static/pydoctheme.css?v=4365c8fe "highlight-"),assign the result to
`res`,and call [`res.fetchone()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") to fetch the resulting row:

Copy

```>>> res = cur.execute("SELECT name FROM sqlite_master")>>>
res.fetchone()('movie',)```

We can see that the table has been created,as the query returns a [`tuple`](../_static/pydoctheme.css?v=4365c8fe "highlight-") containing the table’s name.If we query `sqlite_master`
for a non-existent table `spam`,`res.fetchone()` will return `None`:

Copy

```>>> res = cur.execute("SELECT name FROM sqlite_master WHERE name='spam'")>>> 
res.fetchone() is NoneTrue```

Now, add two rows of data supplied as SQL literalsby executing an `INSERT` statement,once 
again by calling [`cur.execute(...)`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"):

Copy

```cur.execute("""    INSERT INTO movie VALUES        ('Monty Python and the Holy
Grail', 1975, 8.2),        ('And Now for Something Completely Different', 1971, 7.5)""")```

The `INSERT` statement implicitly opens a transaction,which needs to be committed before
changes are saved in the database(see [Transaction control](../_static/pydoctheme.css?v=4365c8fe "stylesheet") for details).Call [`con.commit()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") on the connection objectto commit the transaction:

Copy

```con.commit()```

We can verify that the data was inserted correctlyby executing a `SELECT` query.Use the 
now-familiar [`cur.execute(...)`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") toassign the result to `res`,and 
call [`res.fetchall()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") to return all resulting rows:

Copy

```>>> res = cur.execute("SELECT score FROM movie")>>> res.fetchall()[(8.2,),
(7.5,)]```

The result is a [`list`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") of two `tuple`s,
one per row,each containing that row’s `score` value.

Now, insert three more rows by calling[`cur.executemany(...)`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"):

Copy

```data = [    ("Monty Python Live at the Hollywood Bowl", 1982, 7.9),    ("Monty 
Python's The Meaning of Life", 1983, 7.5),    ("Monty Python's Life of Brian", 1979, 
8.0),]cur.executemany("INSERT INTO movie VALUES(?, ?, ?)", data)con.commit()  # Remember 
to commit the transaction after executing INSERT.```

Notice that `?` placeholders are used to bind `data` to the query.Always use placeholders 
instead of [string formatting](../_static/pydoctheme.css?v=4365c8fe "stylesheet")to bind Python values to SQL statements,to avoid [SQL injection attacks](../_static/pydoctheme.css?v=4365c8fe "stylesheet")(see
[How to use placeholders to bind values in SQL queries](../_static/pydoctheme.css?v=4365c8fe "stylesheet") for more details).

We can verify that the new rows were insertedby executing a `SELECT` query,this time iterating 
over the results of the query:

Copy

```>>> for row in cur.execute("SELECT year, title FROM movie ORDER BY year"):...
print(row)(1971, 'And Now for Something Completely Different')(1975, 'Monty Python
and the Holy Grail')(1979, "Monty Python's Life of Brian")(1982, 'Monty Python Live
at the Hollywood Bowl')(1983, "Monty Python's The Meaning of Life")```

Each row is a two-item [`tuple`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") of `(year, title)`,matching
the columns selected in the query.

Finally, verify that the database has been written to diskby calling [`con.close()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")to close the existing connection, opening a new one,creating a new cursor, then querying the database:

Copy

```>>> con.close()>>> new_con = sqlite3.connect("tutorial.db")>>> 
new_cur = new_con.cursor()>>> res = new_cur.execute("SELECT title, year 
FROM movie ORDER BY score DESC")>>> title, year = res.fetchone()>>> 
print(f'The highest scoring Monty Python movie is {title!r}, released in {year}')The 
highest scoring Monty Python movie is 'Monty Python and the Holy Grail', released 
in 1975>>> new_con.close()```

You’ve now created an SQLite database using the `sqlite3` module,inserted data and retrieved 
values from it in multiple ways.

### Module functions[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")
sqlite3.connect(*database*, *timeout=5.0*, *detect_types=0*, *isolation_level='DEFERRED'*, 
*check_same_thread=True*, *factory=sqlite3.Connection*, *cached_statements=128*, 
*uri=False*, *\**, *autocommit=sqlite3.LEGACY_TRANSACTION_CONTROL*)[¶]( "Search within Python 3.14.7 documentation")
Open a connection to an SQLite database.
Parameters:
- **database** ([path-like object]( "Search within Python 3.14.7 documentation")) – The path to the database file to be opened.You can pass `":memory:"` to create an [SQLite database existing onlyin memory](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), and open a connectionto it.
- **timeout** ([*float*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – How many seconds the connection should wait before raisingan [`OperationalError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") when a table is locked.If another connection opens a transaction to modify a table,that table will be locked until the transaction is committed.Default five seconds.
- **detect_types** ([*int*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – Control whether and how data types not[natively supported by SQLite](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")are looked up to be converted to Python types,using the converters registered with [`register_converter()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").Set it to any combination (using `|`, bitwise or) of[`PARSE_DECLTYPES`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") and [`PARSE_COLNAMES`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")to enable this.Column names take precedence over declared types if both flags are set.By default (`0`), type detection is disabled.
- **isolation_level** ([*str*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")* | **None*) – Control legacy transaction handling behaviour.See [`Connection.isolation_level`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") and[Transaction control via the isolation_level attribute](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") for more information.Can be `"DEFERRED"` (default), `"EXCLUSIVE"` or `"IMMEDIATE"`;or `None` to disable opening transactions implicitly.Has no effect unless [`Connection.autocommit`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") is set to[`LEGACY_TRANSACTION_CONTROL`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") (the default).
- **check_same_thread** ([*bool*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – If `True` (default), [`ProgrammingError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") will be raisedif the database connection is used by a threadother than the one that created it.If `False`, the connection may be accessed in multiple threads;write operations may need to be serialized by the userto avoid data corruption.See [`threadsafety`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") for more information.
- **factory** ([*Connection*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – A custom subclass of [`Connection`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") to create the connection with,if not the default `Connection` class.
- **cached_statements** ([*int*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – The number of statements that `sqlite3`should internally cache for this connection, to avoid parsing overhead.By default, 128 statements.
- **uri** ([*bool*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – If set to `True`, *database* is interpreted as aURI with a file pathand an optional query string.The scheme part *must* be `"file:"`,and the path can be relative or absolute.The query string allows passing parameters to SQLite,enabling various [How to work with SQLite URIs](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").
- **autocommit** ([*bool*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – Control [**PEP 249**](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") transaction handling behaviour.See [`Connection.autocommit`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") and[Transaction control via the autocommit attribute](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") for more information.*autocommit* currently defaults to[`LEGACY_TRANSACTION_CONTROL`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").The default will change to `False` in a future Python release.
Return type:
[*Connection*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

Raises an [auditing event](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") `sqlite3.connect` 
with argument `database`.

Raises an [auditing event](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") `sqlite3.connect/handle` 
with argument `connection_handle`.


Changed in version 3.4: Added the *uri* parameter.


Changed in version 3.7: *database* can now also be a [path-like object](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), not only a string.


Changed in version 3.10: Added the `sqlite3.connect/handle` auditing event.


Changed in version 3.12: Added the *autocommit* parameter.


Changed in version 3.13: Positional use of the parameters *timeout*,
*detect_types*,*isolation_level*, *check_same_thread*, *factory*, *cached_statements*,and 
*uri* is deprecated.They will become keyword-only parameters in Python 3.15.
sqlite3.complete_statement(*statement*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Return `True` if the string *statement* appears to containone or more complete SQL statements.No 
syntactic verification or parsing of any kind is performed,other than checking that 
there are no unclosed string literalsand the statement is terminated by a semicolon.

For example:

Copy

```>>> sqlite3.complete_statement("SELECT foo FROM bar;")True>>>
sqlite3.complete_statement("SELECT foo")False```

This function may be useful during command-line inputto determine if the entered
text seems to form a complete SQL statement,or if additional input is needed before
calling [`execute()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").

See `runsource()` in [Lib/sqlite3/__main__.py](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")for real-world use.
sqlite3.enable_callback_tracebacks(*flag*, */*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Enable or disable callback tracebacks.By default you will not get any tracebacks
in user-defined functions,aggregates, converters, authorizer callbacks etc. If you
want to debug them,you can call this function with *flag* set to `True`. Afterwards,
youwill get tracebacks from callbacks on [`sys.stderr`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"). Use
`False`to disable the feature again.


Note

Errors in user-defined function callbacks are logged as unraisable exceptions.Use
an [`unraisable hook handler`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") forintrospection of the failed callback.
sqlite3.register_adapter(*type*, *adapter*, */*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Register an *adapter* [callable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") to adapt the Python type
*type*into an SQLite type.The adapter is called with a Python object of type *type*
as its soleargument, and must return a value of a[type that SQLite natively understands](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").

autocommit[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")
This attribute controls [**PEP 249**](../_static/pydoctheme.css?v=4365c8fe "stylesheet")-compliant transaction behaviour.`autocommit`
has three allowed values:

- `False`: Select [**PEP 249**](../_static/pydoctheme.css?v=4365c8fe "stylesheet")-compliant transaction behaviour,implying that `sqlite3` ensures a transaction is always open.Use [`commit()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") and [`rollback()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") to close transactions.

	This is the recommended value of `autocommit`.
- `True`: Use SQLite’s [autocommit mode](../_static/pydoctheme.css?v=4365c8fe "stylesheet").[`commit()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") and [`rollback()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") have no effect in this mode.
- [`LEGACY_TRANSACTION_CONTROL`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"):Pre-Python 3.12 (non-[**PEP 249**](../_static/pydoctheme.css?v=4365c8fe "stylesheet")-compliant) transaction control.See [`isolation_level`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") for more details.

	This is currently the default value of `autocommit`.

Changing `autocommit` to `False` will open a new transaction,and changing it to `True` will commit any
pending transaction.

See [Transaction control via the autocommit attribute](../_static/pydoctheme.css?v=4365c8fe "stylesheet") for more details.


Note

The [`isolation_level`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") attribute has no effect unless[`autocommit`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") is [`LEGACY_TRANSACTION_CONTROL`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").


Added in version 3.12.

### Cursor objects[¶](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation")

>
> A `Cursor` object represents a [database cursor](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation")
> which is used to execute SQL statements,
> and manage the context of a fetch operation.
> Cursors are created using [`Connection.cursor()`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation"),
> or by using any of the [connection shortcut methods](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation").
>
> Cursor objects are [iterators]( "Search within Python 3.14.7 documentation"),
> meaning that if you [`execute()`]( "Search within Python 3.14.7 documentation") a `SELECT` query,
> you can simply iterate over the cursor to fetch the resulting rows:
>
> Copy
>
> ```for row in cur.execute("SELECT t FROM data"):
>     print(row)
> ```
>
*class *sqlite3.Cursor[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
A `Cursor` instance has the following attributes and methods.

### How to use placeholders to bind values in SQL queries[¶]( "Search within Python 3.14.7 documentation")

SQL operations usually need to use values from Python variables. However,beware of 
using Python’s string operations to assemble queries, as theyare vulnerable to 
[SQL injection attacks](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"). For example, an attacker can simplyclose the single quote and inject `OR TRUE` 
to select all rows:

Copy

```>>> # Never do this -- insecure!>>> symbol = input()' OR TRUE;
-->>> sql = "SELECT \* FROM stocks WHERE symbol = '%s'" % symbol>>>
print(sql)SELECT \* FROM stocks WHERE symbol = '' OR TRUE; --'>>> cur.execute(sql)```

Instead, use the DB-API’s parameter substitution. To insert a variable into aquery
string, use a placeholder in the string, and substitute the actual valuesinto the
query by providing them as a [`tuple`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") of values to the secondargument of the cursor’s [`execute()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method.

An SQL statement may use one of two kinds of placeholders:question marks (qmark style)
or named placeholders (named style).For the qmark style, *parameters* must be a[sequence](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") whose length must match the number of placeholders,or a [`ProgrammingError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") is raised.For the named style,
*parameters* must bean instance of a [`dict`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") (or a subclass),which must contain keys for all named parameters;any extra items are ignored.Here’s an example of both styles:

Copy

```con = sqlite3.connect(":memory:")cur = con.execute("CREATE TABLE lang(name, first_appeared)")# 
This is the named style used with executemany():data = (    {"name": "C", "year": 
1972},    {"name": "Fortran", "year": 1957},    {"name": "Python", "year": 1991}, 
   {"name": "Go", "year": 2009},)cur.executemany("INSERT INTO lang VALUES(:name, 
:year)", data)# This is the qmark style used in a SELECT query:params = (1972,)cur.execute("SELECT 
\* FROM lang WHERE first_appeared = ?", params)print(cur.fetchall())con.close()```


Note

[**PEP 249**](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") numeric placeholders are
*not* supported.If used, they will be interpreted as named placeholders.

### How to adapt custom Python types to SQLite values[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

SQLite supports only a limited set of data types natively.To store custom Python 
types in SQLite databases, *adapt* them to one of the[Python types SQLite natively 
understands](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").

There are two ways to adapt Python objects to SQLite types:letting your object adapt 
itself, or using an *adapter callable*.The latter will take precedence above the 
former.For a library that exports a custom type,it may make sense to enable that 
type to adapt itself.As an application developer, it may make more sense to take 
direct control byregistering custom adapter functions.

#### How to write adaptable objects[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

Suppose we have a `Point` class that represents a pair of coordinates,`x` and `y`, in a 
Cartesian coordinate system.The coordinate pair will be stored as a text string in 
the database,using a semicolon to separate the coordinates.This can be implemented 
by adding a `__conform__(self, protocol)`method which returns the adapted value.The object passed to *protocol* 
will be of type [`PrepareProtocol`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").

Copy

```class Point:    def __init__(self, x, y):        self.x, self.y = x, y    def
__conform__(self, protocol):        if protocol is sqlite3.PrepareProtocol:      
return f"{self.x};{self.y}"con = sqlite3.connect(":memory:")cur =
con.cursor()cur.execute("SELECT ?", (Point(4.0, -3.2),))print(cur.fetchone()[0])con.close()```

#### How to register adapter callables[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

The other possibility is to create a function that converts the Python objectto an
SQLite-compatible type.This function can then be registered using [`register_adapter()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").

Copy

```class Point:    def __init__(self, x, y):        self.x, self.y = x, ydef adapt_point(point): 
   return f"{point.x};{point.y}"sqlite3.register_adapter(Point, adapt_point)con = 
sqlite3.connect(":memory:")cur = con.cursor()cur.execute("SELECT ?", (Point(1.0, 
2.5),))print(cur.fetchone()[0])con.close()```

### How to convert SQLite values to custom Python types[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

Writing an adapter lets you convert *from* custom Python types *to* SQLitevalues.To 
be able to convert *from* SQLite values *to* custom Python types,we use *converters*.

Let’s go back to the `Point` class. We stored the x and y coordinatesseparated via semicolons 
as strings in SQLite.

First, we’ll define a converter function that accepts the string as a parameterand 
constructs a `Point` object from it.


Note

Converter functions are **always** passed a [`bytes`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object,no matter the underlying SQLite data type.

Copy

```def convert_point(s):    x, y = map(float, s.split(b";"))    return Point(x, y)```

We now need to tell `sqlite3` when it should convert a given SQLite value.This is done when
connecting to a database, using the *detect_types* parameterof [`connect()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation"). There are three options:

- Implicit: set *detect_types* to [`PARSE_DECLTYPES`](../_static/opensearch.xml "Search within Python 3.14.7 documentation")
- Explicit: set *detect_types* to [`PARSE_COLNAMES`](../_static/opensearch.xml "Search within Python 3.14.7 documentation")
- Both: set *detect_types* to`sqlite3.PARSE_DECLTYPES | sqlite3.PARSE_COLNAMES`.Column names take precedence over declared types.

The following example illustrates the implicit and explicit approaches:

Copy

```class Point:    def __init__(self, x, y):        self.x, self.y = x, y    def 
__repr__(self):        return f"Point({self.x}, {self.y})"def adapt_point(point): 
   return f"{point.x};{point.y}"def convert_point(s):    x, y = list(map(float, s.split(b";"))) 
   return Point(x, y)# Register the adapter and convertersqlite3.register_adapter(Point, 
adapt_point)sqlite3.register_converter("point", convert_point)# 1) Parse using declared 
typesp = Point(4.0, -3.2)con = sqlite3.connect(":memory:", detect_types=sqlite3.PARSE_DECLTYPES)cur 
= con.execute("CREATE TABLE test(p point)")cur.execute("INSERT INTO test(p) VALUES(?)", 
(p,))cur.execute("SELECT p FROM test")print("with declared types:",
cur.fetchone()[0])cur.close()con.close()# 2) Parse using column namescon =
sqlite3.connect(":memory:", detect_types=sqlite3.PARSE_COLNAMES)cur = con.execute("CREATE 
TABLE test(p)")cur.execute("INSERT INTO test(p) VALUES(?)", (p,))cur.execute('SELECT 
p AS "p [point]" FROM test')print("with column names:", cur.fetchone()[0])cur.close()con.close()```

### How to use connection shortcut methods[¶](../contents.html "previous chapter")

Using the [`execute()`](../contents.html "previous chapter"),[`executemany()`](#tutorial "previous chapter"), and [`executescript()`](#module-functions "previous chapter")methods of the [`Connection`](#cursor-objects "previous chapter") class, your code canbe written more concisely because you don’t have to create the (oftensuperfluous) [`Cursor`](#exceptions "previous chapter") objects explicitly. Instead, the
`Cursor`objects are created implicitly and these shortcut methods return the cursorobjects.
This way, you can execute a `SELECT` statement and iterate over itdirectly using only a

```# Create and fill the table.con = sqlite3.connect(":memory:")con.execute("CREATE

Print the table contentsfor row in con.execute("SELECT name, first_appeared FROM

"rows")# close() is not a shortcut method and it's not called automatically;# the 
connection object should be closed manuallycon.close()```

### How to use the connection context manager[¶](? "note")

A [`Connection`](note "note") object can be used as a context manager thatautomatically commits or rolls back open transactions when leaving the body ofthe context manager.If the body of the [`with`](../bugs.html ">Improve this page</a></li>
      <li>
        <a href=") statement finishes without exceptions,the transaction is committed.If this commit fails,or if the body of the `with` 
statement raises an uncaught exception,the transaction is rolled back.If [`autocommit`](../genindex.html "General Index") is
`False`,a new transaction is implicitly opened after committing or rolling back.

If there is no open transaction upon leaving the body of the `with` statement,or if [`autocommit`](archiving.html "Data Compression and Archiving") is
`True`,the context manager does nothing.


Note

The context manager neither implicitly opens a new transactionnor closes the connection. 
If you need a closing context manager, considerusing [`contextlib.closing()`](../index.html "Link to this heading").

Copy

```con = sqlite3.connect(":memory:")con.execute("CREATE TABLE lang(id INTEGER PRIMARY
KEY, name VARCHAR UNIQUE)")# Successful, con.commit() is called automatically afterwardswith
con:    con.execute("INSERT INTO lang(name) VALUES(?)", ("Python",))# con.rollback()
is called after the with block finishes with an exception,# the exception is still
raised and must be caughttry:    with con:        con.execute("INSERT INTO lang(name)

twice")# Connection object used as context manager only commits or rollbacks transactions,#

### How to work with SQLite URIs[¶](../_static/pygments.css?v=b86133f3 "highlight-")

Some useful URI tricks include:

- Open a database in read-only mode:

Copy

```>>> con = sqlite3.connect("file:tutorial.db?mode=ro", uri=True)>>> 
con.execute("CREATE TABLE readonly(data)")Traceback (most recent call last):OperationalError: 
attempt to write a readonly database>>> con.close()```

- Do not implicitly create a new database file if it does not already exist;will raise [`OperationalError`](../_static/classic.css?v=234b1a7c "highlight-") if unable to create a new file:

Copy

```>>> con = sqlite3.connect("file:nosuchdb.db?mode=rw", uri=True)Traceback
(most recent call last):OperationalError: unable to open database file```

- Create a shared named in-memory database:

Copy

```db = "file:mem1?mode=memory&cache=shared"con1 = sqlite3.connect(db, uri=True)con2 
= sqlite3.connect(db, uri=True)with con1:    con1.execute("CREATE TABLE shared(data)") 
   con1.execute("INSERT INTO shared VALUES(28)")res = con2.execute("SELECT data FROM 
shared")assert res.fetchone() == (28,)con1.close()con2.close()```

More information about this feature, including a list of parameters,can be found 
in the [SQLite URI documentation](../_static/classic.css?v=234b1a7c "highlight-").

### How to create and use row factories[¶](../_static/classic.css?v=234b1a7c "highlight-")

By default, `sqlite3` represents each row as a [`tuple`](../_static/pydoctheme.css?v=4365c8fe "highlight-").If a `tuple` 
does not suit your needs,you can use the [`sqlite3.Row`](../_static/pydoctheme.css?v=4365c8fe "highlight-") classor a custom [`row_factory`](../_static/pydoctheme.css?v=4365c8fe "highlight-").

While `row_factory` exists as an attribute both on the[`Cursor`](../_static/pydoctheme.css?v=4365c8fe "highlight-") and the [`Connection`](../_static/pydoctheme.css?v=4365c8fe "highlight-"),it is recommended to set [`Connection.row_factory`](../_static/pydoctheme.css?v=4365c8fe "highlight-"),so all cursors created from the connection will use the same row factory.

`Row` provides indexed and case-insensitive named access to columns,with minimal memory 
overhead and performance impact over a `tuple`.To use `Row` as a row factory,assign it to 
the `row_factory` attribute:

Copy

```>>> con = sqlite3.connect(":memory:")>>> con.row_factory = sqlite3.Row```

Queries now return `Row` objects:

Copy

```>>> res = con.execute("SELECT 'Earth' AS name, 6378 AS radius")>>> 
row = res.fetchone()>>> row.keys()['name', 'radius']>>> row[0] 
        # Access by index.'Earth'>>> row["name"]    # Access by name.'Earth'>>> 
row["RADIUS"]  # Column names are case-insensitive.6378>>> con.close()```


Note

The `FROM` clause can be omitted in the `SELECT` statement, as in theabove example. In such 
cases, SQLite returns a single row with columnsdefined by expressions, e.g. literals, 
with the given aliases`expr AS alias`.

You can create a custom [`row_factory`](../_static/pydoctheme.css?v=4365c8fe "highlight-")that returns each row as a [`dict`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), with column names mapped to values:

Copy

```def dict_factory(cursor, row):    fields = [column[0] for column in cursor.description]
return {key: value for key, value in zip(fields, row)}```

Using it, queries now return a `dict` instead of a `tuple`:

Copy

```>>> con = sqlite3.connect(":memory:")>>> con.row_factory =
dict_factory>>> for row in con.execute("SELECT 1 AS a, 2 AS b"):...    
 print(row){'a': 1, 'b': 2}>>> con.close()```

The following row factory returns a [named tuple](../_static/pydoctheme.css?v=4365c8fe "stylesheet"):

Copy

```from collections import namedtupledef namedtuple_factory(cursor, row):    fields
= [column[0] for column in cursor.description]    cls = namedtuple("Row", fields)
return cls._make(row)```

`namedtuple_factory()` can be used as follows:

Copy

```>>> con = sqlite3.connect(":memory:")>>> con.row_factory =
namedtuple_factory>>> cur = con.execute("SELECT 1 AS a, 2 AS b")>>> 
row = cur.fetchone()>>> rowRow(a=1, b=2)>>> row[0]  # Indexed access.1>>> 
row.b   # Attribute access.2>>> con.close()```

With some adjustments, the above recipe can be adapted to use a[`dataclass`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), or any other custom class,instead of a [`namedtuple`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").

### How to handle non-UTF-8 text encodings[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

By default, `sqlite3` uses [`str`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") to adapt SQLite valueswith the `TEXT` 
data type.This works well for UTF-8 encoded text, but it might fail for other encodingsand 
invalid UTF-8.You can use a custom [`text_factory`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") to handle such cases.

Because of SQLite’s [flexible typing](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), it is not uncommon to encounter tablecolumns with the `TEXT` 
data type containing non-UTF-8 encodings,or even arbitrary data.To demonstrate, let’s 
assume we have a database with ISO-8859-2 (Latin-2)encoded text, for example a table 
of Czech-English dictionary entries.Assuming we now have a [`Connection`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") instance
`con`connected to this database,we can decode the Latin-2 encoded text using this 
[`text_factory`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"):

Copy

```con.text_factory = lambda data: str(data, encoding="latin2")```

For invalid UTF-8 or arbitrary data in stored in `TEXT` table columns,you can use the
following technique, borrowed from the [Unicode HOWTO](../_static/pydoctheme.css?v=4365c8fe "stylesheet"):

Copy

```con.text_factory = lambda data: str(data, errors="surrogateescape")```


Note

The `sqlite3` module API does not support stringscontaining surrogates.


See also

[Unicode HOWTO](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

### Transaction control[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

`sqlite3` offers multiple methods of controlling whether,when and how database transactions 
are opened and closed.[Transaction control via the autocommit attribute](../_static/pydoctheme.css?v=4365c8fe "stylesheet") is recommended,while
[Transaction control via the isolation_level attribute](../_static/pydoctheme.css?v=4365c8fe "stylesheet")retains the pre-Python 3.12 behaviour.

#### Transaction control via the `autocommit` attribute[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

The recommended way of controlling transaction behaviour is throughthe [`Connection.autocommit`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") attribute,which should preferably be set using the
*autocommit* parameterof [`connect()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").

It is suggested to set *autocommit* to `False`,which implies [**PEP 249**](../_static/pydoctheme.css?v=4365c8fe "stylesheet")-compliant transaction control.This means:

- `sqlite3` ensures that a transaction is always open,so [`connect()`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation"), [`Connection.commit()`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation"), and [`Connection.rollback()`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation")will implicitly open a new transaction(immediately after closing the pending one, for the latter two).`sqlite3` uses `BEGIN DEFERRED` statements when opening transactions.
- Transactions should be committed explicitly using `commit()`.
- Transactions should be rolled back explicitly using `rollback()`.
- An implicit rollback is performed if the database is[`close()`]( "Search within Python 3.14.7 documentation")-ed with pending changes.

Set *autocommit* to `True` to enable SQLite’s [autocommit mode]( "Search within Python 3.14.7 documentation").In this mode, [`Connection.commit()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") and [`Connection.rollback()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")have no effect.Note that SQLite’s autocommit mode is distinct fromthe
[**PEP 249**](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")-compliant [`Connection.autocommit`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") attribute;use [`Connection.in_transaction`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") to querythe low-level SQLite autocommit mode.

Set *autocommit* to [`LEGACY_TRANSACTION_CONTROL`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")to leave transaction control behaviour to the[`Connection.isolation_level`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") attribute.See
[Transaction control via the isolation_level attribute](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") for more information.

#### Transaction control via the `isolation_level` attribute[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")


Note

The recommended way of controlling transactions is via the[`autocommit`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") attribute.See
[Transaction control via the autocommit attribute](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").

If [`Connection.autocommit`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") is set to[`LEGACY_TRANSACTION_CONTROL`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") (the default),transaction behaviour is controlled usingthe [`Connection.isolation_level`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") attribute.Otherwise, `isolation_level` 
has no effect.

If the connection attribute [`isolation_level`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")is not
`None`,new transactions are implicitly opened before[`execute()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") and [`executemany()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
executes`INSERT`, `UPDATE`, `DELETE`, or `REPLACE` statements;for other statements, no implicit transaction 
handling is performed.Use the [`commit()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") and [`rollback()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") methodsto respectively commit and roll back pending transactions.You can choose the underlying [SQLite transaction behaviour](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") —that is, whether and what type of `BEGIN` 
statements `sqlite3`implicitly executes –via the `isolation_level` attribute.

If [`isolation_level`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") is set to
`None`,no transactions are implicitly opened at all.This leaves the underlying SQLite 
library in [autocommit mode](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"),but also allows the user to perform their own transaction handlingusing explicit SQL statements.The underlying SQLite library autocommit mode can be queried using the[`in_transaction`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") attribute.

The [`executescript()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method implicitly commitsany pending transaction before execution of the given SQL script,regardless of the value of [`isolation_level`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").


Changed in version 3.6: `sqlite3` used to implicitly commit an open transaction before DDLstatements. 
 This is no longer the case.


Changed in version 3.12: The recommended way of controlling transactions is now via 
the[`autocommit`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") attribute.
