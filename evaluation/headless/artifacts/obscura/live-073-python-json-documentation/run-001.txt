# `json` — JSON encoder and decoder[¶](../_static/pygments.css?v=b86133f3 "json — JSON encoder and decoder")

**Source code:** [Lib/json/__init__.py](../_static/pygments.css?v=b86133f3 "viewport")

---

[JSON (JavaScript Object Notation)](../_static/pygments.css?v=b86133f3 "viewport"), specified
by[**RFC 7159**](../_static/pygments.css?v=b86133f3 "viewport") (which obsoletes [**RFC
4627**](../_static/pygments.css?v=b86133f3 "viewport")) and by[ECMA-404](../_static/pygments.css?v=b86133f3 "viewport"),is a lightweight data interchange format inspired by[JavaScript](../_static/pygments.css?v=b86133f3 "viewport") object literal syntax(although it is not a strict subset of JavaScript
[[1]](../_static/pygments.css?v=b86133f3 "viewport") ).


Note

The term “object” in the context of JSON processing in Python can beambiguous.
All values in Python are objects. In JSON, an object refers toany data wrapped in
curly braces, similar to a Python dictionary.


Warning

Be cautious when parsing JSON data from untrusted sources. A maliciousJSON string
may cause the decoder to consume considerable CPU and memoryresources. Limiting the
size of data to be parsed is recommended.

This module exposes an API familiar to users of the standard library[`marshal`](../_static/classic.css?v=234b1a7c "highlight-") and [`pickle`](../_static/classic.css?v=234b1a7c "highlight-") modules.

Encoding basic Python object hierarchies:

Copy

```>>> import json>>> json.dumps(['foo', {'bar': ('baz', None, 
1.0, 2)}])'["foo", {"bar": ["baz", null, 1.0, 2]}]'>>>
print(json.dumps("\\"foo\\bar"))"\\"foo\\bar">>>
print(json.dumps('\\u1234'))"\\u1234">>> print(json.dumps('\\\\'))"\\\\">>> 
print(json.dumps({"c": 0, "b": 0, "a": 0}, sort_keys=True)){"a": 0, "b": 0, "c": 
0}>>> from io import StringIO>>> io = StringIO()>>> json.dump(['streaming 
API'], io)>>> io.getvalue()'["streaming API"]'```

Compact encoding:

Copy

```>>> import json>>> json.dumps([1, 2, 3, {'4': 5, '6': 7}], separators=(',',
':'))'[1,2,3,{"4":5,"6":7}]'```

Pretty printing:

Copy

```>>> import json>>> print(json.dumps({'6': 7, '4': 5}, sort_keys=True, 
indent=4)){    "4": 5,    "6": 7}```

Customizing JSON object encoding:

Copy

```>>> import json>>> def custom_json(obj):...     if isinstance(obj,
complex):...         return {'__complex__': True, 'real': obj.real, 'imag': obj.imag}...
raise TypeError(f'Cannot serialize object of {type(obj)}')...>>> json.dumps(1
+ 2j, default=custom_json)'{"__complex__": true, "real": 1.0, "imag": 2.0}'```

Decoding JSON:

Copy

```>>> import json>>> json.loads('["foo", {"bar":["baz", null, 
1.0, 2]}]')['foo', {'bar': ['baz', None, 1.0, 2]}]>>>
json.loads('"\\\\"foo\\\\bar"')'"foo\\x08ar'>>> from io import StringIO>>> 
io = StringIO('["streaming API"]')>>> json.load(io)['streaming API']```

Customizing JSON object decoding:

Copy

```>>> import json>>> def as_complex(dct):...     if '__complex__'
in dct:...         return complex(dct['real'], dct['imag'])...     return dct...>>>
json.loads('{"__complex__": true, "real": 1, "imag": 2}',...    
object_hook=as_complex)(1+2j)>>> import decimal>>> json.loads('1.1',
parse_float=decimal.Decimal)Decimal('1.1')```

See [Command-line interface](../_static/pydoctheme.css?v=4365c8fe "stylesheet") for detailed documentation.


Note

JSON is a subset of [YAML](../_static/pydoctheme.css?v=4365c8fe "stylesheet") 1.2.  The JSON produced bythis module’s default settings (in particular, the default
*separators*value) is also a subset of YAML 1.0 and 1.1.  This module can thus also
beused as a YAML serializer.


Note

This module’s encoders and decoders preserve input and output order bydefault.
Order is only lost if the underlying containers are unordered.

## Basic Usage[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")
json.dump(*obj*, *fp*, *\**, *skipkeys=False*, *ensure_ascii=True*, *check_circular=True*,
*allow_nan=True*, *cls=None*, *indent=None*, *separators=None*, *default=None*, *sort_keys=False*,
*\*\*kw*)[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")
Serialize *obj* as a JSON formatted stream to *fp* (a `.write()`-supporting[file-like object](../_static/pydoctheme.css?v=4365c8fe "stylesheet")) using this
[Python-to-JSON conversion table](../_static/pydoctheme.css?v=4365c8fe "stylesheet").


Note

Unlike [`pickle`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") and [`marshal`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), JSON is not a framed protocol,so trying to serialize multiple objects with repeated calls to`dump()`
using the same *fp* will result in an invalid JSON file.
Parameters:
- **obj** ([*object*](../_static/pydoctheme.css?v=4365c8fe "stylesheet")) – The Python object to be serialized.
- **fp** ([file-like object](../_static/pydoctheme.css?v=4365c8fe "stylesheet")) – The file-like object *obj* will be serialized to.The `json` module always produces [`str`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") objects,not [`bytes`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") objects,therefore `fp.write()` must support `str` input.
- **skipkeys** ([*bool*](../_static/pydoctheme.css?v=4365c8fe "stylesheet")) – If `True`, keys that are not of a basic type([`str`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`int`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`float`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), `bool`, `None`)will be skipped instead of raising a [`TypeError`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").Default `False`.
- **ensure_ascii** ([*bool*](../_static/pydoctheme.css?v=4365c8fe "stylesheet")) – If `True` (the default), the output is guaranteed tohave all incoming non-ASCII and non-printable characters escaped.If `False`, all characters will be outputted as-is, except forthe characters that must be escaped: quotation mark, reverse solidus,and the control characters U+0000 through U+001F.
- **check_circular** ([*bool*](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation")) – If `False`, the circular reference check for container types is skippedand a circular reference will result in a [`RecursionError`](../_static/pydoctheme.css?v=4365c8fe "Search within Python 3.14.7 documentation") (or worse).Default `True`.
- **allow_nan** ([*bool*]( "Search within Python 3.14.7 documentation")) – If `False`, serialization of out-of-range [`float`]( "Search within Python 3.14.7 documentation") values(`nan`, `inf`, `-inf`) will result in a [`ValueError`]( "Search within Python 3.14.7 documentation"),in strict compliance with the JSON specification.If `True` (the default), their JavaScript equivalents(`NaN`, `Infinity`, `-Infinity`) are used.
- **cls** (a [`JSONEncoder`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") subclass) – If set, a custom JSON encoder with the[`default()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method overridden,for serializing into custom datatypes.If `None` (the default), `JSONEncoder` is used.
- **indent** ([*int*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")* | *[*str*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")* | **None*) – If a positive integer or string, JSON array elements andobject members will be pretty-printed with that indent level.A positive integer indents that many spaces per level;a string (such as `"\t"`) is used to indent each level.If zero, negative, or `""` (the empty string),only newlines are inserted.If `None` (the default), no newlines are inserted.
- **separators** ([*tuple*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")* | **None*) – A two-tuple: `(item_separator, key_separator)`.If `None` (the default), *separators* defaults to`(', ', ': ')` if *indent* is `None`,and `(',', ': ')` otherwise.For the most compact JSON,specify `(',', ':')` to eliminate whitespace.
- **default** ([callable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") | None) – A function that is called for objects that can’t otherwise be serialized.It should return a JSON encodable version of the objector raise a [`TypeError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").If `None` (the default), `TypeError` is raised.
- **sort_keys** ([*bool*](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – If `True`, dictionaries will be outputted sorted by key.Default `False`.


Changed in version 3.2: Allow strings for *indent* in addition to integers.


Changed in version 3.4: Use `(',', ': ')` as default if *indent* is not `None`.


Changed in version 3.6: All optional parameters are now [keyword-only](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").
json.dumps(*obj*, *\**, *skipkeys=False*, *ensure_ascii=True*, *check_circular=True*,
*allow_nan=True*, *cls=None*, *indent=None*, *separators=None*, *default=None*, *sort_keys=False*,
*\*\*kw*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Serialize *obj* to a JSON formatted [`str`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") using this
[conversiontable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").  The arguments have the same meaning as in[`dump()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").


Note

Keys in key/value pairs of JSON are always of the type [`str`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"). Whena dictionary is converted into JSON, all the keys of the dictionary arecoerced to strings. As a result of this, if a dictionary is convertedinto JSON and then back into a dictionary, the dictionary may not equalthe original one. That is, `loads(dumps(x)) != x`
if x has non-stringkeys.
json.load(*fp*, *\**, *cls=None*, *object_hook=None*, *parse_float=None*, *parse_int=None*,
*parse_constant=None*, *object_pairs_hook=None*, *\*\*kw*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Deserialize *fp* to a Python objectusing the [JSON-to-Python conversion table](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").
Parameters:
- **fp** ([file-like object](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")) – A `.read()`-supporting [text file](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") or [binary file](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")containing the JSON document to be deserialized.

- **object_hook** ([callable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") | None) – If set, a function that is called with the result ofany JSON object literal decoded (a [`dict`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")).The return value of this function will be usedinstead of the `dict`.This feature can be used to implement custom decoders,for example [JSON-RPC](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") class hinting.Default `None`.
- **object_pairs_hook** ([callable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") | None) – If set, a function that is called with the result ofany JSON object literal decoded with an ordered list of pairs.The return value of this function will be usedinstead of the [`dict`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").This feature can be used to implement custom decoders.If *object_hook* is also set, *object_pairs_hook* takes priority.Default `None`.
- **parse_float** ([callable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") | None) – If set, a function that is called withthe string of every JSON float to be decoded.If `None` (the default), it is equivalent to `float(num_str)`.This can be used to parse JSON floats into custom datatypes,for example [`decimal.Decimal`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").
- **parse_int** ([callable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") | None) – If set, a function that is called withthe string of every JSON int to be decoded.If `None` (the default), it is equivalent to `int(num_str)`.This can be used to parse JSON integers into custom datatypes,for example [`float`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").
- **parse_constant** ([callable](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") | None) – If set, a function that is called with one of the following strings:`'-Infinity'`, `'Infinity'`, or `'NaN'`.This can be used to raise an exceptionif invalid JSON numbers are encountered.Default `None`.
Raises:
- [**JSONDecodeError**](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") – When the data being deserialized is not a valid JSON document.
- [**UnicodeDecodeError**](../_static/opensearch.xml "Search within Python 3.14.7 documentation") – When the data being deserialized does not containUTF-8, UTF-16 or UTF-32 encoded data.

- *fp* can now be a [binary file](../_static/opensearch.xml "Search within Python 3.14.7 documentation").The input encoding should be UTF-8, UTF-16 or UTF-32.


Changed in version 3.11: The default *parse_int* of [`int()`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") now limits the maximum length ofthe integer string via the interpreter’s
[integer stringconversion length limitation](../_static/opensearch.xml "Search within Python 3.14.7 documentation") to help avoid denialof service attacks.

## Encoders and Decoders[¶](../_static/opensearch.xml "About these documents")
*class *json.JSONDecoder(*\**, *object_hook=None*, *parse_float=None*, *parse_int=None*,
*parse_constant=None*, *strict=True*, *object_pairs_hook=None*)[¶](../_static/py.svg "previous chapter")
Simple JSON decoder.

Performs the following translations in decoding by default:

|               |
|---------------|
|               |
| Python        |
| -             | - |
|               |
| object        |
|               |
| dict          |
| array         |
|               |
| list          |
| string        |
|               |
| str           |
| number (int)  |
|               |
| int           |
| number (real) |
|               |
| float         |
| true          |
|               |
| True          |
| false         |
|               |
| False         |
| null          |
|               |
| None          |

It also understands `NaN`, `Infinity`, and `-Infinity` as theircorresponding `float` values, which is outside
the JSON spec.

*object_hook* is an optional function that will be called with the result ofevery
JSON object decoded and its return value will be used in place of thegiven [`dict`](../_static/py.svg "previous chapter").  This can be used to provide custom deserializations(e.g. to support [JSON-RPC](../_static/py.svg "previous chapter") class hinting).

*object_pairs_hook* is an optional function that will be called with theresult of
every JSON object decoded with an ordered list of pairs.  Thereturn value of *object_pairs_hook*
will be used instead of the[`dict`](../_static/py.svg "previous chapter").  This feature can be used to implement custom decoders.
If*object_hook* is also defined, the *object_pairs_hook* takes priority.


Changed in version 3.1: Added support for *object_pairs_hook*.

*parse_float* is an optional function that will be called with the string ofevery
JSON float to be decoded.  By default, this is equivalent to`float(num_str)`.  This can be used
to use another datatype or parser forJSON floats (e.g. [`decimal.Decimal`](../_static/py.svg "previous chapter")).

*parse_int* is an optional function that will be called with the string ofevery JSON
int to be decoded.  By default, this is equivalent to`int(num_str)`.  This can be used to use
another datatype or parser forJSON integers (e.g. [`float`](https://www.python.org/ "previous chapter")).

*parse_constant* is an optional function that will be called with one of thefollowing
strings: `'-Infinity'`, `'Infinity'`, `'NaN'`.  This can beused to raise an exception if invalid JSON numbers
are encountered.

If *strict* is false (`True` is the default), then control characterswill be allowed
inside strings.  Control characters in this context arethose with character codes
in the 0–31 range, including `'\t'` (tab),`'\n'`, `'\r'` and `'\0'`.

If the data being deserialized is not a valid JSON document, a[`JSONDecodeError`](../contents.html "previous chapter") will be raised.


Changed in version 3.6: All parameters are now [keyword-only](../contents.html "previous chapter").

This can be used to decode a JSON document from a string that may haveextraneous

If *skipkeys* is false (the default), a [`TypeError`](../index.html "Link to this heading") will be raised whentrying to encode keys that are not [`str`](../index.html "Link to this heading"), [`int`](../index.html "Link to this heading"), [`float`](../index.html "Link to this heading"),[`bool`](../index.html "Link to this heading") or

If *ensure_ascii* is true (the default), the output is guaranteed tohave all incoming
non-ASCII and non-printable characters escaped.If *ensure_ascii* is false, all characters
will be output as-is, except forthe characters that must be escaped: quotation mark,
reverse solidus,and the control characters U+0000 through U+001F.

If *check_circular* is true (the default), then lists, dicts, and customencoded objects
will be checked for circular references during encoding toprevent an infinite recursion
(which would cause a [`RecursionError`](../index.html "Link to this heading")).Otherwise, no such check takes place.

If *allow_nan* is true (the default), then `NaN`, `Infinity`, and`-Infinity` will be encoded as such.
This behavior is not JSONspecification compliant, but is consistent with most JavaScript
basedencoders and decoders.  Otherwise, it will be a [`ValueError`](#module-json "Link to this heading") to encodesuch floats.

If *sort_keys* is true (default: `False`), then the output of dictionarieswill be sorted
by key; this is useful for regression tests to ensure thatJSON serializations can
be compared on a day-to-day basis.

If *indent* is a non-negative integer or string, then JSON array elements andobject
members will be pretty-printed with that indent level.  An indent levelof 0, negative,
or `""` will only insert newlines.  `None` (the default)selects the most compact representation.
Using a positive integer indentindents that many spaces per level.  If *indent* is
a string (such as `"\t"`),that string is used to indent each level.


Changed in version 3.2: Allow strings for *indent* in addition to integers.

If specified, *separators* should be an `(item_separator, key_separator)`tuple.  The default is `(', ', ': ')` if *indent* is
`None` and`(',', ': ')` otherwise.  To get the most compact JSON representation,you should specify
`(',', ':')` to eliminate whitespace.


Changed in version 3.4: Use `(',', ': ')` as default if *indent* is not `None`.

If specified, *default* should be a function that gets called for objects thatcan’t
otherwise be serialized.  It should return a JSON encodable version ofthe object
or raise a [`TypeError`](../_static/classic.css?v=234b1a7c "highlight-").  If not specified, `TypeError`is
raised.

## Standard Compliance and Interoperability[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")

The JSON format is specified by [**RFC 7159**](../_static/pydoctheme.css?v=4365c8fe "highlight-") and by[ECMA-404](../_static/pydoctheme.css?v=4365c8fe "highlight-").This section details this module’s level of compliance with the RFC.For simplicity, [`JSONEncoder`](../_static/pydoctheme.css?v=4365c8fe "highlight-") and [`JSONDecoder`](../_static/pydoctheme.css?v=4365c8fe "highlight-") subclasses, andparameters other than those explicitly mentioned, are not considered.

This module does not comply with the RFC in a strict fashion, implementing someextensions 
that are valid JavaScript but not valid JSON.  In particular:

- Infinite and NaN number values are accepted and output;
- Repeated names within an object are accepted, and only the value of the lastname-value pair is used.

Since the RFC permits RFC-compliant parsers to accept input texts that are notRFC-compliant, 
this module’s deserializer is technically RFC-compliant underdefault settings.

### Character Encodings[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")

The RFC requires that JSON be represented using either UTF-8, UTF-16, orUTF-32, with 
UTF-8 being the recommended default for maximum interoperability.

As permitted, though not required, by the RFC, this module’s serializer sets*ensure_ascii=True* 
by default, thus escaping the output so that the resultingstrings only contain printable 
ASCII characters.

Other than the *ensure_ascii* parameter, this module is defined strictly interms 
of conversion between Python objects and[`Unicode strings`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), and thus does not otherwise directly addressthe issue of character encodings.

The RFC prohibits adding a byte order mark (BOM) to the start of a JSON text,and 
this module’s serializer does not add a BOM to its output.The RFC permits, but 
does not require, JSON deserializers to ignore an initialBOM in their input.  This 
module’s deserializer raises a [`ValueError`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")when an initial BOM is present.

The RFC does not explicitly forbid JSON strings which contain byte sequencesthat 
don’t correspond to valid Unicode characters (e.g. unpaired UTF-16surrogates), 
but it does note that they may cause interoperability problems.By default, this module 
accepts and outputs (when present in the original[`str`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")) code points for such sequences.

### Infinite and NaN Number Values[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

The RFC does not permit the representation of infinite or NaN number values.Despite 
that, by default, this module accepts and outputs `Infinity`,`-Infinity`, and `NaN` as if they were valid 
JSON number literal values:

Copy

```>>> # Neither of these calls raises an exception, but the results are
not valid JSON>>> json.dumps(float('-inf'))'-Infinity'>>>
json.dumps(float('nan'))'NaN'>>> # Same when deserializing>>>
json.loads('-Infinity')-inf>>> json.loads('NaN')nan```

In the serializer, the *allow_nan* parameter can be used to alter thisbehavior.  
In the deserializer, the *parse_constant* parameter can be used toalter this behavior.

### Repeated Names Within an Object[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

The RFC specifies that the names within a JSON object should be unique, butdoes not
mandate how repeated names in JSON objects should be handled.  Bydefault, this module
does not raise an exception; instead, it ignores all butthe last name-value pair
for a given name:

Copy

```>>> weird_json = '{"x": 1, "x": 2, "x": 3}'>>> json.loads(weird_json){'x': 
3}```

The *object_pairs_hook* parameter can be used to alter this behavior.

### Top-level Non-Object, Non-Array Values[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

The old version of JSON specified by the obsolete [**RFC 4627**](../_static/pydoctheme.css?v=4365c8fe "stylesheet") required thatthe top-level value of a JSON text must be either a JSON object or array(Python [`dict`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") or [`list`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")), and could not be a JSON null,boolean, number, or string value. 
[**RFC 7159**](../_static/pydoctheme.css?v=4365c8fe "stylesheet") removed that restriction, andthis module does not and has never implemented that restriction in either itsserializer or its deserializer.

Regardless, for maximum interoperability, you may wish to voluntarily adhereto the 
restriction yourself.

### Implementation Limitations[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

Some JSON deserializer implementations may set limits on:

- the size of accepted JSON texts
- the maximum level of nesting of JSON objects and arrays
- the range and precision of JSON numbers
- the content and maximum length of JSON strings

This module does not impose any such limits beyond those of the relevantPython datatypes 
themselves or the Python interpreter itself.

When serializing to JSON, beware any such limitations in applications that mayconsume 
your JSON.  In particular, it is common for JSON numbers to bedeserialized into IEEE 
754 double precision numbers and thus subject to thatrepresentation’s range and 
precision limitations.  This is especially relevantwhen serializing Python [`int`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") values of extremely large magnitude, orwhen serializing instances of “exotic” numerical types such as[`decimal.Decimal`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").

## Command-line interface[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

**Source code:** [Lib/json/tool.py](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

The `json` module can be invoked as a script via `python -m json`to validate and pretty-print JSON 
objects. The `json.tool` submoduleimplements this interface.

If the optional `infile` and `outfile` arguments are notspecified, [`sys.stdin`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") and [`sys.stdout`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") will be used respectively:

Copy

```$ echo '{"json": "obj"}' | python -m json{    "json": "obj"}$ echo '{1.2:3.4}'
| python -m jsonExpecting property name enclosed in double quotes: line 1 column
2 (char 1)```


Changed in version 3.5: The output is now in the same order as the input. Use the[`--sort-keys`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") option to sort the output of dictionariesalphabetically by key.


Changed in version 3.14: The `json` module may now be directly executed as`python -m json`. For backwards
compatibility, invokingthe CLI as `python -m json.tool` remains supported.
