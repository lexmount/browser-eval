# `datetime` — Basic date and time types[¶](../_static/classic.css?v=234b1a7c "highlight-")

**Source code:** [Lib/datetime.py](../_static/classic.css?v=234b1a7c "highlight-")

---

The `datetime` module supplies classes for manipulating dates and times.

While date and time arithmetic is supported, the focus of the implementation ison
efficient attribute extraction for output formatting and manipulation.


Tip

Skip to [the format codes](../_static/classic.css?v=234b1a7c "highlight-").

Time access and conversions.

Third-party library that introduces distinct static types to for example,allow [static

## Aware and naive objects[¶](../_static/classic.css?v=234b1a7c "highlight-")

Date and time objects may be categorized as “aware” or “naive” depending
onwhether or not they include time zone information.

With sufficient knowledge of applicable algorithmic and political timeadjustments,
such as time zone and daylight saving time information,an **aware** object can locate
itself relative to other aware objects.An aware object represents a specific moment
in time that is not open tointerpretation. [[1]](../_static/classic.css?v=234b1a7c "highlight-")

A **naive** object does not contain enough information to unambiguously locateitself
relative to other date/time objects. Whether a naive object representsCoordinated
Universal Time (UTC), local time, or time in some other time zone ispurely up to
the program, just like it is up to the program whether aparticular number represents
metres, miles, or mass. Naive objects are easy tounderstand and to work with, at
the cost of ignoring some aspects of reality.

For applications requiring aware objects, [`datetime`](../_static/classic.css?v=234b1a7c "highlight-") and [`time`](../_static/classic.css?v=234b1a7c "highlight-")objects have an optional time zone information attribute,
`tzinfo`, thatcan be set to an instance of a subclass of the abstract `tzinfo` class.These
[`tzinfo`](../_static/classic.css?v=234b1a7c "highlight-") objects capture information about the offset from UTCtime, the time zone name, and whether daylight saving time is in effect.

Only one concrete [`tzinfo`](../_static/pydoctheme.css?v=4365c8fe "highlight-") class, the [`timezone`](../_static/pydoctheme.css?v=4365c8fe "highlight-") class, issupplied by the `datetime`
module. The `timezone` class canrepresent simple time zones with fixed offsets from UTC,
such as UTC itself orNorth American EST and EDT time zones. Supporting time zones
at deeper levels ofdetail is up to the application. The rules for time adjustment
across theworld are more political than rational, change frequently, and there is
nostandard suitable for every application aside from UTC.

## Available types[¶](../_static/pydoctheme.css?v=4365c8fe "highlight-")
*class *datetime.date
An idealized naive date, assuming the current Gregorian calendar always was, andalways
will be, in effect. Attributes: [`year`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), [`month`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), and[`day`](../_static/pydoctheme.css?v=4365c8fe "highlight-").
*class *datetime.time
An idealized time, independent of any particular day, assuming that every dayhas
exactly 24\*60\*60 seconds.  (There is no notion of “leap seconds” here.)Attributes:
[`hour`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), [`minute`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), [`second`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), [`microsecond`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"),and [`tzinfo`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").
*class *datetime.datetime
A combination of a date and a time. Attributes: [`year`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`month`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"),[`day`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`hour`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`minute`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`second`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`microsecond`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"),and [`tzinfo`](../_static/pydoctheme.css?v=4365c8fe "stylesheet").
*class *datetime.timedelta
A duration expressing the difference between two [`datetime`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")or [`date`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") instances to microsecond resolution.
*class *datetime.tzinfo
An abstract base class for time zone information objects. These are used by the[`datetime`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") and [`time`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") classes to provide a customizable notion oftime adjustment (for example, to account for time zone and/or daylight savingtime).
*class *datetime.timezone
A class that implements the [`tzinfo`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") abstract base class as afixed offset from the UTC.


Added in version 3.2.

Objects of these types are immutable.

### Common properties[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

The [`date`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`datetime`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), [`time`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), and [`timezone`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") typesshare these common features:

- Objects of these types are immutable.
- Objects of these types are [hashable](../_static/pydoctheme.css?v=4365c8fe "stylesheet"), meaning that they can be used asdictionary keys.
- Objects of these types support efficient pickling via the [`pickle`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") module.

### Determining if an object is aware or naive[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

Objects of the [`date`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") type are always naive.

An object of type [`time`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") or [`datetime`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") may be aware or naive.

A [`datetime`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") object `d` is aware if both
of the following hold:

1. `d.tzinfo` is not `None`
2. `d.tzinfo.utcoffset(d)` does not return `None`


Otherwise, `d` is naive.

A [`time`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") object `t` is aware if both
of the following hold:

1. `t.tzinfo` is not `None`
2. `t.tzinfo.utcoffset(None)` does not return `None`.


Otherwise, `t` is naive.

The distinction between aware and naive doesn’t apply to [`timedelta`](../_static/pydoctheme.css?v=4365c8fe "stylesheet")objects.

## `timedelta` objects[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")

A [`timedelta`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") object represents a duration, the difference between two[`datetime`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") or [`date`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") instances.
*class *datetime.timedelta(*days=0*, *seconds=0*, *microseconds=0*, *milliseconds=0*,
*minutes=0*, *hours=0*, *weeks=0*)[¶](../_static/pydoctheme.css?v=4365c8fe "stylesheet")
All arguments are optional and default to 0. Arguments may be integersor floats,
and may be positive or negative.

Only *days*, *seconds* and *microseconds* are stored internally.Arguments are converted
to those units:

- A millisecond is converted to 1000 microseconds.
- A minute is converted to 60 seconds.
- An hour is converted to 3600 seconds.
- A week is converted to 7 days.

and days, seconds and microseconds are then normalized so that therepresentation
is unique, with

- `0 <= microseconds < 1000000`
- `0 <= seconds < 3600*24` (the number of seconds in one day)
- `-999999999 <= days <= 999999999`

The following example illustrates how any arguments besides*days*, *seconds* and
*microseconds* are “merged” and normalized into thosethree resulting attributes:

Copy

```>>> import datetime as dt>>> delta = dt.timedelta(...     days=50,... 
    seconds=27,...     microseconds=10,...     milliseconds=29000,...     minutes=5,... 
    hours=8,...     weeks=2... )>>> # Only days, seconds, and microseconds 
remain>>> deltadatetime.timedelta(days=64, seconds=29156, microseconds=10)```


Tip

`import datetime as dt` instead of `import datetime` or`from datetime import datetime` to avoid confusion between the moduleand the class. See [How I Import Python’s datetime Module](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").

If any argument is a float and there are fractional microseconds,the fractional microseconds 
left over from all arguments arecombined and their sum is rounded to the nearest 
microsecond usinground-half-to-even tiebreaker. If no argument is a float, theconversion 
and normalization processes are exact (no information islost).

If the normalized value of days lies outside the indicated range,[`OverflowError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") is raised.

Note that normalization of negative values may be surprising at first. Forexample:

Copy

```>>> import datetime as dt>>> d = dt.timedelta(microseconds=-1)>>>
(d.days, d.seconds, d.microseconds)(-1, 86399, 999999)```

Since the string representation of `timedelta` objects can be confusing,use the following
recipe to produce a more readable format:

Copy

```>>> def pretty_timedelta(td):...     if td.days >= 0:...         return 
str(td)...     return f'-({-td!s})'...>>> d = timedelta(hours=-1)>>> 
str(d)  # not human-friendly'-1 day, 23:00:00'>>> pretty_timedelta(d)'-(1:00:00)'```

Class attributes:
timedelta.min[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
The most negative [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object,
`timedelta(-999999999)`.
timedelta.max[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
The most positive [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object, `timedelta(days=999999999,

timedelta.resolution[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
The smallest possible difference between non-equal [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

Note that, because of normalization, `timedelta.max` is greater than `-timedelta.min`.`-timedelta.max` is not representable 
as a [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object.

Instance attributes (read-only):
timedelta.days[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Between -999,999,999 and 999,999,999 inclusive.
timedelta.seconds[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Between 0 and 86,399 inclusive.

It is a somewhat common bug for code to unintentionally use this attributewhen it 
is actually intended to get a [`total_seconds()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")value instead:

Copy

```>>> import datetime as dt>>> duration =
dt.timedelta(seconds=11235813)>>> duration.days, duration.seconds(130,
3813)>>> duration.total_seconds()11235813.0```
timedelta.microseconds[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Between 0 and 999,999 inclusive.

4. `-timedelta.max` is not representable as a [`timedelta`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object.
5. String representations of [`timedelta`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") objects are normalizedsimilarly to their internal representation. This leads to somewhatunusual results for negative timedeltas. For example:

Copy		>>> timedelta(hours=-5)datetime.timedelta(days=-1, seconds=68400)>>> print(_)-1 day, 19:00:00
6. The expression `t2 - t3` will always be equal to the expression `t2 + (-t3)` exceptwhen t3 is equal to `timedelta.max`; in that case the former will produce a resultwhile the latter will overflow.


In addition to the operations listed above, [`timedelta`](../_static/pydoctheme_dark.css "previous chapter") objects supportcertain additions and subtractions with [`date`](../_static/py.svg "previous chapter") and [`datetime`](../_static/py.svg "previous chapter")objects (see below).


Changed in version 3.2: Floor division and true division of a [`timedelta`](../_static/py.svg "previous chapter") object by another`timedelta`
object are now supported, as are remainder operations andthe [`divmod()`](../_static/py.svg "previous chapter") function. True division and multiplication of a`timedelta`
object by a [`float`](../_static/py.svg "previous chapter") object are now supported.

[`timedelta`](../_static/py.svg "previous chapter") objects support equality and order comparisons.

In Boolean contexts, a [`timedelta`](../_static/py.svg "previous chapter") object isconsidered to be true if and only if it isn’t equal to
`timedelta(0)`.

Instance methods:

Notes:

1. *date2* is moved forward in time if `timedelta.days > 0`, or backward if`timedelta.days < 0`. ## `datetime` objects[¶](../_static/opensearch.xml "Search within Python 3.14.7 documentation")

A [`datetime`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object is a single object containing all the informationfrom a [`date`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object and a [`time`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object.

Like a [`date`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object, [`datetime`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") assumes the current Gregoriancalendar extended in both directions; like a [`time`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object,`datetime` 
assumes there are exactly 3600\*24 seconds in every day.

Constructor:
*class *datetime.datetime(*year*, *month*, *day*, *hour=0*, *minute=0*, *second=0*, 
*microsecond=0*, *tzinfo=None*, *\**, *fold=0*)[¶](../_static/py.svg "previous chapter")
The *year*, *month* and *day* arguments are required. *tzinfo* may be `None`, or aninstance 
of a [`tzinfo`](../_static/py.svg "previous chapter") subclass. The remaining arguments must be integersin the following ranges:

- `MINYEAR <= year <= MAXYEAR`,
- `1 <= month <= 12`,
- `1 <= day <= number of days in the given month and year`,
- `0 <= hour < 24`,
- `0 <= minute < 60`,
- `0 <= second < 60`,
- `0 <= microsecond < 1000000`,
- `fold in [0, 1]`.

If an argument outside those ranges is given, [`ValueError`](../_static/py.svg "previous chapter") is raised.


Changed in version 3.6: Added the *fold* parameter.

Other constructors, all class methods:
*classmethod *datetime.today()[¶](https://www.python.org/ "previous chapter")
Return the current local date and time, with [`tzinfo`](../contents.html "previous chapter") `None`.

Copy

This method is functionally equivalent to [`now()`](../contents.html "previous chapter"), but without a`tz`

*classmethod *datetime.now(*tz=None*)[¶](../contents.html "previous chapter")
Return the current local date and time.

If optional argument *tz* is `None`or not specified, this is like [`today()`](../contents.html "previous chapter"), but, if possible, supplies moreprecision than can be gotten from going through a [`time.time()`](../contents.html "previous chapter") timestamp(for example, this may be possible on platforms supplying the C`gettimeofday()`
function).

If *tz* is not `None`, it must be an instance of a [`tzinfo`](#aware-and-naive-objects "previous chapter") subclass,and the current date and time are converted to
*tz*’s time zone.

This function is preferred over [`today()`](#determining-if-an-object-is-aware-or-naive "previous chapter") and [`utcnow()`](#timedelta-objects "previous chapter").


Note

Subsequent calls to `datetime.now()` may return the sameinstant depending on the precision of the
underlying clock.
*classmethod *datetime.utcnow()[¶](#examples-of-usage-datetime "previous chapter")
Return the current UTC date and time, with [`tzinfo`](#time-objects "previous chapter") `None`.

`datetime.now(timezone.utc)`. See also `now()`.


Warning

Because naive `datetime` objects are treated by many `datetime` methodsas local times, it is preferred
to use aware datetimes to represent timesin UTC. As such, the recommended way to
create an object representing thecurrent time in UTC is by calling `datetime.now(timezone.utc)`.

```(dt - datetime(1970, 1, 1, tzinfo=timezone.utc)).total_seconds()```


Note

supplying`tzinfo=timezone.utc`:

Copy

```timestamp = dt.replace(tzinfo=timezone.utc).timestamp()```

or by calculating the timestamp directly:

Copy

```timestamp = (dt - datetime(1970, 1, 1)) / timedelta(seconds=1)```

- `'milliseconds'`: Include full time, but truncate fractional secondpart to milliseconds. `HH:MM:SS.sss` format.

## `time` objects[¶](../_static/py.svg "previous chapter")

A [`time`](../_static/py.svg "previous chapter") object represents a (local) time of day, independent of any particularday, and subject to adjustment via a [`tzinfo`](../_static/py.svg "previous chapter") object.
*class *datetime.time(*hour=0*, *minute=0*, *second=0*, *microsecond=0*, *tzinfo=None*,
*\**, *fold=0*)[¶](../_static/py.svg "previous chapter")
All arguments are optional. *tzinfo* may be `None`, or an instance of a[`tzinfo`](https://www.python.org/ "previous chapter") subclass. The remaining arguments must be integers in thefollowing ranges:

- `0 <= hour < 24`,
- `0 <= minute < 60`,
- `0 <= second < 60`,
- `0 <= microsecond < 1000000`,
- `fold in [0, 1]`.

If an argument outside those ranges is given, [`ValueError`](../contents.html "previous chapter") is raised. Alldefault to 0 except
*tzinfo*, which defaults to `None`.

Class attributes:
time.min[¶](../contents.html "previous chapter")
The earliest representable [`time`](../contents.html "previous chapter"), `time(0, 0, 0, 0)`.
time.max[¶](../contents.html "previous chapter")
The latest representable [`time`](../contents.html "previous chapter"), `time(23, 59, 59, 999999)`.
time.resolution[¶](../contents.html "previous chapter")
The smallest possible difference between non-equal [`time`](../contents.html "previous chapter")
objects,`timedelta(microseconds=1)`, although note that arithmetic on`time` objects
is not supported.

Instance attributes (read-only):
time.hour[¶](#common-properties "previous chapter")
In `range(24)`.
time.minute[¶](#date-objects "previous chapter")
In `range(60)`.
time.second[¶](#datetime-objects "previous chapter")
In `range(60)`.
time.microsecond[¶](#time-objects "previous chapter")
In `range(1000000)`.
time.tzinfo[¶](#timezone-objects "previous chapter")
The object passed as the tzinfo argument to the [`time`](#timezone-objects "previous chapter") constructor, or`None`
if none was passed.
time.fold[¶](#technical-detail "previous chapter")
In `[0, 1]`. Used to disambiguate wall times during a repeated interval. (Arepeated interval
occurs when clocks are rolled back at the end of daylight savingtime or when the
UTC offset for the current zone is decreased for political reasons.)The values 0
and 1 represent, respectively, the earlier and later of the twomoments with the same
wall time representation.


Added in version 3.6.

[`time`](? "meta[property="og:title"]") objects support equality and order comparisons,where `a`
is considered less than `b` when `a` precedes `b` in time.

Naive and aware `time` objects are never equal.Order comparison between naive and aware
`time` objects raises[`TypeError`](https://docs.python.org/3/improve-page.html?pagetitle=datetime+%E2%80%94+Basic+date+and+time+types&pageurl=https%3A%2F%2Fdocs.python.org%2F3%2Flibrary%2Fdatetime.html&pagesource=library%2Fdatetime.rst ">Improve this page</a></li>
<li>
<a href=").

If both comparands are aware, and have the same [`tzinfo`](https://github.com/python/cpython/blob/main/Doc/library/datetime.rst?plain=1 "General Index")attribute, the `tzinfo`
and `fold` attributes areignored and the base times are compared. If both comparands
are aware andhave different `tzinfo` attributes, the comparands are first adjusted bysubtracting
their UTC offsets (obtained from `self.utcoffset()`).


Changed in version 3.3: Equality comparisons between aware and naive [`time`](https://www.python.org/ "Link to this heading") instancesdon’t raise [`TypeError`](../index.html "Link to this heading").

In Boolean contexts, a [`time`](../index.html "Link to this heading") object is always considered to be true.

## `tzinfo` objects[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
*class *datetime.tzinfo[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
This is an [abstract base class](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), meaning that this class should not beinstantiated directly.  Define a subclass of `tzinfo`
to captureinformation about a particular time zone.

An instance of (a concrete subclass of) `tzinfo` can be passed to theconstructors for [`datetime`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") and [`time`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") objects. The latter objectsview their attributes as being in local time, and the `tzinfo`
objectsupports methods revealing offset of local time from UTC, the name of the timezone,
and DST offset, all relative to a date or time object passed to them.

You need to derive a concrete subclass, and (at least)supply implementations of the
standard `tzinfo` methods needed by the[`datetime`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") methods you use. The `datetime`
module provides[`timezone`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), a simple concrete subclass of `tzinfo`
which canrepresent time zones with fixed offset from UTC such as UTC itself or NorthAmerican
EST and EDT.

Special requirement for pickling:  A `tzinfo` subclass must have an[`__init__()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method that can be called with no arguments,otherwise it can bepickled but possibly not unpickled again. This is a technical requirement thatmay be relaxed in the future.

A concrete subclass of `tzinfo` may need to implement the followingmethods. Exactly which
methods are needed depends on the uses made of aware`datetime` objects. If in doubt, simply
implement all of them.
tzinfo.utcoffset(*dt*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Return offset of local time from UTC, as a [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object that ispositive east of UTC. If local time is west of UTC, this should be negative.

This represents the *total* offset from UTC; for example, if a[`tzinfo`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object represents both time zone and DST adjustments,`utcoffset()`
should return their sum. If the UTC offset isn’t known,return `None`. Else the value
returned must be a [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") objectstrictly between `-timedelta(hours=24)`
and `timedelta(hours=24)`(the magnitude of the offset must be less than one day). Most implementationsof
`utcoffset()` will probably look like one of these two:

Copy

```return CONSTANT                 # fixed-offset classreturn CONSTANT + self.dst(dt) 
 # daylight-aware class```

If `utcoffset()` does not return `None`, [`dst()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") should not return`None` 
either.

The default implementation of `utcoffset()` raises[`NotImplementedError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation").


Changed in version 3.7: The UTC offset is not restricted to a whole number of minutes.
tzinfo.dst(*dt*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Return the daylight saving time (DST) adjustment, as a [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")object or`None` 
if DST information isn’t known.

Return `timedelta(0)` if DST is not in effect.If DST is in effect, return the offset as a [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") object(see [`utcoffset()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") for details). Note that DST offset, if applicable, hasalready been added to the UTC offset returned by
`utcoffset()`, so there’sno need to consult `dst()` unless you’re interested in obtaining 
DST infoseparately. For example, [`datetime.timetuple()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") calls its [`tzinfo`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")attribute’s `dst()` 
method to determine how the [`tm_isdst`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") flagshould be set, and [`tzinfo.fromutc()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") calls `dst()` 
to account forDST changes when crossing time zones.

An instance *tz* of a [`tzinfo`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") subclass that models both standard anddaylight times must be consistent in this sense:

`tz.utcoffset(dt) - tz.dst(dt)`

must return the same result for every [`datetime`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
*dt* with `dt.tzinfo ==
tz`. For sane `tzinfo` subclasses, this expression yields the timezone’s “standard 
offset”, which should not depend on the date or the time, butonly on geographic 
location. The implementation of [`datetime.astimezone()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")relies on this, but cannot detect violations; it’s the programmer’sresponsibility to ensure it. If a `tzinfo` 
subclass cannot guaranteethis, it may be able to override the default implementation 
of[`tzinfo.fromutc()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") to work correctly with `astimezone()` 
regardless.

Most implementations of `dst()` will probably look like one of these two:

Copy

```import datetime as dtdef dst(self, when):    # a fixed-offset class:  doesn't
account for DST    return dt.timedelta(0)```

or:

Copy

```import datetime as dtdef dst(self, when):    # Code to set dston and dstoff to 
the time zone's DST    # transition times based on the input when.year, and expressed 
   # in standard local time.    if dston <= when.replace(tzinfo=None) < dstoff:

The default implementation of `dst()` raises [`NotImplementedError`](../_static/opensearch.xml "Search within Python 3.14.7 documentation").


Changed in version 3.7: The DST offset is not restricted to a whole number of minutes.
tzinfo.tzname(*dt*)[¶](../_static/opensearch.xml "Search within Python 3.14.7 documentation")
Return the time zone name corresponding to the [`datetime`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object
*dt*, asa string. Nothing about string names is defined by the `datetime` module,and there’s 
no requirement that it mean anything in particular. For example,`"GMT"`, `"UTC"`, `"-500"`, `"-5:00"`, `"EDT"`, 
`"US/Eastern"`, `"America/New York"` are allvalid replies. Return `None` if a string name isn’t known. Note that 
this isa method rather than a fixed string primarily because some [`tzinfo`](../_static/opensearch.xml "Search within Python 3.14.7 documentation")subclasses will wish to return different names depending on the specific valueof
*dt* passed, especially if the `tzinfo` class is accounting fordaylight time.

The default implementation of `tzname()` raises [`NotImplementedError`](../_static/opensearch.xml "Search within Python 3.14.7 documentation").

These methods are called by a [`datetime`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") or [`time`](../_static/opensearch.xml "Search within Python 3.14.7 documentation") object, inresponse to their methods of the same names. A `datetime` 
object passesitself as the argument, and a `time` object passes `None` as theargument. A 
[`tzinfo`](https://docs.python.org/3/library/datetime.html "previous chapter") subclass’s methods should therefore be prepared toaccept a
*dt* argument of `None`, or of class `datetime`.

When `None` is passed, it’s up to the class designer to decide the bestresponse. For 
example, returning `None` is appropriate if the class wishes tosay that time objects 
don’t participate in the [`tzinfo`](../_static/py.svg "previous chapter") protocols. Itmay be more useful for `utcoffset(None)` 
to return the standard UTC offset, asthere is no other convention for discovering 
the standard offset.

When a [`datetime`](../_static/py.svg "previous chapter") object is passed in response to a `datetime`method, 
`dt.tzinfo` is the same object as *self*. [`tzinfo`](../_static/py.svg "previous chapter") methods canrely on this, unless user code calls `tzinfo` 
methods directly. Theintent is that the `tzinfo` methods interpret *dt* as being in localtime, 
and not need worry about objects in other time zones.

There is one more [`tzinfo`](../_static/py.svg "previous chapter") method that a subclass may wish to override:
tzinfo.fromutc(*dt*)[¶](../_static/py.svg "previous chapter")
This is called from the default [`datetime.astimezone()`](../_static/py.svg "previous chapter")implementation. When called from that, `dt.tzinfo` 
is *self*, and *dt*’sdate and time data are to be viewed as expressing a UTC time. 
The purposeof `fromutc()` is to adjust the date and time data, returning anequivalent datetime 
in *self*’s local time.

Most [`tzinfo`](../_static/py.svg "previous chapter") subclasses should be able to inherit the default`fromutc()` 
implementation without problems. It’s strong enough to handlefixed-offset time 
zones, and time zones accounting for both standard anddaylight time, and the latter 
even if the DST transition times differ indifferent years. An example of a time zone 
the default `fromutc()`implementation may not handle correctly in all cases is one where the 
standardoffset (from UTC) depends on the specific date and time passed, which can 
happenfor political reasons. The default implementations of [`astimezone()`](https://www.python.org/ "previous chapter") and`fromutc()` 
may not produce the result you want if the result is one of thehours straddling the 
moment the standard offset changes.

Skipping code for error cases, the default `fromutc()` implementation actslike:

Copy

```import datetime as dtdef fromutc(self, when):    # raise ValueError error if when.tzinfo

When DST starts (the “start” line), the local wall clock leaps from 1:59 to3:00.
A wall time of the form 2:MM doesn’t really make sense on that day, so`astimezone(Eastern)` won’t
deliver a result with `hour == 2` on the day DSTbegins. For example, at the Spring forward

## `timezone` objects[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

The [`timezone`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") class is a subclass of [`tzinfo`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), eachinstance of which represents a time zone defined by a fixed offset fromUTC.

Objects of this class cannot be used to represent time zone information in thelocations
where different offsets are used in different days of the year orwhere historical
changes have been made to civil time.
*class *datetime.timezone(*offset*, *name=None*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
The *offset* argument must be specified as a [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")object representing the difference between the local time and UTC. It mustbe strictly between `-timedelta(hours=24)`
and`timedelta(hours=24)`, otherwise [`ValueError`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") is raised.

The *name* argument is optional. If specified it must be a string thatwill be used
as the value returned by the [`datetime.tzname()`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") method.


Added in version 3.2.


Changed in version 3.7: The UTC offset is not restricted to a whole number of minutes.
timezone.utcoffset(*dt*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Return the fixed value specified when the [`timezone`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") instance isconstructed.

The *dt* argument is ignored. The return value is a [`timedelta`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")instance equal to the difference between the local time and UTC.


Changed in version 3.7: The UTC offset is not restricted to a whole number of minutes.
timezone.tzname(*dt*)[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")
Return the fixed value specified when the [`timezone`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") instanceis constructed.

If *name* is not provided in the constructor, the name returned by`tzname(dt)` is generated
from the value of the `offset` as follows. If*offset* is `timedelta(0)`, the name is “UTC”, otherwise
it is a string inthe format `UTC±HH:MM`, where ± is the sign of `offset`, HH and MM aretwo digits
of `offset.hours` and `offset.minutes` respectively.


Changed in version 3.6: Name generated from `offset=timedelta(0)` is now plain `'UTC'`, not`'UTC+00:00'`.

## `strftime()` and `strptime()` behavior[¶](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation")

[`date`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), [`datetime`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation"), and [`time`](../_static/pygments_dark.css?v=0fc419ee "Search within Python 3.14.7 documentation") objects all support a`strftime(format)`
method, to create a string representing the time under thecontrol of an explicit
format string.

### Technical detail[¶](../contents.html "previous chapter")

Broadly speaking, `d.strftime(fmt)` acts like the [`time`](../contents.html "previous chapter") module’s`time.strftime(fmt, d.timetuple())` 
although not all objects support a[`timetuple()`](../contents.html "previous chapter") method.

For the [`datetime.strptime()`](# "previous chapter") and [`date.strptime()`](#aware-and-naive-objects "previous chapter") class methods,the default value is
`1900-01-01T00:00:00.000`: any components not specifiedin the format string will 
be pulled from the default value.


Note

Format strings without separators can be ambiguous for parsing. Forexample, with 
`%Y%m%d`, the string `2026111` may be parsed either as`2026-11-01` or as `2026-01-11`.Use separators to ensure the 
input is parsed as intended.


Note

When used to parse partial dates lacking a year, [`datetime.strptime()`](#datetime-objects "previous chapter")and [`date.strptime()`](#examples-of-usage-datetime "previous chapter") will raise when encountering February 29 becausethe default year of 1900 is
*not* a leap year.  Always add a default leapyear to partial date strings before 
parsing.

Copy

```>>> import datetime as dt>>> value = "2/29">>>
dt.datetime.strptime(value, "%m/%d")Traceback (most recent call last):...ValueError:
day 29 must be in range 1..28 for month 2 in year 1900>>> dt.datetime.strptime(f"1904
{value}", "%Y %m/%d")datetime.datetime(1904, 2, 29, 0, 0)```

Using `datetime.strptime(date_string, format)` is equivalent to:

Copy

```datetime(\*(time.strptime(date_string, format)[0:6]))```

except when the format includes sub-second components or time zone offsetinformation, 
which are supported in `datetime.strptime` but are discarded by`time.strptime`.

For [`time`](https://github.com/python/cpython/blob/main/Doc/library/datetime.rst?plain=1 "General Index") objects, the format codes for year, month, and day should notbe used, as `time` 
objects have no such values. If they’re used anyway,1900 is substituted for the 
year, and 1 for the month and day.

For [`date`](../py-modindex.html "Python Module Index") objects, the format codes for hours, minutes, seconds, andmicroseconds should not be used, as `date` 
objects have no suchvalues. If they’re used anyway, 0 is substituted for them.

For the same reason, handling of format strings containing Unicode code pointsthat 
can’t be represented in the charset of the current locale is alsoplatform-dependent. 
On some platforms such code points are preserved intact inthe output, while on others 
`strftime` may raise [`UnicodeError`](../index.html "Link to this heading") or returnan empty string instead.

Notes:

1. Because the format depends on the current locale, care should be taken whenmaking assumptions about the output value. Field orderings will vary (forexample, “month/day/year” versus “day/month/year”), and the output maycontain non-ASCII characters.
2. The [`strptime()`](../index.html "Link to this heading") method can parse years in the full [1, 9999] range, butyears < 1000 must be zero-filled to 4-digit width.

Changed in version 3.2: In previous versions, [`strftime()`](../index.html "Link to this heading") method was restricted toyears >= 1900.

Changed in version 3.3: In version 3.2, [`strftime()`](../_static/pygments.css?v=b86133f3 "viewport") method was restricted toyears >= 1000.
3. When used with the [`strptime()`](../_static/pygments.css?v=b86133f3 "viewport") method, the `%p` directive only affectsthe output hour field if the `%I` directive is used to parse the hour.
4. Unlike the [`time`](../_static/pygments.css?v=b86133f3 "viewport") module, the `datetime` module does not supportleap seconds.
5. When used with the [`strptime()`](../_static/pygments.css?v=b86133f3 "viewport") method, the `%f` directiveaccepts from one to six digits and zero pads on the right. `%f` isan extension to the set of format characters in the C standard (butimplemented separately in datetime objects, and therefore alwaysavailable).
6. For a naive object, the `%z`, `%:z` and `%Z` format codes are replacedby empty strings.

	For an aware object:
`%z`[`utcoffset()`](../_static/classic.css?v=234b1a7c "highlight-") is transformed into a string of the form`±HHMM[SS[.ffffff]]`, where `HH` is a 2-digit string giving the numberof UTC offset hours, `MM` is a 2-digit string giving the number of UTCoffset minutes, `SS` is a 2-digit string giving the number of UTC offsetseconds and `ffffff` is a 6-digit string giving the number of UTCoffset microseconds. The `ffffff` part is omitted when the offset is awhole number of seconds and both the `ffffff` and the `SS` part isomitted when the offset is a whole number of minutes. For example, if`utcoffset()` returns `timedelta(hours=-3, minutes=-30)`, `%z` isreplaced with the string `'-0330'`.

Changed in version 3.7: The UTC offset is not restricted to a whole number of minutes.

Changed in version 3.7: When the `%z` directive is provided to the  [`strptime()`](../_static/classic.css?v=234b1a7c "highlight-") method,the UTC offsets can have a colon as a separator between hours, minutesand seconds.For example, `'+01:00:00'` will be parsed as an offset of one hour.In addition, providing `'Z'` is identical to `'+00:00'`.
`%:z`Behaves exactly as `%z`, but has a colon separator added betweenhours, minutes and seconds.
`%Z`In [`strftime()`](../_static/classic.css?v=234b1a7c "highlight-"), `%Z` is replaced by an empty string if[`tzname()`](../_static/classic.css?v=234b1a7c "highlight-") returns `None`; otherwise `%Z` is replaced by thereturned value, which must be a string.

	[`strptime()`](../_static/classic.css?v=234b1a7c "highlight-") only accepts certain values for `%Z`:

1. any value in `time.tzname` for your machine’s locale
2. the hard-coded values `UTC` and `GMT`

So someone living in Japan may have `JST`, `UTC`, and `GMT` asvalid values, but probably not `EST`. It will raise `ValueError` forinvalid values.

Changed in version 3.2: When the `%z` directive is provided to the [`strptime()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") method, anaware [`datetime`](../_static/pydoctheme.css?v=4365c8fe "highlight-") object will be produced. The `tzinfo` of theresult will be set to a [`timezone`](../_static/pydoctheme.css?v=4365c8fe "highlight-") instance.
- When used with the [`strptime()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") method, `%U` and `%W` are only usedin calculations when the day of the week and the calendar year (`%Y`)are specified.
- Similar to `%U` and `%W`, `%V` is only used in calculations when theday of the week and the ISO year (`%G`) are specified in a[`strptime()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") format string. Also note that `%G` and `%Y` are notinterchangeable.
- When used with the [`strptime()`](../_static/pydoctheme.css?v=4365c8fe "highlight-") method, the leading zero is optionalfor  formats `%d`, `%m`, `%H`, `%I`, `%M`, `%S`, `%j`, `%U`,`%W`, and `%V`. Format `%y` does require a leading zero.
- When parsing a month and day using [`strptime()`](../_static/pydoctheme.css?v=4365c8fe "highlight-"), alwaysinclude a year in the format.  If the value you need to parse lacks a year,append an explicit dummy leap year.  Otherwise your code will raise anexception when it encounters leap day because the default year used by theparser (1900) is not a leap year.  Users run into that bug every leap year.

Copy		>>> month_day = "02/29">>> dt.datetime.strptime(f"{month_day};1984", "%m/%d;%Y")  # No leap year bug.datetime.datetime(1984, 2, 29, 0, 0)

Deprecated since version 3.13, will be removed in version 3.15: [`strptime()`](../_static/pydoctheme.css?v=4365c8fe "stylesheet") calls using a format string containinga day of month without a year now emit a[`DeprecationWarning`](../_static/pydoctheme.css?v=4365c8fe "stylesheet"). In 3.15 or later we may change this intoan error or change the default year to a leap year. See [gh-70647](../_static/pydoctheme.css?v=4365c8fe "stylesheet").
