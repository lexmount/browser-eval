            <h1>HTML images</h1>
             <section class="content-section">
    
    <ul class="prev-next"><li class="prev"><a class="button secondary" href="/en-US/docs/Learn_web_development/Core/Structuring_content/Structuring_a_page_of_content"><span class="button-wrap"> Previous </span></a></li><li class="menu"><a class="button secondary" href="/en-US/docs/Learn_web_development/Core/Structuring_content"><span class="button-wrap"> Overview: Structuring content with HTML</span></a></li><li class="next"><a class="button secondary" href="/en-US/docs/Learn_web_development/Core/Structuring_content/Test_your_skills/Images"><span class="button-wrap"> Next  </span></a></li></ul>

            <section class="content-section" aria-labelledby="how_do_we_put_an_image_on_a_webpage">
    <!--lit-part jGku9COoaiE=--><!--lit-node 0--><h2 id="how_do_we_put_an_image_on_a_webpage" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#how_do_we_put_an_image_on_a_webpage">How do we put an image on a webpage?</a></h2><!--/lit-part-->
    <p>In order to put an image on a web page, we use the <a href="/en-US/docs/Web/HTML/Reference/Elements/img"><code>&lt;img&gt;</code></a> element. This is a <a href="/en-US/docs/Glossary/Void_element">void element</a> (meaning, it cannot have any child content and cannot have an end tag) that requires two attributes to be useful: <code>src</code> and <code>alt</code>. The <code>src</code> attribute contains a URL pointing to the image you want to embed in the page. As with the <code>href</code> attribute for <a href="/en-US/docs/Web/HTML/Reference/Elements/a"><code>&lt;a&gt;</code></a> elements, the <code>src</code> attribute can be a relative URL or an absolute URL. Without a <code>src</code> attribute, an <code>img</code> element has no image to load.</p>
<p>The <a href="#alternative_text"><code>alt</code> attribute is described below</a>.</p>
<div class="notecard note">
<p><strong>Note:</strong>
You should read <a href="/en-US/docs/Learn_web_development/Core/Structuring_content/Creating_links#a_quick_primer_on_urls_and_paths">A quick primer on URLs and paths</a> to refresh your memory on relative and absolute URLs before continuing.</p>
</div>
<p>So for example, if your image is called <code>dinosaur.jpg</code>, and it sits in the same directory as your HTML page, you could embed the image like so:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;img src="dinosaur.jpg" alt="Dinosaur" /&gt;
</code></pre></div>
<p>If the image was in an <code>images</code> subdirectory, which was inside the same directory as the HTML page, then you'd embed it like this:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;img src="images/dinosaur.jpg" alt="Dinosaur" /&gt;
</code></pre></div>
<p>And so on.</p>
<div class="notecard note">
<p><strong>Note:</strong>
Search engines also read image filenames and count them towards SEO. Therefore, you should give your image a descriptive filename; <code>dinosaur.jpg</code> is better than <code>img835.png</code>.</p>
</div>
<p>You could also embed the image using its absolute URL, for example:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;img src="https://www.example.com/images/dinosaur.jpg" alt="Dinosaur" /&gt;
</code></pre></div>
<p>Linking via absolute URLs is not recommended, however. You should host the images you want to use on your site, which in simple setups means keeping the images for your website on the same server as your HTML. In addition, it is more efficient to use relative URLs than absolute URLs in terms of maintenance (when you move your site to a different domain, you won't need to update all your URLs to include the new domain). In more advanced setups, you might use a <a href="/en-US/docs/Glossary/CDN">CDN (Content Delivery Network)</a> to deliver your images.</p>
<p>If you did not create the images, you should make sure you have the permission to use them under the conditions of the license they are published under (see <a href="#media_assets_and_licensing">Media assets and licensing</a> below for more information).</p>
<div class="notecard warning">
<p><strong>Warning:</strong>
<em>Never</em> point the <code>src</code> attribute at an image hosted on someone else's website <em>without permission</em>. This is called "hotlinking". It is considered unethical, since someone else would be paying the bandwidth costs for delivering the image when someone visits your page. It also leaves you with no control over the image being removed or replaced with something embarrassing.</p>
</div>
<p>The previous code snippet, either with the absolute or the relative URL, will give us the following result:</p>
<p><img src="/en-US/docs/Learn_web_development/Core/Structuring_content/HTML_images/basic-image.png" alt="A basic image of a dinosaur, embedded in a browser, with &quot;Images in HTML&quot; written above it" width="700" height="700" loading="lazy"></p>
<div class="notecard note">
<p><strong>Note:</strong>
Elements like <a href="/en-US/docs/Web/HTML/Reference/Elements/img"><code>&lt;img&gt;</code></a> and <a href="/en-US/docs/Web/HTML/Reference/Elements/video"><code>&lt;video&gt;</code></a> are sometimes referred to as <strong>replaced elements</strong>. This is because the element's content and size are defined by an external resource (like an image or video file), not by the contents of the element itself. You can read more about them at <a href="/en-US/docs/Glossary/Replaced_elements">replaced elements</a>.</p>
</div>
  </section><section class="content-section" aria-labelledby="alternative_text">
    <!--lit-part xPN3Z5WgUlo=--><!--lit-node 0--><h3 id="alternative_text" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#alternative_text">Alternative text</a></h3><!--/lit-part-->
    <p>The next attribute we'll look at is <code>alt</code>. Its value is supposed to be a textual description of the image, for use in situations where the image cannot be seen/displayed or takes a long time to render because of a slow internet connection. For example, our above code could be modified like so:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;img
  src="images/dinosaur.jpg"
  alt="The head and torso of a dinosaur skeleton;
          it has a large head with long sharp teeth" /&gt;
</code></pre></div>
<p>The easiest way to test your <code>alt</code> text is to purposely misspell your filename. If for example our image name was spelled <code>dinosooooor.jpg</code>, the browser wouldn't display the image, and would display the alt text instead:</p>
<p><img src="/en-US/docs/Learn_web_development/Core/Structuring_content/HTML_images/alt-text.png" alt="The Images in HTML title, but this time the dinosaur image is not displayed, and alt text is in its place." width="700" height="700" loading="lazy"></p>
<p>So, why would you ever see or need alt text? It can come in handy for a number of reasons:</p>
<ul>
<li>The user is visually impaired, and is using a <a href="https://en.wikipedia.org/wiki/Screen_reader" class="external" target="_blank" title="External link (opens in new tab)">screen reader</a> to read the web out to them. In fact, having alt text available to describe images is useful to most users.</li>
<li>As described above, the spelling of the file or path name might be wrong.</li>
<li>The browser doesn't support the image type. Some people still use text-only browsers, such as <a href="https://en.wikipedia.org/wiki/Lynx_%28web_browser%29" class="external" target="_blank" title="External link (opens in new tab)">Lynx</a>, which displays the alt text of images.</li>
<li>You may want to provide text for search engines to utilize; for example, search engines can match alt text with search queries.</li>
<li>Users have turned off images to reduce data transfer volume and distractions. This is especially common on mobile phones, and in countries where bandwidth is limited or expensive.</li>
</ul>
<p>What exactly should you write inside your <code>alt</code> attribute? It depends on <em>why</em> the image is there in the first place. In other words, what you lose if your image doesn't show up:</p>
<ul>
<li><strong>Decoration.</strong> You should use <a href="#css_background_images">CSS background images</a> for decorative images, but if you must use HTML, add a blank <code>alt=""</code>. If the image isn't part of the content, a screen reader shouldn't waste time reading it.</li>
<li><strong>Content.</strong> If your image provides significant information, provide the same information in a <em>brief</em> <code>alt</code> text – or even better, in the main text which everybody can see. Don't write redundant <code>alt</code> text. How annoying would it be for a sighted user if all paragraphs were written twice in the main content? If the image is described adequately by the main text body, you can just use <code>alt=""</code>.</li>
<li><strong>Link.</strong> If you put an image inside <a href="/en-US/docs/Web/HTML/Reference/Elements/a"><code>&lt;a&gt;</code></a> tags, to turn an image into a link, you still must provide <a href="/en-US/docs/Learn_web_development/Core/Structuring_content/Creating_links#use_clear_link_wording">accessible link text</a>. In such cases you may, either, write it inside the same <code>&lt;a&gt;</code> element, or inside the image's <code>alt</code> attribute – whichever works best in your case.</li>
<li><strong>Text.</strong> You should not put your text into images. If your main heading needs a drop shadow, for example, <a href="/en-US/docs/Web/CSS/Reference/Properties/text-shadow">use CSS</a> for that rather than putting the text into an image. However, if you <em>really can't avoid doing this</em>, you should supply the text inside the <code>alt</code> attribute.</li>
</ul>
<p>Essentially, the key is to deliver a usable experience, even when the images can't be seen. This ensures all users are not missing any of the content. Try turning off images in your browser and see how things look. You'll soon realize how helpful alt text is if the image cannot be seen.</p>
<div class="notecard note">
<p><strong>Note:</strong>
See our guide to <a href="/en-US/docs/Learn_web_development/Core/Accessibility/HTML#text_alternatives">Text Alternatives</a> and <a href="https://www.w3.org/WAI/tutorials/images/decision-tree/" class="external" target="_blank" title="External link (opens in new tab)">An alt Decision Tree</a> to learn how to use an <code>alt</code> attribute for images in various situations.</p>
</div>

    <!--lit-part tUBJ5CSlfNI=--><!--lit-node 0--><h3 id="width_and_height" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#width_and_height">Width and height</a></h3><!--/lit-part-->
    <p>You can use the <a href="/en-US/docs/Web/HTML/Reference/Elements/img#width"><code>width</code></a> and <a href="/en-US/docs/Web/HTML/Reference/Elements/img#height"><code>height</code></a> attributes to specify the width and height of your image. They are given as integers without a unit, and represent the image's width and height in pixels.</p>
<p>You can find your image's width and height in a number of ways. For example, on the Mac you can use <kbd>Cmd</kbd> + <kbd>I</kbd> to get the display information for the image file. Returning to our example, we could do this:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;img
  src="images/dinosaur.jpg"
  alt="The head and torso of a dinosaur skeleton;
          it has a large head with long sharp teeth"
  width="400"
  height="341" /&gt;
</code></pre></div>
<p>There's a very good reason to do this. The HTML for your page and the image are separate resources, fetched by the browser as separate HTTP(S) requests. As soon as the browser has received the HTML, it will start to display it to the user. If the images haven't yet been received (and this will often be the case, as image file sizes are often much larger than HTML files), then the browser will render only the HTML, and will update the page with the image as soon as it is received.</p>
<p>For example, suppose we have some text after the image:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;h1&gt;Images in HTML&lt;/h1&gt;

&lt;img
  src="dinosaur.jpg"
  alt="The head and torso of a dinosaur skeleton; it has a large head with long sharp teeth"
  title="A T-Rex on display in the Manchester University Museum" /&gt;
&lt;blockquote&gt;
  &lt;p&gt;
    But down there it would be dark now, and not the lovely lighted aquarium she
    imagined it to be during the daylight hours, eddying with schools of tiny,
    delicate animals floating and dancing slowly to their own serene currents
    and creating the look of a living painting. That was wrong, in any case. The
    ocean was different from an aquarium, which was an artificial environment.
    The ocean was a world. And a world is not art. Dorothy thought about the
    living things that moved in that world: large, ruthless and hungry. Like us
    up here.
  &lt;/p&gt;
  &lt;footer&gt;- Rachel Ingalls, &lt;cite&gt;Mrs. Caliban&lt;/cite&gt;&lt;/footer&gt;
&lt;/blockquote&gt;
</code></pre></div>
<p>As soon as the browser downloads the HTML, the browser will start to display the page.</p>
<p>Once the image is loaded, the browser adds the image to the page. Because the image takes up space, the browser has to move the text down the page, to fit the image above it:</p>
<p><img src="/en-US/docs/Learn_web_development/Core/Structuring_content/HTML_images/no-size.png" alt="Comparison of page layout while the browser is loading a page and when it has finished, when no size is specified for the image." width="1844" height="1314" loading="lazy"></p>
<p>Moving the text like this is extremely distracting to users, especially if they have already started to read it, and it also causes the browser to re-render the page, which is bad for performance.</p>
<p>If you specify the actual size of the image in your HTML using the <code>width</code> and <code>height</code> attributes, then the browser knows how much space to allow for the image, before it has downloaded.</p>
<p>This means that when the image has been downloaded, the browser doesn't have to move the surrounding content.</p>
<p><img src="/en-US/docs/Learn_web_development/Core/Structuring_content/HTML_images/size.png" alt="Comparison of page layout while the browser is loading a page and when it has finished, when the image size is specified." width="1842" height="1315" loading="lazy"></p>
<p>For an excellent article on the history of this feature, see <a href="https://www.smashingmagazine.com/2020/03/setting-height-width-images-important-again/" class="external" target="_blank" title="External link (opens in new tab)">Setting height and width on images is important again</a>.</p>
<p>Note that if there's no content below the image, re-rendering isn't a problem because resizing the image won't cause other elements to shift. In that case, you can set the image's <code>width</code> only. If you set a <code>width</code> but don't set a <code>height</code>, the <code>height</code> defaults to <code>auto</code> which means it is set to a value that maintains the image's <a href="/en-US/docs/Glossary/Aspect_ratio">aspect ratio</a>.</p>
<h4 id="resizing_images">Resizing images</h4>
<p>Although, as we have said, it is good practice to specify the <em>actual</em> size of your images using HTML attributes, you should not use them to <em>resize</em> images.</p>
<p>If you set the image size too big, you'll end up with images that look grainy, fuzzy, or too small, and wasting bandwidth downloading an image that is not fitting the user's needs. The image may also end up looking distorted, if you don't maintain the correct <a href="/en-US/docs/Glossary/Aspect_ratio">aspect ratio</a>. You should use an image editor to put your image at the correct size before putting it on your webpage.</p>
<p>If you do need to alter an image's size, you should use <a href="/en-US/docs/Learn_web_development/Core/Styling_basics">CSS</a> instead.</p>

    <!--lit-part EsiYJaPyZCM=--><!--lit-node 0--><h2 id="media_assets_and_licensing" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#media_assets_and_licensing">Media assets and licensing</a></h2><!--/lit-part-->
    <p>Images (and other media asset types) you find on the web are released under various license types. Before you use an image on a site you are building, ensure you own it, have permission to use it, or comply with the owner's licensing conditions.</p>
  </section><section class="content-section" aria-labelledby="understanding_license_types">
    <!--lit-part /H1znutQuyI=--><!--lit-node 0--><h3 id="understanding_license_types" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#understanding_license_types">Understanding license types</a></h3><!--/lit-part-->
    <p>Let's look at some common categories of licenses you are likely to find on the web.</p>
<h4 id="all_rights_reserved">All rights reserved</h4>
<p>Creators of original work such as songs, books, or software often release their work under closed copyright protection. This means that, by default, they (or their publisher) have exclusive rights to use (for example, display or distribute) their work. If you want to use copyrighted images with an <em>all rights reserved</em> license, you need to do one of the following:</p>
<ul>
<li>Obtain explicit, written permission from the copyright holder.</li>
<li>Pay a license fee to use them. This can be a one-time fee for unlimited use ("royalty-free"), or it might be "rights-managed", in which case you might have to pay specific fees per use by time slot, geographic region, industry or media type, etc.</li>
<li>Limit your uses to those that would be considered <a href="https://fairuse.stanford.edu/overview/fair-use/what-is-fair-use/" class="external" target="_blank" title="External link (opens in new tab)">fair use</a> or <a href="https://copyrightservice.co.uk/copyright/p27_work_of_others" class="external" target="_blank" title="External link (opens in new tab)">fair dealing</a> in your jurisdiction.</li>
</ul>
<p>Authors are not required to include a copyright notice or license terms with their work. Copyright exists automatically in an original work of authorship once it is created in a tangible medium. So if you find an image online and there are no copyright notices or license terms, the safest course is to assume it is protected by copyright with all rights reserved.</p>
<h4 id="permissive">Permissive</h4>
<p>If the image is released under a permissive license, such as <a href="https://mit-license.org/" class="external" target="_blank" title="External link (opens in new tab)">MIT</a>, <a href="https://opensource.org/license/BSD-3-clause" class="external" target="_blank" title="External link (opens in new tab)">BSD</a>, or a suitable <a href="https://creativecommons.org/chooser/" class="external" target="_blank" title="External link (opens in new tab)">Creative Commons (CC) license</a>, you do not need to pay a license fee or seek permission to use it. Still, there are various licensing conditions you will have to fulfill, which vary by license.</p>
<p>For example, you might have to:</p>
<ul>
<li>Provide a link to the original source of the image and credit its creator.</li>
<li>Indicate whether any changes were made to it.</li>
<li>Share any derivative works created using the image under the same license as the original.</li>
<li>Not share any derivative works at all.</li>
<li>Not use the image in any commercial work.</li>
<li>Include a copy of the license along with any release that uses the image.</li>
</ul>
<p>You should consult the applicable license for the specific terms you will need to follow.</p>
<div class="notecard note">
<p><strong>Note:</strong>
You may come across the term "copyleft" in the context of permissive licenses. Copyleft licenses (such as the <a href="https://www.gnu.org/licenses/gpl-3.0.en.html" class="external" target="_blank" title="External link (opens in new tab)">GNU General Public License (GPL)</a> or "Share Alike" Creative Commons licenses) stipulate that derivative works need to be released under the same license as the original.</p>
</div>
<p>Copyleft licenses are prominent in the software world. The basic idea is that a new project built with the code of a copyleft-licensed project (this is known as a "fork" of the original software) will also need to be licensed under the same copyleft license. This ensures that the source code of the new project will also be made available for others to study and modify. Note that, in general, licenses that were drafted for software, such as the GPL, are not considered to be good licenses for non-software works as they were not drafted with non-software works in mind.</p>
<p>Explore the links provided earlier in this section to read about the different license types and the kinds of conditions they specify.</p>
<h4 id="public_domaincc0">Public domain/CC0</h4>
<p>Work released into the public domain is sometimes referred to as "no rights reserved" — no copyright applies to it, and it can be used without permission and without having to fulfill any licensing conditions. Work can end up in the public domain by various means such as expiration of copyright, or specific waiving of rights.</p>
<p>One of the most effective ways to place work in the public domain is to license it under <a href="https://wiki.creativecommons.org/wiki/CC0" class="external" target="_blank" title="External link (opens in new tab)">CC0</a>, a specific creative commons license that provides a clear and unambiguous legal tool for this purpose.</p>
<p>When using public domain images, obtain proof that the image is in the public domain and keep the proof for your records. For example, take a screenshot of the original source with the licensing status clearly displayed, and consider adding a page to your website with a list of the images acquired along with their license requirements.</p>
  </section><section class="content-section" aria-labelledby="searching_for_permissively-licensed_images">
    <!--lit-part kGw5sWx5suk=--><!--lit-node 0--><h3 id="searching_for_permissively-licensed_images" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#searching_for_permissively-licensed_images">Searching for permissively-licensed images</a></h3><!--/lit-part-->
    <p>You can find permissive-licensed images for your projects using an image search engine or directly from image repositories.</p>
<p>Search for images using a description of the image you are seeking along with relevant licensing terms. For example, when searching for "yellow dinosaur" add "public domain images", "public domain image library", "open licensed images", or similar terms to the search query.</p>
<p>Some search engines have tools to help you find images with permissive licenses. For example, when using Google, go to the "Images" tab to search for images, then click "Tools". There is a "Usage Rights" dropdown in the resulting toolbar where you can choose to search specifically for images under creative commons licenses.</p>
<p>Image repository sites, such as <a href="https://flickr.com/" class="external" target="_blank" title="External link (opens in new tab)">Flickr</a>, <a href="https://www.shutterstock.com/" class="external" target="_blank" title="External link (opens in new tab)">ShutterStock</a>, and <a href="https://pixabay.com/" class="external" target="_blank" title="External link (opens in new tab)">Pixabay</a>, have search options to allow you to search just for permissively-licensed images. Some sites exclusively distribute permissively-licensed images and icons, such as <a href="https://picryl.com/" class="external" target="_blank" title="External link (opens in new tab)">Picryl</a> and <a href="https://thenounproject.com/" class="external" target="_blank" title="External link (opens in new tab)">The Noun Project</a>.</p>
<p>Complying with the license the image has been released under is a matter of finding the license details, reading the license or instruction page provided by the source, and then following those instructions. Reputable image repositories make their license conditions clear and easy to find.</p>
  </section><section class="content-section" aria-labelledby="annotating_images_with_figures_and_figure_captions">
    <!--lit-part Yl4oLV0vMqs=--><!--lit-node 0--><h2 id="annotating_images_with_figures_and_figure_captions" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#annotating_images_with_figures_and_figure_captions">Annotating images with figures and figure captions</a></h2><!--/lit-part-->
    <p>Speaking of captions, there are a number of ways that you could add a caption to go with your image. For example, there would be nothing to stop you from doing this:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;div class="figure"&gt;
  &lt;img
    src="images/dinosaur.jpg"
    alt="The head and torso of a dinosaur skeleton;
            it has a large head with long sharp teeth"
    width="400"
    height="341" /&gt;

  &lt;p&gt;A T-Rex on display in the Manchester University Museum.&lt;/p&gt;
&lt;/div&gt;
</code></pre></div>
<p>This is OK. It contains the content you need, and is nicely stylable using CSS. But there is a problem here: there is nothing that semantically links the image to its caption, which can cause problems for screen readers. For example, when you have 50 images and captions, which caption goes with which image?</p>
<p>A better solution, is to use the HTML <a href="/en-US/docs/Web/HTML/Reference/Elements/figure"><code>&lt;figure&gt;</code></a> and <a href="/en-US/docs/Web/HTML/Reference/Elements/figcaption"><code>&lt;figcaption&gt;</code></a> elements. These are created for exactly this purpose: to provide a semantic container for figures, and to clearly link the figure to the caption. Our above example could be rewritten like this:</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html notranslate"><code>&lt;figure&gt;
  &lt;img
    src="images/dinosaur.jpg"
    alt="The head and torso of a dinosaur skeleton;
            it has a large head with long sharp teeth"
    width="400"
    height="341" /&gt;

  &lt;figcaption&gt;
    A T-Rex on display in the Manchester University Museum.
  &lt;/figcaption&gt;
&lt;/figure&gt;
</code></pre></div>
<p>The <a href="/en-US/docs/Web/HTML/Reference/Elements/figcaption"><code>&lt;figcaption&gt;</code></a> element tells browsers, and assistive technology that the caption describes the other content of the <a href="/en-US/docs/Web/HTML/Reference/Elements/figure"><code>&lt;figure&gt;</code></a> element.</p>
<div class="notecard note">
<p><strong>Note:</strong>
From an accessibility viewpoint, captions and <a href="/en-US/docs/Web/HTML/Reference/Elements/img#alt"><code>alt</code></a> text have distinct roles. Captions benefit even people who can see the image, whereas <a href="/en-US/docs/Web/HTML/Reference/Elements/img#alt"><code>alt</code></a> text provides the same functionality as an absent image. Therefore, captions and <code>alt</code> text shouldn't just say the same thing, because they both appear when the image is gone. Try turning images off in your browser and see how it looks.</p>
</div>
<p>A figure doesn't have to be an image. It is an independent unit of content that:</p>
<ul>
<li>Expresses your meaning in a compact, easy-to-grasp way.</li>
<li>Could go in several places in the page's linear flow.</li>
<li>Provides essential information supporting the main text.</li>
</ul>
<p>A figure could be several images, a code snippet, audio, video, equations, a table, or something else.</p>
  </section><section class="content-section" aria-labelledby="creating_a_figure">
    <!--lit-part PdfKVDSfZFg=--><!--lit-node 0--><h3 id="creating_a_figure" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#creating_a_figure">Creating a figure</a></h3><!--/lit-part-->

</ol>
<p>If you make a mistake, you can clear your work using the <em>Reset</em> button in the MDN Playground. If you get really stuck, you can view the solution below the code block.</p>
<div class="code-example"><div class="example-header"><span class="language-name">html</span></div><pre class="brush: html live-sample___images-2 notranslate live-sample---images-2"><code>&lt;img
  src="dinosaur_small.jpg"
  alt="The head and torso of a dinosaur skeleton; it has a large head with long sharp teeth"

  height="171"

  </section><section class="content-section" aria-labelledby="css_background_images">
    <!--lit-part do65sQyyr/4=--><!--lit-node 0--><h2 id="css_background_images" class="heading"><!--lit-node 1--><a class="heading-anchor" href="#css_background_images">CSS background images</a></h2><!--/lit-part-->
    <p>You can also use CSS to embed images into webpages (and JavaScript, but that's another story entirely). The CSS <a href="/en-US/docs/Web/CSS/Reference/Properties/background-image"><code>background-image</code></a> property, and the other <code>background-*</code> properties, are used to control background image placement. For example, to place a background image on every paragraph on a page, you could do this:</p>
<div class="code-example"><div class="example-header"><span class="language-name">css</span></div><pre class="brush: css notranslate"><code>p {
  background-image: url("images/dinosaur.jpg");
}
</code></pre></div>
<p>The resulting embedded image is arguably easier to position and control than HTML images. So why bother with HTML images? As hinted above, CSS background images are for decoration only. If you just want to add something pretty to your page to enhance the visuals, this is fine. However, such images have no semantic meaning at all. They can't have any text equivalents, are invisible to screen readers, and so on. This is where HTML images shine!</p>
<p>Summing up: if an image has meaning, in terms of your content, you should use an HTML image. If an image is purely decoration, you should use CSS background images (we'll cover these in detail later in the Core modules).</p>
