| [.gitmodules](https://github.com/denoland/deno/blob/main/.gitmodules ".gitmodules") | [.gitmodules](https://github.com/denoland/deno/blob/main/.gitmodules ".gitmodules") | [perf: lazy-load OSX frameworks with](https://github.com/denoland/deno/commit/80bc12f9e1a899d7d37373fa7ecab9e9b7d566d2 "perf: lazy-load OSX frameworks with `lzld` (#35341)  ## Why  On `aarch64-apple-darwin`, the deno binary links 8 system frameworks — CoreFoundation, Foundation, Security, CoreServices, Metal, QuartzCore, CoreGraphics, MetalPerformanceShaders — but only touches them in rarely-hit paths (`fs.watch`/FSEvents, keychain, WebGPU). Even with the existing `-weak_framework` linkage, **dyld loads + initializes them at process launch** (weak only makes missing symbols non-fatal; the dylib is still loaded). That's pure startup cost paid on every `deno run`.  `dyld_info -imports` shows deno imports only ~47 symbols from these frameworks; QuartzCore/CoreGraphics/MPS import **zero**.  ## What  [lzld](https://github.com/littledivy/lzld) is a thin `ld64.lld` wrapper that strips `-framework`/`-weak_framework` and links `liblzld` instead — a static shim that provides exactly the symbols deno imports, each `dlopen`-ing its framework on **first use**. Frameworks a given run never touches are never loaded.  - Added as a git submodule at `tools/lzld`. - **CI builds the macOS aarch64 release binary through lzld by default** (`.github/workflows/ci.ts`): the release step inits the submodule, builds `liblzld`, and patches the linker before `cargo build --release`. Guarded to Darwin/arm64; other matrix entries skip it. - Opt-in build helper `tools/build_lzld.sh` for local use; the default `cargo build` is unchanged. - `.cargo/config.toml` is left untouched: `-fuse-ld` requires an *absolute* linker path (Apple clang rejects relative ones), computed at build time by both CI and the helper.  ## `otool -L` — frameworks gone from the load commands  **Before (shipping main):** 11 load commands, 8 frameworks loaded at launch ``` $ otool -L $(which deno) 	/System/Library/Frameworks/Security.framework/.../Security 	/System/Library/Frameworks/CoreFoundation.framework/.../CoreFoundation 	/usr/lib/libobjc.A.dylib 	/System/Library/Frameworks/CoreServices.framework/.../CoreServices 	/usr/lib/libSystem.B.dylib 	/System/Library/Frameworks/QuartzCore.framework/.../QuartzCore (weak) 	/System/Library/Frameworks/Metal.framework/.../Metal (weak) 	/System/Library/Frameworks/Foundation.framework/.../Foundation 	/usr/lib/libiconv.2.dylib 	/System/Library/Frameworks/MetalPerformanceShaders.framework/.../MetalPerformanceShaders (weak) 	/System/Library/Frameworks/CoreGraphics.framework/.../CoreGraphics (weak) ```  **After (lzld build):** 3 load commands, 0 frameworks ``` $ otool -L target/release/deno 	/usr/lib/libSystem.B.dylib 	/usr/lib/libobjc.A.dylib 	/usr/lib/libiconv.2.dylib $ otool -l target/release/deno | grep -iE 'Metal|CoreFoundation|Foundation|Security|QuartzCore|CoreServices|CoreGraphics'   (none) ```  ## Results  aarch64-macOS (Apple M4 Max, macOS 15.6), warm, lzld vs. stock main. [Deno](https://deno.com/)
( [/ˈdiːnoʊ/](https://ipa-reader.com/?text=%CB%88di%CB%90no%CA%8A), pronounced
`dee-no`) is a JavaScript, TypeScript, and WebAssembly runtime with secure
defaults and a great developer experience. It's built on [V8](https://v8.dev/),
[Rust](https://www.rust-lang.org/), and [Tokio](https://tokio.rs/).

Learn more about the Deno runtime
[in the documentation](https://docs.deno.com/runtime/manual).

## Installation

[Permalink: Installation](https://github.com/denoland/deno#installation)

Install the Deno runtime on your system using one of the commands below. Note
that there are a number of ways to install Deno - a comprehensive list of
installation options can be found
[here](https://docs.deno.com/runtime/manual/getting_started/installation).

Shell (Mac, Linux):

```
curl -fsSL https://deno.land/install.sh | sh
```

PowerShell (Windows):

```
irm https://deno.land/install.ps1 | iex
```

[Homebrew](https://formulae.brew.sh/formula/deno) (Mac):

```
brew install deno
```

[Chocolatey](https://community.chocolatey.org/packages/deno) (Windows):

```
choco install deno
```

[WinGet](https://winstall.app/apps/DenoLand.Deno) (Windows):

```
winget install --id=DenoLand.Deno
```

[Scoop](https://scoop.sh/#/apps?q=deno&id=678d8fb557b611df996989c675b1099630a5bbee)
(Windows):

```
scoop install main/deno
```

## Your first Deno program

[Permalink: Your first Deno program](https://github.com/denoland/deno#your-first-deno-program)

Deno can be used for many different applications, but is most commonly used to
build web servers. Create a file called `server.ts` and include the following
TypeScript code:

```
Deno.serve((_req: Request) => {
  return new Response("Hello, world!");
});
```

Run your server with the following command:

```
deno run --allow-net server.ts
```

This should start a local web server on
[http://localhost:8000](http://localhost:8000/).

Learn more about writing and running Deno programs
[in the docs](https://docs.deno.com/runtime/manual).
