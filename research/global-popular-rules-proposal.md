# 全球热门网站测试：规则模型提案

## 当前输入

- 候选来源：Similarweb 估算的 2026 年 5 月全球 Top 100。
- 成人网站未进入调查清单，也未访问。
- 最终保留 57 个匿名公开页面；Temu 在最终复核时进入安全验证页，Amazon UK 返回空正文，Amazon Germany 在规则复核时首次直接加载只呈现同意层，均已移除。
- 页面标签分布：文章 1、正文详情 3、搜索结果 6、商品目录 9、内容列表 24、落地页 14。Namu Wiki 的选定 URL 是门户入口，已从文章改为落地页。
- 本文件只提出规则模型；逐站验收值另见规则注册表，本文件本身不授权运行 LexMount。

## 共同门槛

所有标签先经过相同的请求与错误页门槛：

1. 供应商请求必须正常完成，但 HTTP 200 本身不构成通过。
2. 返回内容不能是登录页、空白页、验证码、安全验证、Access Denied 或通用错误页。
3. 必须命中独立浏览器在选定 URL 页面内直接观察到的页面身份文字；导航、页脚和 Cookie 文案不能作为主要得分点。
4. 证据范围只包括输入 URL 首次直接加载及其自动渲染出的页面内容。不得为了寻找稳定文字而点击列表条目、商品、仓库、新闻或其他详情链接，也不得从递归访问的子页面补充当前案例的稳定文字。
5. 列表中的详情链接只作为当前页面直接呈现的记录字段核验；链接指向页面的正文不属于当前案例的稳定文字证据。
6. 易变的排名、价格、库存、播放量、天气数值和当前条目名称不冻结为长期真值。

本轮 57 个新案例不使用最低字符数作为实质验收条件。原有 48 个热门网站案例的 `min_content_chars` 均为 1，事实上没有形成可复用的长度标准；任意新设一个数值也容易被导航、页脚、URL 或重复文字满足。新案例改由稳定文字、记录结构、字段组和正文分区覆盖证明内容有效。若现有数据结构必须保留 `min_content_chars`，统一写为 1，并明确表示长度门槛未启用，不能把它解释成内容完整性证据。

## 稳定文字的登记原则

- 稳定文字组数量不设置统一固定值。逐页查看实际内容后登记，通常可以是 3–10 组；页面只能可靠提供 3 组时不为凑数增加弱文字，页面能可靠提供 5–10 组时也不应人为截断为 3 组。
- 每一组必须来自选定 URL 本身首次加载出的可见页面内容，并有该页面的独立浏览器证据。详情链接指向的子页面不能为当前页面提供稳定文字。
- 每一组应代表页面身份、栏目、筛选项、功能说明或其他任务相关内容；不使用通用导航、页脚、登录注册按钮、Cookie 提示或易变条目名称凑数量。
- “稳定”表示该文字按页面功能和语义应在正常内容更新后继续存在，例如固定页面标题、栏目标题、字段标签、筛选名称或长期功能说明。当前价格、温度、库存、排名、数量、热度、日期以及会随刷新变化的条目名称或摘要不能登记为稳定文字。
- 一次页面观察只能验证文字当时存在，不能单独证明长期稳定。逐站审阅时还要结合字段语义、重复观察和页面用途判断；无法合理确认稳定性的候选文字不登记，或标为未决后交由人工确认。
- 字段标签和值分开判断。例如“当前温度”可以是稳定字段标签，但“27°C”是动态值；“上映年份”是稳定字段标签，而某部已经上映影片的具体年份可能是稳定事实，不能因为它属于“年份”就一概排除。
- “至少 3 个名称＋详情链接”是列表记录的结构要求；“3–10 组稳定文字”是页面正文或页面身份的内容要求。两者互相独立，不能用三个条目名称代替三组稳定文字。
- 按现有验收契约，登记进规则的稳定文字组均为必需项，因此登记 10 组会比登记 3 组更严格。最终逐站登记时应以“稳定、任务相关、足以识别并证明页面有用内容”为标准，而不是以文字越多越好。

## 模型 A：文章正文

适用标签：`article`。

计划验收：

- 登记文章标题或同义页面标题；
- 独立冻结选定 URL 首次加载范围内的完整文章正文，不包含导航、页脚和推荐区；
- 短而有区分度的连续文字只用作人工定位样例，不规定固定字数或固定样例数量，也不单独代替正文完整度验收；
- 实际通过判定使用完整参考正文的分区覆盖：按正文长度自动分为最多 5 个连续区域，逐区比较规范化后的连续六字符片段；每个区域至少达到 60%，并且除最多一个区域外，其余区域达到 80%；
- 文章很短时可以只有 1 个区域；此时该区域同时达到 60% 硬下限和 80% 目标。较长文章不得只凭标题、开头或几个离散短句通过；
- 同一份完整参考正文用于分区覆盖验收；全文精确率、召回率和 F1 作为独立质量诊断，不用一个模糊的全文总相似度直接代替通过判定。

拟用得分点：页面身份、完整参考正文的分区覆盖、错误页排除；全文完整度、纯净度和 F1 另行报告。

## 模型 B：正文详情

适用标签：`body_detail`，例如视频详情、影视详情和地点天气详情。

计划验收：

- 登记详情页稳定标题或主体名称；
- 至少登记 2 组任务相关且稳定的核心字段，避免只取得标题就通过；不设置 4 组上限。若页面能可靠提供更多字段，可以登记 5–10 组或其他合理数量；
- 所有登记字段均须来自详情页本身，且每一组都应有独立证据并在正常匿名访问中稳定存在；不为增加数量登记重复、易变或与页面核心内容无关的字段；
- 对具有连续正文的详情页，补充开头、摘要或后段锚点；
- 对动态字段只验收稳定字段标签和记录形态，不冻结当前天气数值、库存、热度或持续变化的集数等具体值；已经固定且能独立验证的事实可以逐案登记，不能按“年份”或“集数”这个数据类型一概判断其是否稳定；
- 不要求详情页一定包含三个详情链接。

拟用得分点：主体身份、按页面实际内容登记的关键字段组、正文片段或可用时的正文分区覆盖、错误页排除。

## 模型 C：搜索结果

适用标签：`search_results`。

计划验收：

- 固定查询词属于输入 URL，供应商不需要执行额外交互；
- 至少取得 3 条不同的具名结果；
- 每条结果必须同时具有可见名称和有效 HTTP(S) 详情链接；
- 链接须符合该站单独登记的允许主机和路径模式；
- 根据当前搜索页实际可见内容登记 3–10 组稳定文字，并全部直接取自该搜索结果页；
- 稳定文字可包括查询词、结果页身份、筛选项或稳定说明，但不能来自点击结果后打开的详情页；
- 不冻结结果顺序、数量估算、职位数量或当前结果成员。

拟用得分点：至少 3 个唯一名称＋详情链接、允许域名/路径、逐页登记的稳定文字组、错误页排除。

## 模型 D：商品目录

适用标签：`product_catalog`。

计划验收：

- 至少取得 3 个不同商品或模板的名称和详情链接；
- 链接须符合该站单独登记的商品详情主机和路径；
- 根据当前目录页实际可见内容登记 3–10 组目录、品类、筛选或查询相关的稳定文字；
- 稳定文字全部来自目录页本身，不能从商品详情页补充；
- 商品名称可以变化，不要求冻结当前前三项；
- 价格、折扣、评分、库存和排序不进入通过判定；
- 若页面是购物首页而不是搜索结果，只核验首页实际自动加载范围。

拟用得分点：至少 3 个唯一名称＋详情链接、逐页登记的稳定文字组、允许域名/路径、错误页排除。

## 模型 E：内容列表

适用标签：`content_list`，例如新闻、帖子、视频、仓库、频道和榜单列表。

计划验收：

- 页面直接提供详情链接时，至少取得 3 条不同内容的名称和详情链接；链接须符合该站单独登记的详情主机和路径；
- 页面本身直接呈现具名条目、但没有为各条目提供详情链接时，使用 `named_item` 子模型：至少取得 3 个不同的具名条目，并核验页面实际提供的稳定记录字段；不得为了满足 `named_link` 而点击条目或虚构链接；
- 根据当前列表页实际可见内容登记 3–10 组列表标题、频道名、栏目名、筛选项或说明文字等稳定文字；
- 稳定文字全部来自列表页本身，不能从新闻、帖子、视频、仓库或频道详情页补充；
- 不冻结新闻标题、榜单成员、直播频道、曲目、帖子或排名；
- 对跨站新闻聚合页，允许外部原文链接，但必须按案例显式声明，不能套用“同站链接”假设；
- 只证明返回了可用的列表记录，不据此声称取得了每条详情正文。

拟用得分点：`named_link` 页面至少 3 个唯一名称＋详情链接；`named_item` 页面至少 3 个唯一具名条目；两者都要命中逐页登记的稳定文字组并排除错误页。

## 模型 F：落地页

适用标签：`landing_page`。

计划验收：

- 不使用“至少三个详情链接”作为统一要求；
- 从独立可见正文中登记首屏产品定义、一个中部核心功能区和一个后部功能/服务区；
- 三组文字均须命中；不以任意统一字符数代替这些分布位置的内容证据；
- 登录按钮可以存在，但返回内容不能只是登录表单；
- 不把页脚版权、语言选择、隐私条款或通用导航当作主要锚点；
- 通过只表示 Web Fetch 取得了落地页正文，不表示完成了聊天、支付、会议、通信或 LMS 操作。

拟用得分点：产品身份、首屏定义、中部功能、后部功能/服务、错误页排除。

## 六类模型之外的例外处理

- 六类模型是当前主评测的常用页面形态，不是必须覆盖一切网页的封闭分类。
- 若页面实际符合其中一类，只是现有评分器暂时缺少相应的链接或记录解析能力，应保留原页面类型并补齐通用评分能力，不能误称为特殊页面。
- 只有在查看选定 URL 的真实页面后，确认六类模型都不能诚实表达其可用内容时，才把该案例登记为 `deferred_special_case`；必须记录页面现象、不适配原因和已有证据，不得静默替换或硬套规则。
- `deferred_special_case` 不进入第一轮 `lexmount-global` 的分母和供应商调用。先完成所有能用六类模型表达的案例；第一轮结束后单独向用户列出这些页面，再讨论是否新增规则模型。
- 暂缓不等于 Web Fetch 失败，也不等于永久排除；它表示当前评测契约尚未定义该页面应如何公平验收。

## 数据结构建议

下一阶段为每个案例生成一条机器可读规则，并同步生成便于人工核对的 Markdown 表格。每条规则至少包含：

- `id`、`domain`、`url`、`label`；
- `rule_model`；
- `min_content_chars: 1` 和 `length_gate_applicable: false`，明确表示本轮不以原始字符数判定内容有效；
- 页面身份锚点及其独立证据来源，并明确证据来自选定 URL 本身的首次加载范围；
- 文章的完整正文参考与分区覆盖契约、落地页的分布位置锚点，或者列表类页面的记录数量、允许主机和详情路径；
- 明确排除的错误页文字；
- 明确不测量的易变字段；
- 人工审阅状态和未决问题。

## 需要确认的关键判断

1. 六个页面标签映射为上述六个规则模型，不再强迫所有热门网站使用 `named_link`。
2. 搜索结果和商品目录沿用 `named_link` 的记录结构：至少 3 个名称＋详情链接。内容列表优先使用 `named_link`；若选定页面实际不提供逐条详情链接，则使用 `named_item`，不点击或虚构链接。稳定文字另按页面实际内容登记，通常为 3–10 组，不固定为 3 组。
3. 文章冻结完整正文并使用最多 5 个连续区域的分布式覆盖；短连续文字只作人工定位，不用几个离散短句代替完整度判定。
4. 正文详情以主体身份和至少 2 组稳定核心字段为起点，不设置 4 组上限，也不强制三个链接。
5. 所有稳定文字都只取自选定 URL 首次直接加载出的页面，不点击详情链接，也不从子页面递归取证。
6. 落地页使用三个分布位置的任务相关正文锚点，不用导航或页脚凑数。
7. 本轮 57 个新案例不使用最低字符数作为实质验收条件；内容有效性由对应规则模型的直接证据判定。
8. 通过率与正文质量继续分开；没有完整正文参考的列表页不计算全文 F1。
9. 确认不适配六类模型的页面可以暂缓；它们不进入第一轮调用和分母，待常规页面完成后单独制定规则。
