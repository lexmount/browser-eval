通过更多网页的方法，未必交付更干净的正文

${rank_reversal} ${quality_figure}

正文通过要满足长度、指定内容和错误页等规则，不设 F1 门槛。F1 则按词频重合衡量全文：完整度看参考内容取回了多少，纯净度看输出有多少属于参考，F1 用调和平均综合二者。它比较的是文字重合，不是逐句语义。

${low_f1_case}

这个反例让排名逆转有了具体含义：允许更多非正文文字进入输出，可能更容易保住被抽查的关键点，却会拉低纯净度。对于需要长文检索的应用，额外导航和目录会占据检索候选或模型上下文；对于只需定位少量字段的应用，这些附带文字未必足以让结果不可用。该不该清理，取决于下游是否依赖整段内容。

参考选取也影响判断：有用的附录若不在参考范围内，同样会被计为额外文字。正文清理的目标应是改善实际阅读或检索，而不只是把 F1 提高。至于价格和商品是否对应，词频重合并不能回答，需要回到内容验收。

规则能识别已登记的价格错误，但如果输出保留这些核对点，却漏掉另一条未登记书目，仍可能通过；字符串出现也不能自动证明逐行归属正确。对商品采集应用，应按条目核验名称、价格、库存和详情链接的对应关系。${rules_link}提供完整匹配口径。

保留更多文字，也意味着保留更多负担

${cow_result} ${initial_audit}

当前核对到的网页提取函数先删除 script 和 style 内容，再删除 HTML 标签、整理空白。这条文本路线没有借助大模型理解页面，也不会因为网页里包含脚本就自动执行脚本。对已经出现在响应 HTML 中的正文，它可能足够；对藏在脚本或运行时响应中的内容，同样的操作就可能把所需信息留在文本之外。

${probe_figure}

同一次去标签操作，既保住了文字，也丢掉了地址。它能满足某些正文任务，却无法替下游决定哪些部分值得保留；文字要清理到什么程度、链接是否必须保留，应由交付目标决定。属性已经从输出中消失之后，再提高关键词匹配精度也找不回地址。

这与低纯净度的实测案例相符，但实验只验证合成输入上的当前提取函数。历史 CowAgent 记录没有逐次源码指纹，也没有把同一份历史响应字节交给多个提取算法做对照。因此，还不能把每次成功或失败都归因于这段函数，更不能量化“保留更多文字”贡献了多少通过率。

比再排一次名更有用的，是比较失败是否重叠

${overlap_analysis} ${rescue_mechanism}

后备方法能否发挥作用，取决于系统是否识别出了首方法的错误。生产环境通常没有每个新 URL 的完整参考，不能照搬这里的事后判分；页面身份、最低内容量和业务必需字段才是需要试验的触发条件。若判定器接受了一份看似充足的错误正文，后备方法即使有能力也不会被调用。

这使 CowAgent 作为技术文档基线、Moli 作为后备成为值得验证的组合。试验应在同一时间窗跑完整链路，记录错误触发、漏触发、后备结果和总耗时，而不能只重放已经知道会失败的案例。正文噪声还应单独验收，以免提高了交付覆盖，却降低了检索质量。

换成文件或媒体，交付边界先于方法排名

${media_case}

这也解释了为什么不能把正文选型直接用于文档与媒体交付。PDF、DOCX 的文字可用，不代表版式或原文件已保留；图片与视频入口可用，也不代表文件已经下载或画面已被理解。若下游需要地址，就应核验地址；若下游需要文件，就必须收到可核验的字节。纯文本输出是否更易读，无法代替这项检查。

原文件任务尤其需要区分缺测与产品失败。本轮共有 ${raw_file_records} 条记录，${raw_file_missing} 条没有写入 raw_file_pass，只有 ${raw_file_verified} 条形成已验证通过记录。缺失标记在当前判定中不算通过，但不能据此宣称参评产品不支持文件下载。要做有效比较，需要实际字节或受控附件证据，再验 MIME、字节数和 SHA-256。对于以文件为最终产物的业务，这条验收链路应先接通，正文榜单无法代替它。

复杂热门网站：多接几个方法，也有共同空白

复杂热门网站组中，单方法最好通过 ${challenge_best}/${challenge_cases}，所有方法成功集的离线并集也只有 ${challenge_union}/${challenge_cases}。仍无任何已验证通过记录的 ${challenge_missing_count} 个任务是：${challenge_unpassed}。这与网页正文组的互补现象形成对照：切换方法有机会补上独立失败，却无法从现有记录中补出共同缺失的交付。

这里的通过要求至少三个具名详情入口，且前三条名称与详情身份都有独立证据，不认证实时名次或价格。新条目缺少独立证据时，结果是未证实，不是认定编造；因此共同未通过还不能全部归为共同抓取失败。但它们确实是当前没有可验证交付的空白。

登录限制、地区差异和拦截页面可能就是目标业务的实际工作条件。把这些任务剔除会提高分数，却不会解决交付问题。与普通文档的后备试验相比，这些站点应先验证访问条件和条目身份核验，再决定是否增加接口。已有方法的成功集都没有覆盖它们时，单纯扩充后备列表还缺少实测依据。
