复现与附录

从零复现的执行步骤

  1. 准备 Linux + Docker Engine（cgroup v2）或使用 Linux VM 的 Docker Desktop/Colima；Python 3.11+；至少 4 CPU、6 GiB 可用内存和公网访问。
  2. 在仓库根目录执行 ./examples/browser_use/run.sh。
  3. 首次运行会构建两个固定基础镜像、下载 Moli 1.0.6、创建本地 Python 虚拟环境；不需要 LLM API Key、网站账号或登录状态。
  4. 运行结束后检查 artifacts/browser_use/latest/attempts.jsonl、manifest.json、summary.json。
  5. 打开 docs/reports/browser-use-evaluation-latest.html 阅读这组分页报告。
git clone https://github.com/lexmount/browser-harness-eval.git
cd browser-harness-eval
./examples/browser_use/run.sh

数据文件与可追溯性

输出文件
文件用途
attempts.jsonl每次任务执行的状态、耗时、资源采样摘要和错误；最原始的事实表。
manifest.json运行编号、任务集哈希、浏览器版本、镜像 ID、环境和协议。
summary.json由 attempts.jsonl 派生的 P50、平均值、P95、成功率、配对资源和漂移摘要。
docs/reports/*.html面向用户的中文分页报告；由 manifest 与 summary 生成。

边界与限制

  • 公开网站、CDN 和网络路径会变化；交替顺序与重复统计只能降低，不能消除外部波动。
  • 内存以 100 ms 采样，短于采样间隔的尖峰可能遗漏。
  • 每任务仅 5 次，任务级 P95 等于最大值，适合发现尾部异常，不适合精确估计长期 95 分位。
  • 本地 Docker 是可重复的计量边界，不是 CowAgent 生产部署必须使用 Docker 的建议。
  • Chromium 容器因 Debian Chromium 的 CDP 回环绑定包含一个轻量 TCP 转发器，其成本计入 Chromium，产生轻微上偏。
  • 本轮是浏览器动作层评测，没有调用 CowAgent/LLM；端到端 agent token、规划质量和重试成本需要单独评测。

CubeSandbox 的位置

CubeSandbox 官方支持在 MicroVM 内通过 CDP 运行 headless Chromium，可作为后续生产拓扑和硬件隔离评测后端。但其原生指标默认 5 秒采集、只保留最新样本，且文档未提供与本报告等价的每 sandbox 网络字节，因此不应与本轮 100 ms Docker cgroup 数据混合汇总。
