为什么本轮 Moli 看起来更快

当前结果与早期公网报告不能直接比较：本轮使用本机固定 fixture、暖浏览器、较短确定性调用链，并修正了早期执行器与 CowAgent get_text 不一致的问题。更重要的是，资源表只保留双方成功交集：Moli 未通过的 4 个复杂动态控件任务被排除，形成明显的成功交集选择偏差。

因此应表述为“在本轮 11 个双方成功任务上，Moli 的配对耗时比值 P50/mean/P95 如上”，不能表述为“Moli 对全部任务普遍更快”。每任务仅一次首次样本也不足以建立稳定的性能置信区间。

产品决策边界

  1. 默认 provider 先看结果首次正确率，再看组合正确率、重试恢复、时延和成本。
  2. 资源结论只来自双方首次结果正确交集，不能外推成所有网站上的固定倍数。
  3. 当前固定参考路径适合隔离 provider；自由规划 Agent 的过程评价必须改为里程碑和约束。
  4. LLM 诊断是可验证假设，不是成功 Oracle，也不替代最小复现。
