结论摘要

结论与产品建议

本轮建议默认使用 Chromium：其结果正确任务数为 30，高于 Moli 的 20；Moli 在双方均成功的任务上若表现出更低耗时或资源占用，可作为任务已验证兼容时的备选。

这是浏览器工具调用层的确定性微基准，不是 LLM Agent 排名。评测集包含 30 个结果唯一的任务；结果由程序逐字判定，LLM 不参与成功评分。

任务正确率

结果正确率是默认 Provider 的第一决策指标。“结果与过程均正确”额外要求参考路径完整且每次 BrowserTool 调用成功；首次与最终结果分开，避免重试掩盖首次失败。

关键技术结论

  • 正确性：Chromium 最终结果正确 30/30（100.00%），Moli 为 20/30（66.67%）。
  • 成功交集：资源只比较双方首次均成功的 20 个任务；Moli 未通过的 10 个任务不进入性能统计。
  • 速度与资源：成功交集上，Moli / Chromium 平均耗时聚合值之比为 0.56×，时间加权平均内存聚合值之比为 0.19×；网络接收量聚合值之比为 3.53×。
  • 时序边界：Moli 的 1 Hz 是 CDP screencast 下采样，不等于 JavaScript 或 requestAnimationFrame 只有 1 fps；源码中的 rAF 目标间隔为 16 ms。
  • 失败现象：多数失败现场表现为 DOM 已连接且 computed style 可见，但布局矩形为零；这能定位 actionability 异常，尚不能单独证明根因属于 screencast、渲染器或适配层。
  • 校准修正：场景隔离后，早期 label/details 失败消失，说明共享 fixture 干扰会制造假阳性，正式结论已排除该部分。

评测可信度与解读边界

  • Ground truth 已由 Codex Desktop in-app Browser Tool 按真实 BrowserTool 操作复核 30/30；人工复核状态为 pending，详细标注见“评测集”。
  • 所有数值均由 run.sh → metrics.py → summary.json → report.py 生成，Codex 不参与统计计算。
  • 失败任务、重试和任一方未通过的任务不进入资源基线，因此性能结论存在成功样本选择偏差。
  • 每个任务只有一个首次执行样本，当前结果不能外推为所有网站上的固定性能倍数。
