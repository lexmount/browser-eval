结论摘要

结论与产品建议

本轮建议默认使用 Chromium：其结果正确任务数为 30，高于 Moli 的 20；Moli 在双方均成功的任务上若表现出更低耗时或资源占用，可作为任务已验证兼容时的备选。

这是浏览器工具调用层的确定性微基准，不是 LLM Agent 排名。评测集包含 30 个结果唯一的任务，程序重放预先声明的有效参考路径；结果由程序逐字判定，LLM 不参与成功评分。每个任务先执行 1 次，仅结果失败时最多重试。

关键技术结论

  • 正确性：Chromium 为 30/30，Moli 为 20/30；默认 Provider 应先看正确率。
  • 成功交集：资源只比较双方首次均成功的 20 个任务；Moli 未通过的 10 个任务不进入性能统计。
  • 速度与资源：成功交集上，Moli / Chromium 耗时平均值为 0.58×，时间加权平均内存比值为 0.19×；网络接收量平均比值为 3.43×。
  • 时序边界：Moli 的 1 Hz 是 CDP screencast 下采样，不等于 JavaScript 或 requestAnimationFrame 只有 1 fps；源码中的 rAF 目标间隔为 16 ms。
  • 失败现象：多数失败现场表现为 DOM 已连接且 computed style 可见，但布局矩形为零；这能定位 actionability 异常，尚不能单独证明根因属于 screencast、渲染器或适配层。
  • 校准修正：场景隔离后，早期 label/details 失败消失，说明共享 fixture 干扰会制造假阳性，正式结论已排除该部分。

如何解读

  • 结果正确率是主指标；“结果与过程均正确率”单独报告，不与结果正确率混成一个数。
  • 耗时、内存、CPU、RX/TX 只比较双方首次结果均正确的同任务，重试与失败样本不进入资源基线。
  • 配对比值先对每个同任务计算 Moli / Chromium，再报告这 20 个比值的 P50、P95、平均值；小于 1 表示 Moli 数值更低，大于 1 表示 Chromium 数值更低。
  • 所有数值均由 run.sh → metrics.py → summary.json → report.py 一键生成；报告层只读取结构化结果并排版，Codex 不参与统计计算。
  • 本轮只有 20 个成功配对点，且 Moli 失败的 10 个任务被排除，速度结论存在成功样本选择偏差，不能外推为全任务更快。
  • 完整标准答案、实际输出、原始异常和逐调用执行轨迹均可审计。
