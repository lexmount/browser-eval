结论摘要

这次评测要回答什么

在浏览器保持启动、任务间清理站点状态、两种内核获得相同容器配额的前提下，比较 Chromium 与 Moli 的成功率、耗时、CPU、峰值内存、网络流量和工具输出量。冷启动不属于本报告。

核心结果

50/50Chromium 成功
44/50Moli 成功
44双方均成功的同任务同轮次配对
1.58×Moli / Chromium 耗时配对比值 P50
0.53×峰值内存配对比值 P50
1.00×工具输出量配对比值 P50

结论与产品建议

当前不应把 Moli 设为默认 browser provider。本轮 Moli 成功率为 88.00%，低于 Chromium 的 100.00%；在双方均成功的配对样本中，Moli 的峰值内存明显更低，但耗时、CPU 和容器网络流量未表现出总体优势。

更合适的产品定位是：Chromium 保持默认；Moli 作为偏重内存密度、需要先做工作负载验证的推荐选项。当关键任务成功率接近 Chromium 后，再讨论默认值切换。

Moli 失败涉及：读取 PyPI requests 当前版本、浏览 RFC 9110 并进入指定章节。这不是对所有网站和部署形态的普遍结论，只对本报告记录的版本、环境和 10 个公开任务成立。
