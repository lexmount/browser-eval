结论摘要

结论与产品建议

本轮建议默认使用 Chromium：其结果正确任务数为 30，高于 Moli 的 27；Moli 在双方均成功的任务上若表现出更低耗时或资源占用，可作为任务已验证兼容时的备选。

这是浏览器工具调用层的公网确定性微基准，不是 LLM Agent 排名。评测集包含 30 个结果唯一的任务；结果由程序逐字判定，LLM 不参与成功评分。

任务正确率

结果正确率是默认 Provider 的第一决策指标。“结果与参考过程均正确”额外要求参考路径完整且每次 BrowserTool 调用成功。重试只属于同一任务的内部执行证据，不单列为另一套任务指标。

关键技术结论

  • 正确性：Chromium 结果正确 30/30（100.00%），Moli 为 27/30（90.00%）。
  • 成功交集：资源只比较双方都成功的 27 个同任务；Moli 未通过的 3 个任务不进入性能统计。
  • 速度与资源：成功交集上先逐任务计算 Moli / Chromium，再汇总；耗时比平均值为 1.61×，时间加权平均内存比平均值为 0.42×，网络接收量比平均值为 2.26×。
  • 时序边界：Moli 的 1 Hz 是 CDP screencast 下采样，不等于 JavaScript 或 requestAnimationFrame 只有 1 fps；源码中的 rAF 目标间隔为 16 ms。
  • 失败解释边界：actionability 与布局证据可以定位现象，但不能单凭一次失败证明根因属于 screencast、渲染器或适配层；报告只陈述当前证据支持的层级。

评测可信度与解读边界

  • Ground truth 已由 Codex Desktop in-app Browser Tool 按真实 BrowserTool 操作复核 30/30；人工复核状态为 pending，详细标注见“评测集”。
  • 所有数值均由 run.sh → metrics.py → summary.json → report.py 生成，Codex 不参与统计计算。
  • 失败任务、重试和任一方未通过的任务不进入资源基线，因此性能结论存在成功样本选择偏差。
  • 每个任务只有一个正式结果样本，当前结果不能外推为所有网站上的固定性能倍数。
