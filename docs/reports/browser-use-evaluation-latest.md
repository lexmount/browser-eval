# Chromium 与 Moli 暖浏览器正式评测报告

运行编号：`1721a7fae735`

## 结论摘要

- Chromium：50/50（100.00%）。
- Moli：44/50（88.00%）。
- 双方均成功的配对样本：44。
- Moli / Chromium 配对比值 P50：耗时 1.58×，CPU 1.09×，峰值内存 0.53×，网络接收 1.96×，网络发送 2.75×，工具输出 token 1.00×。
- 决策：Chromium 保持默认；Moli 作为偏重内存密度、需要工作负载验证的可选 provider。

## 评测集介绍

1. **读取 Example Domain 标题**（2 步，1–5 步）：验证最短路径的页面打开与文本提取。
2. **读取 Hacker News 首条新闻**（3 步，1–5 步）：验证动态列表等待与首项文本提取。
3. **读取 PyPI requests 当前版本**（3 步，1–5 步）：验证包索引页加载、等待与标题提取。
4. **读取 Transformer 论文摘要**（3 步，1–5 步）：验证论文页长文本提取与内容断言。
5. **浏览 Python 维基条目**（6 步，6–10 步）：验证长页提取、滚动与视口快照。
6. **浏览 Moli GitHub README**（6 步，6–10 步）：验证动态代码托管页、长文本与滚动。
7. **从 MDN Fetch API 进入 Using Fetch**（8 步，6–10 步）：验证站内点击跳转和前后页面内容提取。
8. **浏览 Python 教程与历史记录**（11 步，11–15 步）：验证多步骤点击、后退、前进与页面恢复。
9. **浏览 RFC 9110 并进入指定章节**（13 步，11–15 步）：验证超长标准文档、锚点点击、滚动和历史恢复。
10. **跨四个公开来源收集 Python 信息**（16 步，16–20 步）：验证多站点连续导航和长链路稳定性。

## 评测环境与方法

- 浏览器进程和 context 全程保持启动，排除冷启动。
- 每任务前清除所有已访问来源的数据、Cookie、权限、HTTP 缓存与历史；只替换 page，并在计时外静置。
- 每个内核使用独立网络和相同容器配额；控制器不计入浏览器 CPU 与内存。
- 每任务重复 5 次并交替内核顺序。功能统计使用全部尝试，资源比较仅使用双方均成功的同任务同轮次。
- P50 就是中位数；同时报告平均值和 nearest-rank P95。单任务 n=5 时 P95 等于最大值。
- RX 是浏览器容器网络接收量，TX 是网络发送量；二者包含网页与 CDP 流量，不是纯网页资源大小。

## 评测结果

| 内核 | 成功/尝试 | 成功率 | 耗时 P50 ms | 平均 ms | P95 ms |
|---|---:|---:|---:|---:|---:|
| chromium | 50/50 | 100.00% | 1,288.03 | 2,078.69 | 6,443.80 |
| moli | 44/50 | 88.00% | 2,472.34 | 3,546.44 | 9,251.06 |

## 评测结果分析

- Moli 的峰值内存优势成立，但本轮不支持其总体更快、更省 CPU、更省网络或更省 token。
- Moli 的 5 次 RFC 9110 失败呈系统性，另有 1 次 PyPI 可见性失败；成功率尚不足以成为默认 provider。
- 任务间状态已清理但暖进程可保留分配内存；这不等同于缓存污染，也未观察到同量级持续耗时恶化。
