步骤的严格定义

一步 = 一次 CowAgent BrowserTool 等价调用，例如 navigate、click、get_text、fill、select、scroll、back 或 forward。等待页面就绪和定位器可用不是 Agent 的独立决策，不计步。每次调用的参数、耗时、输出和状态写入 trace。

模型与执行边界

  • 浏览器工具层（本报告主体）：不调用模型；按固定序列驱动浏览器，以隔离 provider 的成功率、耗时和资源成本。
  • CowAgent 端到端控制层：bot_type=openai、model=gpt-5.6-sol、reasoning_effort=low、open_ai_api_base=https://litellm.local.lexmount.net/v1。真实模型调用由 Lexmount LiteLLM API 执行，不是 Codex 代替 CowAgent。
  • 兼容性实测：LiteLLM 的 Azure 路由要求 allowed_openai_params=[reasoning_effort]；普通请求和带 function tool 请求均已验证 low 可用。
  • Codex：只开发、运行和检查工具，不是被测 Agent。

Agent 规划、重试、LLM token 和答案准确率必须在 CowAgent 端到端层单独统计，不能混入确定性浏览器微基准。

执行流程

  1. 分别启动并预热两个浏览器，浏览器与 context 全程不关闭。
  2. 任务前清 Cookie、权限、HTTP 缓存、Cache Storage、Service Worker、IndexedDB、来源存储和历史；替换 page。
  3. 计时外静置 1500 ms，按轮次交替先后顺序。
  4. 计时内执行完整工具调用并采样容器；最后验证输出。
  5. 功能统计保留全部尝试；资源只比较双方都成功的配对样本。

统计口径

  • P50 与中位数是同一个统计量；同时报告 mean 和 nearest-rank P95。
  • 每任务 n=3 时，任务级 P95 等于最大值，仅用于暴露尾部异常。
  • 内存 mean 是时间加权均值；任务内存 P95 先对单次时序样本求 P95，再跨任务汇总。
  • RX = Receive（接收），TX = Transmit（发送）；总量含网页资源与 CDP。速率 P95/峰值来自相邻采样点差分。
