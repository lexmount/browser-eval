步骤的严格定义

一步 = 一次 CowAgent BrowserTool 等价调用，例如 navigate、click、get_text、fill、select、scroll、back 或 forward。等待页面就绪和目标值出现属于该工具调用内部，不单列、不计步。每次调用的参数、耗时、输出和状态写入 trace。

成功判定：两个独立程序指标

  1. 结果正确（主指标）：每个标注输出与 expected_outputs 做严格字符串相等；不存在最低长度、模糊包含或 LLM 主观评分。
  2. 结果及过程均正确（辅指标）：在结果正确之外，本轮被重放的参考动作序列还必须与 expected_actions 一致，且全部 BrowserTool 调用成功。
  3. 重试合同：结果首次失败才重试，最多 1 次；结果首次通过率、恢复数、结果最终正确率和组合正确率分别统计。

边界：expected_actions 是工具层微基准的固定参考路径，不代表任务只有一种解法。若评测自由规划 CowAgent，应把过程 Oracle 改成必要里程碑、禁止动作和步数预算，不能要求整条序列逐步相等。

模型与执行边界

  • 浏览器工具层（本报告主体）：成功评分不调用模型；按固定参考路径驱动浏览器，以隔离 provider 的正确率、耗时和资源成本。
  • 失败诊断：规则引擎自动提取失败方法、步骤、selector 和错误类型；可选 gpt-5.6-sol（low）只生成可验证的根因假设，永不修改评分。
  • CowAgent 端到端控制层：bot_type=openai、model=gpt-5.6-sol、reasoning_effort=low，由 Lexmount LiteLLM API 执行，不是 Codex 代替 CowAgent。
  • Codex：只开发、运行和检查工具，不是被测 Agent，也不负责报告中的自动错误分类。

执行流程

  1. 分别启动并预热两个浏览器，browser/context 全程不关闭。
  2. 任务前清 Cookie、权限、HTTP 缓存、Cache Storage、Service Worker、IndexedDB、来源存储和历史；替换 page。
  3. 计时外静置 300 ms，按任务交替内核先后顺序。
  4. 执行一次完整任务并采样；仅结果失败时清理状态后重试。
  5. 资源基线只比较双方首次结果均正确的同任务，重试与失败样本不混入正常路径。

统计口径

  • P50 与中位数是同一个统计量；总体跨任务报告 P50、mean 和 nearest-rank P95。
  • 资源比较严格使用双方首次结果均正确的成功交集，实际样本数见结果页；失败任务完全排除。
  • 配对比值先逐任务计算 Moli / Chromium，再报告比值分布的 P50、mean、P95；这比只用两个总体 P50 相除更尊重配对关系。
  • 每个任务仅有一个首次样本，因此逐任务不计算分位数；当前跨任务点不足以证明普遍性能优势。
  • 内存 mean 是时间加权均值；任务内存 P95 来自单次任务时序采样。
  • RX = Receive（接收），TX = Transmit（发送）；总量含页面资源与 CDP，速率来自相邻采样点差分。
