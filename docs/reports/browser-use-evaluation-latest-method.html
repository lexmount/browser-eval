  • 每个内核使用独立容器和独立 Docker bridge，容器之间没有 peer；控制器在容器外，不计入浏览器 CPU 与内存。
  • 两个内核使用相同 CPU、内存、共享内存和 PID 上限；CDP 端口只发布到宿主机回环地址。
  • 任务轮次交替执行 Chromium→Moli 与 Moli→Chromium，降低网站/CDN 时段变化造成的顺序偏差。
评测方法介绍

一次完整执行如何发生

  1. 构建并记录固定版本的 Chromium 与 Moli 镜像，创建独立网络和等额资源配额。
  2. 启动浏览器并通过 CDP 连接；先访问 Example Domain 做一次不计时预热，排除浏览器冷启动。
  3. 每个任务开始前，清除已访问来源的 Cookie、权限、本地存储、IndexedDB、Cache Storage、Service Worker、HTTP 缓存和历史。
  4. 浏览器进程与 context 保持不关闭；仅关闭旧 page 并创建空白 page，执行渲染器 GC，再静置 1500 ms。清理与静置均不计时。
  5. 读取容器 CPU、网络累计计数器；启动每 100 ms 一次的内存/PID 采样与任务计时。
  6. 按任务文件执行打开、等待、提取、点击、滚动、后退、前进等动作，并逐条检查内容断言。
  7. 停止计时和采样，计算本任务的 CPU 与网络增量、峰值内存、输出字符折算 token；失败也计入成功率。
  8. 每任务重复 5 次。功能结果使用全部尝试；资源比较只使用“同任务、同轮次、双方都成功”的配对样本。

统计口径

统计量定义
指标含义为何保留
P50（中位数）一半样本不高于此值；P50 与中位数是同一个统计量。不易被单个极慢样本拉高，作为典型体验。
平均值（Mean）所有样本的算术平均。能反映慢样本对总体成本的实际拖累，但对异常值敏感。
P9595% 样本不高于此值，采用 nearest-rank。观察尾部体验；单任务仅 5 次时 P95 实际等于该组最大值，应谨慎解读。
成功率通过全部内容断言的次数 / 全部尝试次数。性能不能替代正确性；失败耗时不混入性能分布。

资源指标与 RX/TX 解释

指标定义
指标本报告中的定义
耗时从任务计时开始到动作与断言完成；不含启动、预热、状态清理和静置。
CPU浏览器容器 cgroup 累计 CPU 时间的任务前后差值。
峰值内存计时区间内浏览器容器 memory.current 的最高采样值。
网络接收量（RX）RX = Receive，浏览器容器从非回环网络接口收到的总字节。既包括网站响应资源，也包括从宿主机进入容器的 CDP 控制流量。
网络发送量（TX）TX = Transmit，浏览器容器从非回环网络接口发出的总字节。既包括发往网站的请求，也包括发往控制器的 CDP 响应与提取结果。
工具输出 token浏览器动作产生的结构化文本按本地确定性规则估算；本评测没有调用 LLM，因此不是模型真实计费 token。
PIDDocker cgroup 中的 Linux task/thread 数，不等同于只数操作系统进程。
网络数据的正确解读：RX/TX 是容器网络命名空间总流量，不是“网页资源大小”。因此 Moli TX 更高可能来自网页请求、CDP 协议输出或二者共同作用；本轮数据不能单独证明网站下载量更大。
