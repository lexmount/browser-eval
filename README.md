# Browser Service Eval

Reproducible evaluation of browser engines and services across public task
suites, functional correctness, latency, output size, CPU, memory, and network
traffic.

The first backend compares warm local Chromium and Moli in equal, isolated
Docker cgroups. It does not require Codex, another coding agent, an LLM API key,
website accounts, or login state.

## Run the browser evaluation

Requirements: Docker Engine (cgroup v2), `uv`, Python 3.11, at least 4 CPU
cores, 6 GiB available memory, and Internet access.

```bash
./examples/trajectory_replay/run.sh
```

The command builds pinned browser images, resolves the locked project
environment, runs the versioned 30-task deterministic suite, and writes:

- raw reproducibility artifacts to `artifacts/trajectory_replay/latest/` (ignored by Git)
- latest-only Markdown, HTML, and audit data to `docs/reports/` (ignored by Git)

All statistics and HTML are generated by repository scripts. To rebuild the
summary and report from an existing `attempts.jsonl` without rerunning the
browsers, use:

```bash
uv run --frozen python examples/trajectory_replay/rebuild_report.py
```

See [examples/trajectory_replay/README.md](examples/trajectory_replay/README.md) for the
measurement protocol, complexity tiers, overrides, and CubeSandbox decision.

## Harness layout

- `harness/trajectory_replay`: fixed-action trajectory-replay execution, metrics, and reports
- `harness/trajectory_replay/public_webarena`: public WebArena human-recording replay
- `harness/browser_use`: autonomous CowAgent execution with official WebArena-Verified scoring
- `harness/web_fetch`: Web Fetch providers, execution, scoring, and reports

The trajectory-replay microbenchmark, autonomous browser-use evaluation, and
Web Fetch intentionally keep separate suites and metrics.
Web Fetch has no legacy top-level package or compatibility imports.

## Autonomous browser-use pilot

The second browser track runs the real CowAgent loop against pre-registered
WebArena-Verified tasks. Browsers remain the evaluated participants; models are
separate experiment layers. Each model is collected in its own evidence
directory, and the report builder merges those immutable cohorts in memory.

```bash
./examples/browser_use/run.sh
make browser-use-review EVIDENCE="$HOME/.browser-eval/browser-use/current"
make browser-use-report EVIDENCE="$HOME/.browser-eval/browser-use/current"
make browser-use-report-check EVIDENCE="$HOME/.browser-eval/browser-use/current"
# Before packaging or publishing; adds full responsive, theme, and language visual QA.
make browser-use-release-check EVIDENCE="$HOME/.browser-eval/browser-use/current"
```

For a joint report, repeat `--evidence` once per model cohort; never concatenate
their `attempts.jsonl` files:

```bash
uv run --frozen python scripts/build_browser_use_report.py \
  --evidence "$MODEL_A_EVIDENCE" --evidence "$MODEL_B_EVIDENCE" \
  --output reports/browser-use
uv run --frozen python scripts/check_browser_use_report.py reports/browser-use \
  --evidence "$MODEL_A_EVIDENCE" --evidence "$MODEL_B_EVIDENCE"
```

See [examples/browser_use/README.md](examples/browser_use/README.md) for the
local-site and credential boundary.

## Web Fetch 评测

当前独立浏览器 Markdown 对比覆盖 Kitesurf、Lightpanda、Obscura、
Moli 1.1.5 与 Chromium，并在公开 WebMainBench-545 母集中预先冻结的 200 份 HTML
上使用官方指标。200 页在任何方法结果产生前选定；这是派生子集，不冒充官方
545 例榜单。完整的输入冻结、调用、评分、结果独立审查和发布协议见
[运行协议](harness/web_fetch/HEADLESS.md)。实测输出保留在用户目录的持久化证据中，
不提交到 Git；公开冻结 HTML 抽取结果不与历史真实 URL 套件混排。

另有历史十方法矩阵：150 个任务 × 10 种方法，共 1,500 条逻辑结果；它使用 `evaluation/dataset.json`，与本轮 200 页公开集不是同一评测。网页正文、动态正文、文档、图片、视频和复杂热门网站的旧结果保留各自的任务定义与分榜，不混入 WebMainBench 官方指标。

## 报告构建入口

```text
evaluation/current-report.json # 本轮公开集及发布目标
evaluation/dataset.json        # 历史十方法矩阵的任务集
harness/web_fetch/             # 接口适配、评分、报告生成器
scripts/build_report.py        # 正式报告构建入口
reports/webfetch/              # 默认构建目录；当前配置构建 WebMainBench 报告
reports/webfetch-public-benchmarks/ # 本轮独立发布使用的生成目录
research/provider-adoption.json # 当前已核验采用统计及候选文件目录
```

```bash
make setup
make report EVIDENCE=/absolute/path/to/evidence
make report-check
make test
```

上述入口由 `.python-version`、`uv.lock` 和 Makefile 固定 Python 3.11 与依赖版本；
不得改用系统 `python` / `python3`。环境不满足时立即失败，不降级执行。
构建不调用供应商、不修改当前测量成绩。输出校验失败会中止；重建会替换整个已标记的生成目录，避免旧页面残留。

解读配图保存在数据目录的 `editorial/moli-webfetch/`（默认 `~/.browser-eval/`），不提交 Git。`research/editorial-figures.json` 登记文件指纹、用途及语言版本；构建会核验图片并生成在线资源和内嵌图片的独立文章。变更配图须重新核对图中文字、数字和对应测量记录，再更新指纹。

参考与评分规则更新时，依次执行 `uv run --frozen python scripts/prepare_references.py`、`uv run --frozen python scripts/rescore_content.py`，再构建报告。前者仅规范化评分参考，原始源页快照不改；后者校验每份原始输出的 SHA-256，并仅重新计算机械评分，不调用供应商。零宽排版字符、Unicode 和 Markdown 可见文本规则对所有方法一致；真正缺失的内容不能用模糊相似度放行。运行 ID 根据执行记录及开始时间稳定生成，区别于详情中供应商返回的请求 ID。

采用统计用 `uv run --frozen python research/search_method_adoption.py` 发现候选，再统一核验；`uv run --frozen python research/refresh_adoption_candidates.py` 可复查已有候选。候选文件目录独立保留，暂时未达星数或活跃条件不丢失；只有完整核验成功才原子替换当前统计。原始发现快照仅作候选来源，计数以当前默认分支文件证据为准，不能解释为全网生产用户数。

`reports/` 和 `publish/` 是可重建产物及本地发布回执，不提交 Git；发布凭据不得写入仓库。

## 十方法 Web Fetch 旧矩阵的补测

把根目录 `.env.example` 复制为 `.env`，只填写需要的方法。若账号集中保存在用户目录 `~/.env`，执行 `make import-env`：它只把本评测声明的 9 个托管方法变量导入仓库 `.env`，保留已有非空值，不复制其他账号，不打印变量值，并把目标权限设为 `0600`；缺少任何目标变量会列出变量名并失败。所有 Web Fetch 入口仍默认只读取仓库根目录 `.env`，绝不隐式读取用户目录或执行 shell 内容；已导出的环境变量优先。只有显式 `--env-file <路径>` 才改用其他文件，文件不存在时报错。`.env` 与本地变体已被 Git 忽略，示例不含凭据。

先执行 `make setup`，再用 `uv run --frozen python -m harness.web_fetch validate --providers <方法名>` 校验凭据。LangChain 与 Crawl4AI 已由 `uv.lock` 固定并随 `make setup` 安装，worker 默认使用项目 `.venv`；OpenClaw、DeepSeek Harness 和 CowAgent 还需要固定源码仓库，路径均在 `.env.example` 中列出，可通过 `scripts/bootstrap_oss_baselines.sh` 准备。空仓库路径会在任何调用前失败。

```bash
uv run --frozen python scripts/run_benchmark.py
# 或仅实测 Moli（旧十方法任务集，不调用其他供应商）
uv run --frozen python scripts/run_benchmark.py --providers moli-webfetch --output ~/.browser-eval/runs/moli-webfetch
# 仅检查新增动态组配置，不创建输出、不调用接口
uv run --frozen python scripts/run_benchmark.py --track dynamic --validate-only
# 扩充案例时，只运行已独立冻结的新案例 JSON；源页证据放在其旁边的 sources/
uv run --frozen python scripts/run_benchmark.py --dataset ~/.browser-eval/runs/new-reference/dataset.json --track dynamic --output ~/.browser-eval/runs/new-cases
# 仅补跑指定的托管方法；其余已测记录不受影响
uv run --frozen python scripts/run_benchmark.py --track dynamic --providers lexmount-global,lexmount-cn,firecrawl,tavily,exa,cloudflare-markdown --output ~/.browser-eval/runs/dynamic-hosted
```

本节命令针对十方法 Web Fetch 旧矩阵，不针对当前 `evaluation/current-report.json` 绑定的 WebMainBench-545 五浏览器报告。旧矩阵可用 `--providers` 选择方法；云端方法可能消耗配额。所有选中方法先通过配置检查，再开始调用。不同方法并发，同一方法先完成网页组，再测其他组；正文与资源配置分开。已有输出目录会被拒绝覆盖。新结果须独立核验，不能把测量输出写入 `evaluation/`，也不自动替换已发布成绩。`evaluation/current-rerun.json` 记录旧十方法矩阵的修正范围和测速批次，不是当前公开集报告的执行配置。

新增方法完成旧十方法任务集后，可执行 `uv run --frozen python scripts/add_provider_results.py ~/.browser-eval/runs/<完整运行目录> --provider <新方法>`。已有方法补测尚未执行的组时，使用 `--provider <方法> --track dynamic`；输入必须完整覆盖该组，案例与参考须与旧任务集完全一致。此入口拒绝缺失/重复任务、参考变化、输出哈希不符或执行批次不完整；原有 JSONL 行和输出字节不变，禁止覆盖已测任务。补测后同步审查 `configs/evaluation-inventory.json` 的方法覆盖，再重建旧矩阵报告。原始执行组、运行 ID 与时间仍各自保留，不能把不同时间的调用描述成同时测量。

### Moli WebFetch

历史十方法矩阵按 [Moli 1.1.4 官方 skill](https://github.com/lexmount/moli/tree/v1.1.4/skills/moli-webfetch) 安装并固定 `MOLI_BINARY`（不需要账号/API Key）。普通正文使用 `moli fetch --dump markdown`；挑战题使用一次 `moli fetch --dump json --trace-network`，同时保留最终 DOM、HTTP 状态、最终 URL 和有界网络诊断，DOM 在同一截止预算内本地转为 Markdown；资源页通过一次 `--eval` 从渲染 DOM、已加载同源 iframe 与有界同源模块中返回结构化 URL。动态任务分别使用预声明的完成条件和正文提取范围，避免把等待按钮误当作答案。直接 PDF、图片和视频地址使用裸 `moli fetch URL`；该版本 Moli CLI 会把 OOXML 响应误送入 HTML 序列化，因此 DOCX 正文任务在同一次 CLI 运行中预先选择页面运行时 `fetch(location.href)` 取得原始字节，并明确记录第二次 HTTP 请求。冻结的公开测试域名若因 split DNS 映射到私网地址，只对已经实测冲突的精确白名单省略 `--block-private-networks`，其余 URL 仍开启保护。文档正文解析计入同一截止预算；文件任务验收到格式、长度和 SHA-256。工具成功不等于任务通过，仍使用同一套机械评分规则。

官方还提供 JSON/HTML/semantic tree、DOM eval、授权会话及需 layout 的截图/PDF 输出。这些能力与正文和原始响应路线分开说明；生成 PDF 不等于解析已有 PDF，媒体链接也不等于取得原文件。历史十方法矩阵对直接非 HTML 响应优先使用自动原始输出；本地文档解析属于正文任务的计时内后处理，不暗中借用其他 provider。本轮五浏览器公开集报告和已发布十方法旧版保留各自的实测身份和成绩，不用新版本倒改旧结果。

独立源页检查：`uv run --frozen python scripts/audit_sources.py`，需要 requests、BeautifulSoup4 和文档解析依赖。HTTP 失败只触发进一步检查，不能据此自动删除任务。复杂热门网站的列表按字段结构评分，不耦合当前标题、排序或价格。动态正文参考采集须遵守 `harness/web_fetch/README.md` 的配对证据与有界完成条件；页面分类不是 JS 必要性的证据。


当前配置的公开集报告绑定独立站点 `6jNzpGiPozLW`；十方法 Web Fetch 参考报告 `RSdbALdbdNG6` 和五类浏览器参考报告 `UUAhhQMnrGwm` 均不作为本报告的发布目标。打包将完整证据去重压缩并按需加载。Artifact Site 令牌优先读取显式进程环境 `ARTIFACT_SITE_TOKEN` 和目标服务的 `~/.config/artifact-site/tokens/<host>`；旧产品名的变量和路径仅作迁移回退，不加载仓库 `.env`。构建、打包与发布从 `evaluation/current-report.json` 读取目标地址、站点和预期版本，并用服务端版本标识防止并发覆盖。发布令牌与管理回执不得提交或放入站点。

## 内容规范

只维护当前实现，不建带版本号的报告脚本、兼容跳转或旧报告依赖链。正式报告只包含任务、参考范围、评测方法、结果、接口说明与证据；协助操作和工作日志只在会话中沟通。知乎、大众点评已有快照继续保留，访问受限不等于网站无效。
