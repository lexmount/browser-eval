# Browser Service Eval

Reproducible evaluation of browser engines and services across public task
suites, functional correctness, latency, output size, CPU, memory, and network
traffic.

The first backend compares warm local Chromium and Moli in equal, isolated
Docker cgroups. It does not require Codex, another coding agent, an LLM API key,
website accounts, or login state.

## Latest report

[Chromium 与 Moli 浏览器工具调用评测](https://artifact-hub.dev.lexmount.net/s/zzzUqvSKjTFB)

This stable Sites link opens the latest published version. Generated report
files are local build outputs and are not committed to this repository.

## Run the browser evaluation

Requirements: Docker Engine (cgroup v2), Python 3.11+ with `venv`, at least 4
CPU cores, 6 GiB available memory, and Internet access.

```bash
./examples/browser_use/run.sh
```

The command builds pinned browser images, installs the controller in a local
virtual environment, runs the versioned 30-task deterministic suite, and writes:

- raw reproducibility artifacts to `artifacts/browser_use/latest/` (ignored by Git)
- latest-only Markdown, HTML, and audit data to `docs/reports/` (ignored by Git)

All statistics and HTML are generated by repository scripts. To rebuild the
summary and report from an existing `attempts.jsonl` without rerunning the
browsers, use:

```bash
uv run --frozen python examples/browser_use/rebuild_report.py
```

See [examples/browser_use/README.md](examples/browser_use/README.md) for the
measurement protocol, complexity tiers, overrides, and CubeSandbox decision.

## Harness layout

- `harness/browser_use`: interactive browser-use execution, metrics, and reports
- `harness/web_fetch`: Web Fetch providers, execution, scoring, and reports

Browser Use and Web Fetch intentionally keep separate suites and metrics.
Web Fetch has no legacy top-level package or compatibility imports.

## Web Fetch 评测

独立的浏览器 Markdown 对比覆盖 Kitesurf、Lightpanda、Obscura、
Moli 1.0.6、Moli 1.1.1、Moli 1.1.3 与 Chromium。完整的参考冻结、调用、
测后核验、结果独立审查和发布协议见
[运行协议](harness/web_fetch/HEADLESS.md)。实测输出保留在用户目录的持久化证据中，
不提交到 Git；这组数据不与下面的历史 12 方法混排。

当前十二方法主矩阵为 150 个任务 × 12 种方法：网页正文 100 个，动态网页正文、文档、图片、视频、复杂热门网站各 10 个，共 1,800 条权威逻辑结果。六类任务进入同一个等权综合总榜，并保留各自分榜；动态组的异步接口、前端应用、内嵌数据、延迟呈现和 iframe 子文档仍按独立类别解释，不与静态网页质量混算。`evaluation/dataset.json` 的 `coverage_plan` 显式规定参评范围，未运行或缺少判分证据时禁止发布。

## 唯一当前入口

```text
evaluation/                 # 当前任务、评分契约和发布 authority；不存放实测输出
harness/web_fetch/          # 接口适配、评分、当前报告生成器
scripts/build_report.py     # 唯一正式报告构建入口
reports/webfetch/           # 唯一当前报告，可重复生成
research/provider-adoption.json # 当前已核验采用统计及候选文件目录
```

```bash
make setup
make report EVIDENCE=/absolute/path/to/evidence
make report-check
make test
```

上述入口由 `.python-version`、`uv.lock` 和 Makefile 固定 Python 3.11 与依赖版本；
不得改用系统 `python` / `python3`。环境不满足时立即失败，不降级执行。
构建不调用供应商、不修改当前测量成绩。输出校验失败会中止；重建会替换整个已标记的生成目录，避免旧页面残留。

解读配图保存在数据目录的 `editorial/moli-webfetch/`（默认 `~/.browser-eval/`），不提交 Git。`research/editorial-figures.json` 登记文件指纹、用途及语言版本；构建会核验图片并生成在线资源和内嵌图片的独立文章。变更配图须重新核对图中文字、数字和对应测量记录，再更新指纹。

参考与评分规则更新时，依次执行 `uv run --frozen python scripts/prepare_references.py`、`uv run --frozen python scripts/rescore_content.py`，再构建报告。前者仅规范化评分参考，原始源页快照不改；后者校验每份原始输出的 SHA-256，并仅重新计算机械评分，不调用供应商。零宽排版字符、Unicode 和 Markdown 可见文本规则对所有方法一致；真正缺失的内容不能用模糊相似度放行。运行 ID 根据执行记录及开始时间稳定生成，区别于详情中供应商返回的请求 ID。

采用统计用 `uv run --frozen python research/search_method_adoption.py` 发现候选，再统一核验；`uv run --frozen python research/refresh_adoption_candidates.py` 可复查已有候选。候选文件目录独立保留，暂时未达星数或活跃条件不丢失；只有完整核验成功才原子替换当前统计。原始发现快照仅作候选来源，计数以当前默认分支文件证据为准，不能解释为全网生产用户数。

`reports/` 和 `publish/` 是可重建产物及本地发布回执，不提交 Git；发布凭据不得写入仓库。

## 重新实测

把根目录 `.env.example` 复制为 `.env`，只填写需要的方法。若账号集中保存在用户目录 `~/.env`，执行 `make import-env`：它只把本评测声明的 9 个托管方法变量导入仓库 `.env`，保留已有非空值，不复制其他账号，不打印变量值，并把目标权限设为 `0600`；缺少任何目标变量会列出变量名并失败。所有 Web Fetch 入口仍默认只读取仓库根目录 `.env`，绝不隐式读取用户目录或执行 shell 内容；已导出的环境变量优先。只有显式 `--env-file <路径>` 才改用其他文件，文件不存在时报错。`.env` 与本地变体已被 Git 忽略，示例不含凭据。

先执行 `make setup`，再用 `uv run --frozen python -m harness.web_fetch validate --providers <方法名>` 校验凭据。LangChain 与 Crawl4AI 已由 `uv.lock` 固定并随 `make setup` 安装，worker 默认使用项目 `.venv`；OpenClaw、DeepSeek Harness 和 CowAgent 还需要固定源码仓库，路径均在 `.env.example` 中列出，可通过 `scripts/bootstrap_oss_baselines.sh` 准备。空仓库路径会在任何调用前失败。

```bash
uv run --frozen python scripts/run_benchmark.py
# 或仅实测 Moli（当前完整评测集，不调用其他供应商）
uv run --frozen python scripts/run_benchmark.py --providers moli-webfetch --output ~/.browser-eval/runs/moli-webfetch
# 仅检查新增动态组配置，不创建输出、不调用接口
uv run --frozen python scripts/run_benchmark.py --track dynamic --validate-only
# 扩充案例时，只运行已独立冻结的新案例 JSON；源页证据放在其旁边的 sources/
uv run --frozen python scripts/run_benchmark.py --dataset ~/.browser-eval/runs/new-reference/dataset.json --track dynamic --output ~/.browser-eval/runs/new-cases
# 仅补跑指定的托管方法；其余已测记录不受影响
uv run --frozen python scripts/run_benchmark.py --track dynamic --providers lexmount-global,lexmount-cn,firecrawl,tavily,exa,cloudflare-markdown --output ~/.browser-eval/runs/dynamic-hosted
```

使用具备当前全部解析依赖的 Python 环境执行。当前 profile 固定 12 种方法，可用 `--providers` 选择；云端方法可能消耗配额。所有选中方法先通过配置检查，再开始调用。不同方法并发，同一方法先完成网页组，再测其他组；正文与资源配置分开。已有输出目录会被拒绝覆盖。新结果核验后才能组装进 Git 外的当前证据，不能把测量输出写入 `evaluation/`，也不自动替换已发布成绩。本次从旧 12 方法证据升级的精确主矩阵与同窗测速范围见 `evaluation/current-rerun.json`；未列入其中的调用只离线重评分，不为改善分数而重跑。

新增方法完成同一评测集后，可执行 `uv run --frozen python scripts/add_provider_results.py ~/.browser-eval/runs/<完整运行目录> --provider <新方法>`。已有方法补测尚未执行的组时，使用 `--provider <方法> --track dynamic`；输入必须完整覆盖该组，案例与参考须与当前评测集完全一致。此入口拒绝缺失/重复任务、参考变化、输出哈希不符或执行批次不完整；原有 JSONL 行和输出字节不变，禁止覆盖已测任务。补测后同步审查 `configs/evaluation-inventory.json` 的方法覆盖，再重建报告。原始执行组、运行 ID 与时间仍各自保留，不能把不同时间的调用描述成同时测量。

### Moli WebFetch

当前十二方法矩阵按 [Moli 1.1.4 官方 skill](https://github.com/lexmount/moli/tree/v1.1.4/skills/moli-webfetch) 安装并固定 `MOLI_BINARY`（不需要账号/API Key）。普通正文使用 `moli fetch --dump markdown`；挑战题使用一次 `moli fetch --dump json --trace-network`，同时保留最终 DOM、HTTP 状态、最终 URL 和有界网络诊断，DOM 在同一截止预算内本地转为 Markdown；资源页通过一次 `--eval` 从渲染 DOM、已加载同源 iframe 与有界同源模块中返回结构化 URL；动态任务把数据集预先声明的通用 selector、最少数量和有界等待转换为 Moli 等价参数，并用一次 `--eval` 返回有界记录文本，不把标准答案写进命令。直接 PDF、DOCX、图片和视频地址在调用前选择裸 `moli fetch URL`，由 CLI 自动返回原始响应或序列化页面；嵌入式文档查看器用页面运行时读取文档。PDF 等取得原始字节后，文档正文在同一截止预算内解析。直接文件任务一直验收到格式、长度和 SHA-256，不做无关 Markdown 转换。适配器保留 stdout 原文、独立 stderr 和退出状态；JSON 路线对原包只公开安全摘要，不公开 cookie 或完整响应头；不发第二次请求拼接元数据。工具成功不等于任务通过，仍使用同一套机械评分规则。

官方还提供 JSON/HTML/semantic tree、DOM eval、授权会话及需 layout 的截图/PDF 输出。这些能力与正文和原始响应路线分开说明；生成 PDF 不等于解析已有 PDF，媒体链接也不等于取得原文件。当前十二方法矩阵对直接非 HTML 响应使用自动原始输出，不能强制 `--dump html/markdown`；本地文档解析属于正文任务的计时内后处理，不暗中借用其他 provider。上文的独立五浏览器报告仍保留 Moli 1.0.6、1.1.1、1.1.3 的历史实测身份和成绩，不用 1.1.4 倒改旧结果。

独立源页检查：`uv run --frozen python scripts/audit_sources.py`，需要 requests、BeautifulSoup4 和文档解析依赖。HTTP 失败只触发进一步检查，不能据此自动删除任务。复杂热门网站的列表按字段结构评分，不耦合当前标题、排序或价格。动态正文参考采集须遵守 `harness/web_fetch/README.md` 的配对证据与有界完成条件；页面分类不是 JS 必要性的证据。

```bash
export WEBFETCH_REPORT_PUBLIC_URL=https://artifact-hub.app.lexmount.com/api/preview/RSdbALdbdNG6
make report EVIDENCE=/absolute/path/to/evidence
make report-check
uv run --frozen python scripts/package_artifact_hub.py
# 上传前先只读确认远端基线版本；不要拿新包和尚未更新的远端比较内容。
uv run --frozen python scripts/verify_artifact_hub.py --slug RSdbALdbdNG6 --base-url https://artifact-hub.app.lexmount.com
ARTIFACT_HUB_BASE_URL=https://artifact-hub.app.lexmount.com uv run --frozen python scripts/publish_artifact_hub.py --receipt publish/artifact-hub-app-new-receipt.json --update
```

打包输出 `publish/webfetch-sites.zip`，将完整证据去重压缩并按需加载。Sites 发布令牌依次从显式进程环境 `ARTIFACT_HUB_TOKEN`、目标服务的 `~/.config/artifact-hub/tokens/<host>` 读取，不加载仓库 `.env`。新授权按目标 host 保存，文件权限为 0600；不同部署的令牌不通用，也不互相覆盖，host 包含显式端口（如有）。其他评测密钥仍只读取仓库配置。当前报告绑定 `https://artifact-hub.app.lexmount.com` 的 12 方法站点 `RSdbALdbdNG6`；此前的 dev 域站点 `MblD_VwSPBRX`、旧 12 方法站点 `UeZE1vfcEOrM` 和五类浏览器参考报告站点 `UUAhhQMnrGwm` 均保持不变。构建、打包与发布都从 `evaluation/current-report.json` 读取公开地址、站点和预期远端版本；回执的服务地址与 slug 共同决定更新目标，回执、请求地址或命令行版本只要不一致就拒绝更新。服务端版本标识仅用于并发保护；成功发布后，把 profile 的预期版本更新为服务端新版本。例行发布只检查提交响应、轻量站点元数据和公开页面渲染，不回下载 ZIP 或逐文件镜像；`verify_artifact_hub.py --export` 与 `--public-files` 仅用于明确的服务端排障。发布令牌和管理回执不得提交或放入站点。
